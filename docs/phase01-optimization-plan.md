# 阶段 01：需求与机会优化计划

## 目标、依据与完成边界

本计划把本轮讨论中已由用户确认的方向转化为可分步实施、独立验证的工作包，适用于独立开发者及小团队与 Agent 协作的研发流程。核心目标是：用与风险和不确定性相称的证据，判断一个机会是否值得投入下一阶段的澄清成本。

用户已确认阶段边界、六项最小完成标准、分层处理路径、六种状态、相对排序，以及单一主记录与交接建议。本文是实施计划；下列规则在对应 workflow、SKILL、模板及验证完成前，不代表现有执行资产已同步或目标项目已采用。计划交付、工作包完成、实际项目采用和正式发布分别判断。

依据为[研发全流程](software-development-lifecycle.md)、[阶段 01 workflow](workflows/01-demand-and-opportunity.md)、[阶段 02 workflow](workflows/02-refinement-and-initiation.md)、[阶段 03 workflow](workflows/03-solution-and-planning.md)、[机会模板](../templates/delivery/opportunity-record.md)及[追溯契约](../templates/delivery/README.md)。文档、授权、证据和独立性继续遵循[文档规范](documentation-standard.md)、[质量门禁](quality-gates.md)与[可信来源](evidence-trust.md)。

## 已确认的目标设计

### 阶段边界与最小完成标准

阶段 01 完成只意味着批准投入澄清，不承诺开发、排期或交付日期。阶段 02 明确交付范围与验收，阶段 03 完成可行方案、投入与计划后，才由有权决策人确认开发承诺；阶段完成本身不自动产生外部承诺或执行授权。

| 最小标准 | 进入阶段 02 前的最低内容 |
| --- | --- |
| 受影响对象 | 用户、角色或系统，以及问题发生的情境 |
| 可观察的问题 | 当前行为、影响及原始请求；缺陷补充实际/预期行为和可用复现信息 |
| 来源证据 | 可追溯来源，事实、假设与未知项分开；不以编造信息补齐记录 |
| 期望结果 | 可观察的改善与判断方式，允许定性成功判据 |
| 投入理由 | 价值、紧迫度、初步范围、非目标和风险，以及值得继续澄清的理由 |
| 责任与决定 | 澄清负责人、决策人、批准理由和带时区时间；小团队允许一人承担多个角色 |

数值基线、精确目标、完整验收、实现方案和准确工作量不作为阶段 01 的统一前置要求。缺失数值时写获取方式和限制；不能用含糊的“有价值”代替可观察结果。会改变是否值得投入判断的关键未知项先有限验证；适合阶段 02 解决的未知项记录问题、负责人及下一步后交接；实现细节留给阶段 03，已知技术约束仍须保留。

### 分层路径与范围约束

- 小型且明确的问题可在一条既有记录中完成登记、界定和决定，不强制另写研究报告或逐一重复调用三个技能。
- 关键不确定性大的机会先有限验证，记录假设、方法、责任人、时间或成本上限、结束判据及后续决定；投入上限由实际负责人确认，不设通用固定天数。
- 较大或跨领域机会补充研究与相关负责人判断；材料深度随风险增加，完成标准不因此降低。
- 正在发生的严重事故或安全/隐私事件立即转入对应响应流程，不等待普通排序或六项信息全部补齐。阶段 01 仅保留脱敏线索和受控材料标识，不执行处置或复制受限证据。
- 保留用户原始请求，区分背后问题、明确指定的方案/约束与待验证的实现假设；不得擅自删除用户约束，也不得把实现假设当已批准方案。

### 六种状态与转换要求

| 状态 | 含义 | 必需记录与后续去向 |
| --- | --- | --- |
| 待补充 | 最小事实不足，尚不能判断 | 缺失项、补充负责人、复查时间；补齐后界定问题或进入有限验证 |
| 验证中 | 关键未知项影响投入判断，正在有限验证 | 验证方法、负责人、投入上限、结束判据；结束后按证据作决定，不自动进入澄清 |
| 候选池 | 值得关注但尚未选中投入澄清 | 保留及排序依据、负责人、复查触发；容量或证据改变后重排 |
| 进入澄清 | 六项标准满足，已批准投入阶段 02 | 决策理由、决策人、澄清负责人、范围与待解问题；关联下游记录 |
| 延后 | 有明确原因暂缓 | 原因、负责人、恢复条件或复查时间；条件变化后重新评估 |
| 关闭 | 当前决定不再推进 | 原因、证据、决定人与时间、必要的关联或重开条件；不删除历史 |

“待补充／验证中”表达分析进度，其余状态表达决策去向。状态仅在机会主记录维护，不能与文档 frontmatter、专题或需求状态混用。重新评估可回到待补充、验证中或候选池；进入澄清不是不可撤销终态。转换保留原状态、新状态、原因、决定主体、时间与证据，业务取舍由明确决策人确认，Agent 不自批优先级或开发承诺。候选池是尚未选中，延后是已明确决定暂缓。

### 相对排序、主记录与交接

默认以价值与影响、紧迫性、证据与不确定性、澄清投入、依赖与容量作相对判断，不强制统一数值公式。明确本轮决策窗口、排序理由、被挤出的事项、前提及可改变顺序的新证据。阶段 01 排的是澄清或有限验证投入；粗略实施成本仅作为约束，不能伪装成开发估算。

事故走响应路径；必须处理的外部约束由有权角色确认后与普通机会区分，不参与机械混合打分。高潜力但证据不足的机会可以先获得有限验证投入，不能因缺数值而一律排后；单个机会仍需说明容量与已有承诺，不强制制造第二个比较对象。

每个机会只有一份主记录和稳定 ID，沿用现有 Issue、任务或文档均可；状态与负责人只有一个维护位置，来源、证据和下游记录通过链接关联。重复信号优先关联已有机会，保留各次来源；相似但对象/范围不同的机会可以关联而不强行合并。关闭记录保留，新信号触发重评，不从零重复登记。

进入阶段 02 交接问题与证据、期望结果、初步范围/非目标、约束与风险、未解问题及其负责人、批准澄清的决定。已知方案要求和假设分别标注。后续价值依据失效、范围明显改变或关键假设被推翻时，关联原决定回到阶段 01 复核；下游保留自己的状态，不能用回流掩盖已有承诺及影响。

### S01-01：阶段契约与路由

在阶段 01 workflow 维护未来生效的状态和完成标准，生命周期/相邻阶段只引用并描述自己的交接职责，避免复制多份完整规则。补充小型、未知、复杂和紧急四类路径，保留现有高风险分流和文档门槛。明确状态转换的权限、证据和失效回流。阶段 02 的立项不得被表述为已经承诺开发日期。

完成条件：六项标准、状态含义、交接边界和异常回流可以直接用于判断场景；生命周期、相邻阶段与导航不存在相反表述。用户已确认要求逐项有文件落点和验收场景。

### S01-02：三个技能的实际决策

保留现有技能分工：intake 负责记录、去重与分诊，framing 负责问题/结果/未知项和有限验证设计，prioritization 负责澄清/验证资源取舍建议。明确输入完整时复用既有材料，不强制三次重写；缺关键事实时提出少量可回答问题，不假造背景。保留用户指定方案，区分约束与假设；授权决定和建议分开。

完成条件：每个技能的 description、输入、输出、停止条件与 workflow 路由一致；单机会、证据不足、高风险和紧急信号均有明确去向。修改技能时使用 skill-creator，并同步 skills/README 和要求清单。

### S01-03：主记录、模板与兼容迁移

在现有机会模板中保留全部追溯字段，补最小标准、按需有限验证、六状态历史、排序/容量取舍、交接与复查信息。提供英文副本和互链，中文/英文语义独立核对；同步模板导航。检查器当前会拒绝 opportunity-record.en.md，须在本包支持该指定配对、验证元信息/互链和缺译文负例，保留其他模板及非预期文件检查，不以放开全部文件绕过。

旧“新建”按事实补充到待补充或其他满足条件状态；旧“调研中”只有存在实际有限验证方法/负责人/上限/结束判据时才能映射为验证中，否则记录缺口后由负责人判断。迁移保留原值、时间、来源和映射决定，不批量伪填验证计划或批准。候选池、延后、关闭及进入澄清复核语义；旧进入澄清记录不追溯伪造历史六项信息，补当前可用材料并记录缺口，不能据旧标签推导新基线达标。

完成条件：新旧记录处理明确、可追溯，统一 schema 和检查未削弱；中英模板一致；一份轻量记录能完成决策，复杂记录可链接附件而不复制状态。阶段 02 能据交接定位原决定和未解问题。

### S01-04：验证与收口

优先扩充既有[研发演练](exercises/README.md)的阶段 01 部分及配套输入材料，不新增平行生命周期；执行下表场景。另起独立 Agent 上下文，提供原始任务、固定版本技能和最少场景材料，让其实际登记/界定/排序/交接，保留读取与输出轨迹；不只检查文档关键词或采信“已加载”。桌面场景、合成输入与真实证据分别标注，不将试行当目标产品研究或生产事件。

完成条件：全部适用场景结果与授权/推进范围符合预期，发现问题经作者修正和非作者复核；当前机械检查与独立文档验证通过。所用场景、限制与采用成本有原始记录，不把单次合成试验推广为全项目有效。

## 验收场景矩阵

| ID | 原始输入或变化 | 预期观察与失败判据 |
| --- | --- | --- |
| A01 | 事实清楚的小型缺陷，已有唯一 Issue | 一条记录满足最小判断并可进入澄清；强制另建研究报告、重复三份记录或承诺开发日期均失败 |
| A02 | 新产品想法，有定性改善目标但没有数值基线 | 记录证据、观察方法与基线获取方式；不编数值、不因缺数值一律关闭；仍须满足价值与成功判据 |
| A03 | 关键用户价值未知，结果会改变是否投入 | 进入有限验证，方法/负责人/投入上限/结束判据齐全；到上限或无结论时停止并决策，不自动开发或无限调研 |
| A04 | 一项非关键指标留待阶段 02 明确 | 明确未知项、负责人、下一步并交接；不为非关键未知无限阻塞，也不隐去关键未知 |
| A05 | 用户明确指定技术方案，证据尚不足 | 原始请求和约束保留，问题/方案假设分别标注；擅自替换方案或将其标成已验证均失败 |
| A06 | 多个机会竞争有限澄清容量，含高潜力低置信度机会 | 按共同窗口相对排序，说明挤出项和重排条件；可建议先有限验证，无伪评分或未经确认承诺 |
| A07 | 只有一个机会，需要决定是否继续 | 与实际容量、已有承诺和不做的代价比较，不编造另一机会或强制运行完整多项排序 |
| A08 | 事故正在发生或敏感信息暴露 | 立即路由运行/安全响应，只保存脱敏线索；排队等待普通排序、要求先填满模板或复制秘密均失败 |
| A09 | 候选池、延后、关闭各出现新证据 | 按各自理由和复查条件重评，保留历史；候选/延后混用、关闭后重复建无关联记录均失败 |
| A10 | 两次重复反馈，另有相似但不同范围的问题 | 重复来源关联一份主记录，不丢来源；不同范围可关联不强并，原 ID 与证据可回溯 |
| A11 | 进入阶段 02 后范围扩大或价值假设被推翻 | 回到阶段 01 重评并关联已有需求与决定，明确对下游影响；旧批准不能覆盖新范围 |
| A12 | 旧“新建／调研中”记录、缺验证计划及旧澄清批准 | 按事实迁移、保留原状态与缺口；批量标为验证中、补造批准或沿用旧标签声称达标均失败 |
