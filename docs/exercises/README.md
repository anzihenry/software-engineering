# 端到端研发演练

本目录用三个虚构但可执行的场景检验八阶段流程是否能从问题证据走到运行结果和复盘闭环。演练是桌面推演与证据走查，不执行真实生产部署、不伪造 CI/审批/运行数据，也不要求为低风险变化制造不必要文档。

## 运行方式

1. 指定主持人、交付负责人、业务决策人、独立评审者和观察记录人；高风险场景另指定安全/合规与运维决策角色。
2. 复制[生命周期交付物模板](../../templates/delivery/README.md)，使用场景建议的稳定 ID。允许在同一文档中展示多个记录，但不同交付物必须保持独立 ID 和状态。
3. 主持人只先公布“初始条件”，在参与者到达对应阶段后再公布注入事件。所有外部状态和证据均标记为“演练模拟”，不得冒充真实检查或批准。
4. 参与者逐阶段给出当前决定、最低证据、记录更新和回流路径。门禁不满足时必须停止、降级范围或回流，不以演练时间为由跳过。
5. 观察记录人依据统一评分和场景硬停止条件给出结论，将缺口转为有所有者和效果判据的改进行动。

## 统一评分

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 价值与范围 | 方案先行或范围失控 | 目标明确但边界/指标不完整 | 问题、指标、范围和非目标均可验证 |
| 风险与决策 | 风险降级或无授权推进 | 识别风险但决策/例外不完整 | 风险驱动门禁，决策人、依据和回流清晰 |
| 追溯与证据 | 记录断裂或伪造证据 | 主要记录可关联但版本/环境有缺口 | 八阶段 ID、版本、环境和证据可双向追溯 |
| 验证与恢复 | 仅验证主流程或无恢复路径 | 有相关测试和恢复说明 | 正常/边界/失败/权限及适用恢复均有证据 |
| 运行与学习 | 部署成功即结束 | 有观察或复盘但行动不可验证 | 健康判断、结果度量和改进行动形成闭环 |

总分至少 8/10 且没有场景硬失败才算通过。以下行为无论得分均判失败：伪造检查或批准、在未知高风险下继续、把旧 SHA/制品证据用于新版本、泄露敏感信息、删除阻塞测试、或在恢复能力未知时扩大生产影响。

## 演练导航

| 风险 | 演练 | 建议时长 | 重点 |
| --- | --- | --- | --- |
| 低 | [空状态文案调整](low-risk-copy-change.md) | 30–45 分钟 | 风险匹配的精简流程、视觉/可访问性和快速回退 |
| 中 | [保存默认筛选功能](medium-risk-feature.md) | 60–90 分钟 | 前后端契约、持久化、缓存、功能开关和系统验证 |
| 高 | [角色权限与数据迁移](high-risk-data-permission-change.md) | 90–120 分钟 | 授权矩阵、迁移不变量、安全评审、渐进发布和恢复 |

首次试行后记录实际耗时、含糊门禁和缺失工具。只有在多次演练中重复出现且有证据的问题，才升级为全局流程或自动化变更。

## 阶段 01 专项试用

三条生命周期演练的阶段 01 使用同一[完成门禁与状态规则](../workflows/01-demand-and-opportunity.md)。补充[14 组原始合成输入](fixtures/phase01-opportunities.json)用于独立 Agent 实际登记、界定、排序、迁移或交接：只给原始请求及执行资产，不提前提供验收矩阵或作者预期结论。记录读取资产/输入摘要、实际输出、工具日志、限制和复核，区分模拟角色与真实授权。

当前执行与独立核对范围见[阶段 01 分步验证](../phase01-validation.md)，原始输出集中保留在[原始试用记录](evidence/phase01-forward.json)。记录仅证明对应固定版本的合成场景行为，不证明真实产品研究、生产响应、所有项目采用或远端 CI 已生效。
