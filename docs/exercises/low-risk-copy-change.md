# 低风险演练：空状态文案调整

## 演练目标

验证团队能否对纯文案变化精简流程，同时保留可验收性、当前版本证据、发布观察和结果回流，不把“小改动”理解为无须验证。

## 初始条件

- Web 项目列表空状态当前显示“暂无项目”，用户研究表明新用户不知道下一步，但本次不新增按钮、链接、埋点或业务逻辑。
- 仅调整现有简体中文资源为“还没有项目，创建后会显示在这里”；其他语言、API、权限、数据和布局组件不在范围内。
- 建议记录链：`OPP-COPY-001` → `REQ-COPY-001` → `DES-COPY-001`/`VER-COPY-001` → `CHG-COPY-001` → `REL-COPY-001` → `INC-COPY-001`（仅发生异常时启用）→ `RET-COPY-001`。

## 阶段 1：需求与机会

- 使用[机会记录](../../templates/delivery/opportunity-record.md)在同一主记录保存研究来源、受影响新用户、初步范围/非目标、期望理解改善、风险、负责人和实际批准；已有比例/支持基线就引用，未知则记录观察方式，不编数值。
- 门禁：满足[阶段 01 六项标准](../workflows/01-demand-and-opportunity.md#决策门禁)，业务负责人只批准澄清投入；不强制另写研究报告，不把“文案已修改”当价值结果。
- 注入：利益关系人顺便要求增加跳转链接。参与者须关联原记录重评范围/风险，旧澄清批准不覆盖新范围，也不自动承诺开发。

## 阶段 2：澄清与立项

- 在同一 Issue 用独立 `REQ-COPY-001` 关联 `OPP-COPY-001`，按[需求与风险包](../../templates/delivery/requirements-risk-package.md)用轻量条目明确准确文案、空/非空显示条件、不截断/遮挡、允许换行、200% 缩放和屏幕阅读器读出完整文本的判据及来源。不强制数字化理解效果或另写三份表。
- 门禁：按[阶段 02 七项](../workflows/02-refinement-and-initiation.md#决策门禁)核对原范围、适用可访问性/本地化标准、低风险理由、依赖与未知；有权角色对当前可引用需求修订实际批准后才标“可进入方案”，仅批准设计投入，不承诺开发日期。假设没有交互/路由/埋点/数据/语言回退变化须有事实依据。
- 注入：确认后增加链接，或改要求“不允许任何换行”。记录新旧基线、受影响验收/风险/下游与可继续/需等待范围，回阶段 02 重新确认；不拿旧批准覆盖新范围。非阻塞同义措辞仅在原允许边界内交文案负责人按节点确认。

## 阶段 3：方案与计划

- 用[方案记录](../../templates/delivery/solution-decision.md)的轻量条目关联当前需求修订，说明只复用现有资源键、不改组件/业务边界，按已有可访问性判据验证，版本回退及后续验证节点明确；没有实质取舍不凑备选，不另写六份技能文档。
- 在[验证矩阵](../../templates/delivery/verification-matrix.md)规划资源检查、代表视口、200%缩放、屏幕阅读器和现有自动测试，实际执行前保持未执行，不因方案批准填通过。计入文案修改、相关测试、目标项目文档/译文、后续独立评审和发布准备等适用任务，区间依据、实际接受责任和容量明确。
- 门禁：按[阶段03三类判断](../workflows/03-solution-and-planning.md#决策门禁)分别记录轻量技术评审、实施准备及有权实际开发批准，绑定本次需求/方案/计划和范围；已有明确有效授权可核实引用，不重复请求。批准开发不自动承诺上线日期或发布，交阶段04前核对版本/当前任务前置和实际命令。
- 注入：只剩局部变量命名未定，留原边界内实现；若突然要求增加跳转/埋点，按影响回阶段02确认范围/验收/风险，不借旧批准夹带。无需编码预研时说明依据；确需编码确认可行性则按阶段03独立worktree执行，保全证据后收口。

## 阶段 4：开发与自测

- 在批准范围只改资源，按[阶段04七项实现/自测](../workflows/04-implementation-and-self-test.md)核对空/非空、准确文案、200%缩放及无遮挡/读出；按风险选择资源/代表浏览器观察，不强制照抄字符串的新增单测，保留项目必过集合。
- 用[变更交接](../../templates/delivery/change-handoff.md)链接同一验证矩阵、当前head或文件摘要、实际命令/步骤、环境/时间/退出码及截图原始证据；文档影响和适用译文到位。
- 注入：窄屏三行换行但无遮挡，按原允许换行判据判断；若自测后再改资源则重评受影响证据，不能沿用旧截图。必需工具缺失记阻塞/未执行，不记不适用。
- 门禁：完整范围、本阶段必需检查实际通过及材料当前有效才待评审；否则可Draft协作，不直接标可合入。已规划05完整专项列负责人/节点/判据/证据/失败动作，不提前填通过。

## 阶段 5：集成验证

- 使用[阶段05七项门槛](../workflows/05-integration-validation.md#最低完成七项标准)核对04交接、当前完整CI集合、非作者文案/范围/可访问性评审；核心与本次变更端到端集合保持轻量，但每次功能合入前后都实际执行，不能因文案低风险省略。
- 用[验证矩阵](../../templates/delivery/verification-matrix.md)与[变更交接](../../templates/delivery/change-handoff.md)绑定候选head/base、所测构建/浏览器/数据，以及真实main合入SHA、前后步骤/截图/原始结果；资源单测不替代真实页面路径。
- 合入前核对非Draft、必需CI/独立/端到端及文档通过且无阻塞；有实际授权才交项目机制合入。合入后在精确main运行核心/本次路径，已合入不等于阶段完成。
- 注入：较新main构建取消本次端到端。保留取消状态并补跑指定版本/完整用例，更晚绿不能自动覆盖；若实际文案遮挡核心操作则暂停失败版本发布，按授权修复/回退并复验，原功能不因回退成功补记交付。
- 门禁：实际合入、对应main必需端到端通过、问题闭环与06交接齐备才完成；只交指定已验证范围，发布候选/环境/生产权限仍由06核对。

## 阶段 6：发布与变更管理

- 按[阶段06八项标准](../workflows/06-release-and-change-management.md#最低成功完成八项标准)接收05，使用[发布记录](../../templates/delivery/release-record.md)固定候选修订、source/同一制品、文案范围/目标渠道与恢复目标；低风险不省略实际页面路径和发布观察。
- 人类预批准低风险策略明确类型/风险/环境/范围/窗口、检查、停止恢复和样本；本次适用且前批通过可自动续批，不重复请示。部署后实际核对文案/空非空/关键操作及必要可访问性，观察时间和最低有效样本同时满足才扩大。
- 注入：时间已到而真实会话不足，或监控停采无告警。分别继续观察或无法判定并暂停推进，不以合成探测取代必需样本。批准到期/候选变化则暂停重核；文案遮挡关键操作先停止扩大，按授权恢复并验路径。
- 门禁：达到批准目标、验证观察/文档/问题处置及07实际接收齐备才成功；内部目标可以内部收口，全量目标不以灰度成功关闭。取消核实副作用/残留，恢复旧版记原功能未交付，失败证据保留。

## 阶段 7：运行与支持

- 按[07工作单元与七底线](../workflows/07-operations-and-support.md#七项共同验收底线)接收06实际版本/范围、监控/手册访问、主替补与覆盖时段，记录接收。以[运行与支持记录](../../templates/delivery/operations-record.md)关联页面健康和反馈，够用即处理，不因咨询索取账户密码。
- 监测页面关键路径/错误与用户反馈，核对采集新鲜度及告警送达/接手；无异常记未触发事件，不编造事故。文案误导或遮挡关键操作按实际影响升级，单用户严重影响也核实；事件使用[事件记录](../../templates/delivery/incident-record.md)，按授权预案恢复/回退并实证后才按条件关闭。
- 注入：监控停采但无告警不能记正常；同类普通咨询按风险优先处理。用户未回复仅按已有提醒等待规则可无回复结案，效果未确认、不计已验证解决且提供重开；转交未确认原协调责任持续。
- 将脱敏、适用版本及已验步骤写知识库；重复反馈、影响口径/样本局限、防护与行动接收交08，不承诺无依据修复日期，必要通知依授权。

## 阶段 8：度量与复盘

- 用[效果复盘与行动](../../templates/delivery/outcome-retrospective-actions.md)按明确文案版本/页面/用户群/窗口比较理解指标、关键路径及支持咨询，保留口径/原目标/原始反馈和样本限制；不制造假事故或强制开会。
- 注入：仅3次会话或无咨询，但目标需更大真实样本；按期记录证据不足及受影响决定，明确补证/负责人/期限和等待范围，不宣称无投诉等成功，不倒改阈值。足够定性证据可支持局部问题，不能推总体提升比例。
- 未改善回到问题假设，以证据和权限决定维持/调整/停止，不继续堆文案伪造成功。微小行动也保留实际接收、实施定义、效果/护栏、窗口及有理由不适用项，不混状态。
- 行动验证后才记有效，停止或重复合并可有权关闭但不算改善；新证据可重开并保留旧依据。适用知识和英文更新/当前独立核验完成，回流有承接ID/人/时间，低风险不免必需文档。

## 演练通过条件

- 全流程保持低风险边界，新增链接/逻辑要求被拆分或重新分级。
- 证据对应最新版本且覆盖代表性视觉和可访问性风险。
- 发布和效果记录可以从 `REL-COPY-001` 回溯到机会与需求；没有异常时不制造 `INC-COPY-001` 的假数据。
