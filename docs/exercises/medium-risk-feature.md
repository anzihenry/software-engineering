# 中风险演练：保存默认筛选功能

## 演练目标

验证初步中风险的普通功能跨越 Web 状态、后端 API 和低敏偏好持久化时，团队能否识别实际迁移等高风险触发，并保持契约兼容、失败语义、端到端证据和可控发布。标题/frontmatter 的 medium 是初始场景类别，不覆盖阶段 02 的实际风险重评。

## 初始条件

- 用户希望保存一个项目列表默认筛选条件，下次登录自动恢复；偏好包括状态和排序，不包含敏感数据。
- 现有旧客户端不知道该字段，列表 API 有缓存，数据库尚无偏好列；功能可由服务端开关关闭。
- 建议记录链：`OPP-FILTER-001` → `REQ-FILTER-001` → `DES-FILTER-001`/`VER-FILTER-001` → `CHG-FILTER-001` → `REL-FILTER-001` → `INC-FILTER-001` → `RET-FILTER-001`。

## 阶段 1：需求与机会

- 使用[机会记录](../../templates/delivery/opportunity-record.md)保留重复设置筛选的原始反馈、已知频率/耗时及限制；期望减少重复操作，缺数值时明确可观察判据、基线获取方式和负责人。
- 门禁：按[六项标准](../workflows/01-demand-and-opportunity.md#决策门禁)明确对象、价值、初步范围、隐私边界、不保存自由文本的非目标和责任；仅批准澄清。关键价值未知则先有限验证，非关键指标留阶段 02，不提前规定实现或承诺日期。

## 阶段 2：澄清与立项

- 用[需求与风险包](../../templates/delivery/requirements-risk-package.md)明确首次使用、保存、清除、跨设备、无效值、未登录、后端失败和旧客户端的可观察结果、判断方法、稳定验收 ID/来源及适用非功能要求；缺关键规则留阶段 02，不交技术方案默定。
- 风险从初步中风险重新评估：本场景涉及新增数据库列及后续存量数据/schema迁移时，命中既有数据迁移高风险触发，按高风险补控制和专业评估，不因标题/偏好数据低敏/迁移可逆沿用中风险；若经核对确无迁移或其他高风险触发，保留事实依据再判断。进入方案前必需评估实际完成，后续设计/CI/迁移恢复验证有责任、节点、证据和失败停止动作，不能将排队视为通过。
- 依赖分已识别/待确认/已确认，接口负责人需接受具体条件才算确认。已明确需求的缓存/兼容技术未知可在负责人、验证判断/探索退出/失败动作齐全并获实际批准的范围进入阶段 03；改变保存/清除含义的依赖先澄清，不把未交付环境标成当前可用。
- 注入：产品要求“保存全部搜索词”。记录风险/隐私/验收基线变化、失效证据和受影响范围回阶段 02，由相应有权角色重评；未受影响范围核对原授权后可继续，不自动取消整个需求。满足[七项门禁](../workflows/02-refinement-and-initiation.md#决策门禁)且实际批准仅可进入方案。

## 阶段 3：方案与计划

- 用[方案记录](../../templates/delivery/solution-decision.md)按已确认跨设备需求和约束比较本地/服务端方案的实质取舍，说明选定理由；定义schema、默认值、版本兼容、幂等更新、缓存失效和清除失败语义，不静默补阶段02未定规则。沿阶段02实际风险重评，迁移触发按高风险控制。
- 注入：旧客户端忽略新响应字段、更新不发送新字段。为消费者、缺失值和兼容次序定义判据；需要编码验证时属于阶段03技术预研，独立worktree固定问题/源码/授权/投入上限，保留实际试验环境/原始结果/局限。原型不自动进入实现；成功/失败/无结论先将可复验代码、配置、数据说明及证据保全到工作区外，再核对未提交/忽略材料和使用者并清理。
- 在[验证矩阵](../../templates/delivery/verification-matrix.md)区分当前必需的兼容/可行性证据和后续单元、契约、数据库、缓存、端到端、性能/恢复验证，列责任/节点/证据/失败动作，不将mock或小规模结果当真实集成/生产通过。
- 计划包含兼容、迁移、缓存、测试、观测、文档/译文、评审和恢复等适用成本，列顺序、依赖真实确认、实际接受责任/容量及估算区间。门禁：迁移恢复设计有必要依据，高风险本节点专业确认实际完成，后续演练不提前虚填；技术评审/实施准备/实际开发批准分别成立，仅推进授权范围。
- 注入：设计已过但接口负责人只有联系人、团队容量未接受，客户给出固定日期。保留技术结论、报告实施未就绪，不把估算或期望日期转承诺；独立就绪切片有隔离依据与实际批准才可先行。

## 阶段 4：开发与自测

- 按前端、API、领域数据和缓存边界连接完整保存/清除切片；迁移兼容旧代码、缓存与服务端事实一致。沿02迁移触发保留高风险控制，不能因偏好低敏或可逆降级。
- 正常、空/非法值、依赖失败、取消/竞态、缓存陈旧和适用事务/恢复有可区分正确错误的行为断言；前端按钮未接通不能由组件和API单测绿代替。日志不记录完整偏好载荷。
- 用[变更交接](../../templates/delivery/change-handoff.md)和验证矩阵保留当前SHA/摘要、范围/授权、接口/迁移/配置、原始自测结果/全部重试、文档译文及发布恢复影响。既定05真实依赖/系统验证只填计划与责任/判据/证据/停止动作。
- 注入：API测试绿但原定04数据库/缓存失败恢复没执行，或已有必过测试失败但另开Issue。保留原失败/缺口、定位负责人和最小解阻，不删测、不豁免、不事后改挂05；可Draft诊断，未满足正式交接。
- 门禁：本阶段完整集合实际通过、配套与当前证据齐备才待评审；已批准仅客户端/mock切片只交限定范围，不声称完整端到端。自测后改锁文件或rebase评估影响并重验，05接收不等于验证通过。

## 阶段 5：集成验证

- 对当前候选执行完整CI、非作者需求/实现/测试/运行/文档评审及触发的契约、迁移/恢复、缓存、权限等专项；迁移高风险不因场景标题medium降级。核心与本次保存/重登恢复/清除端到端在合入前后实际运行，验证真实适用服务/存储链路。
- 注入：基础CI绿，端到端清除后旧缓存仍恢复筛选。阻塞合入，保留原报告，回04修复并重验/独立复审受影响路径；不能标偶发、只改断言或关闭线程当已解决。若清除业务含义不清回02，不临时定义正确行为。
- 在[验证矩阵](../../templates/delivery/verification-matrix.md)记录当前head/base及实际构建/依赖/数据、用例/判据、首次失败/全部重试、原始证据和独立结论，以[变更交接](../../templates/delivery/change-handoff.md)汇总；合入后绑定实际main SHA，旧绿不能套新锁文件/rebase候选。
- 注入：A保存与B列表改动连续合入，B仅测列表为绿，A运行被取消。分别保留A/B精确版本/完整集合/责任，A补跑；B不能因包含A代码就替A通过。完整单项可去重或共享报告但逐项覆盖有依据，不免每次前后必需执行。
- 门禁：合入前全部条件满足才可合入；实际合入后端到端失败保留已合入/阶段未完成，暂停失败版本发布，按授权修复或回退并验处置后版本。修复通过交功能，回退仅恢复基线另记未交付/后续任务；06仍核对候选/环境/生产授权。

## 阶段 6：发布与变更管理

- 用[发布记录](../../templates/delivery/release-record.md)关联05精确main及前后端到端/独立证据，固定偏好功能候选、完整组合、制品、配置/开关/兼容迁移；分发同一制品，生产必要签名转换有映射并验实际物。A/B逐PR通过不替代组合风险验证。
- 有效授权绑定候选/环境/动作/范围/批次/窗口及停止恢复；先兼容迁移再内部/小流量，实际验偏好写入读取/清除、API错误、延迟/缓存与数据，按预设时间/样本观察。部署及观察期协调冲突配置/迁移/开关。
- 注入：10实例7新3未知且控制端超时。暂停扩大，核对版本/迁移副作用和仍执行目标，不整体盲重试；证据支持安全续跑时用新关联执行记录，候选或范围改变先补受影响验证/批准。取消不能写未执行并删除日志。
- 门禁：目标全范围及[八项成功条件](../workflows/06-release-and-change-management.md#最低成功完成八项标准)满足后07显式接收；部分成功记录混合兼容/期限/责任。前滚新候选重新验证授权，恢复旧版不记偏好功能成功；遗留的临时开关有退出条件。

## 阶段 7：运行与支持

- 保留技术/功能使用、清除失败和支持反馈监测，用户可关闭功能且旧客户端继续正常工作；大范围错误筛选/列表不可用关联发布批次及实际缓解恢复。
- 按[07契约](../workflows/07-operations-and-support.md)正式接收偏好功能实际版本/开关/迁移/兼容/恢复及遗留，确认监控手册和处置能力。若严重影响仍在而材料不齐，应急接管明确范围/缺口，不倒填06成功。常规检查/支持用[运行与支持记录](../../templates/delivery/operations-record.md)，事件另用[事件记录](../../templates/delivery/incident-record.md)。
- 从真实保存/重启读取/清除、缓存与数据一致性监测，核对口径/窗口/有效样本；多个信号关联主事件保留原时间影响与工单沟通，供应商故障本方继续协调。工作时段和值守不虚构，确认/初分诊/更新/恢复时钟分开。
- 注入：修复请求超时但偏好已写入。先对账实际数据/仍执行及副作用，再安全重试；原失败不删。备份job绿而恢复失败保持未验证，演练实测恢复数据/关键路径和耗时损失目标；告警200不替代用户保存读取正确。
- 已缓解/已恢复/可关闭分开，降级须事前最低标准与限制/期限，数据仍错保持部分恢复；复发重开关联并保留区间。08接收事实/口径局限/失败、防护和行动责任期限判据，未恢复责任继续，不把长期改进登记当已做。

## 阶段 8：度量与复盘

- 使用[效果复盘与行动](../../templates/delivery/outcome-retrospective-actions.md)比较重复设置次数、任务耗时、采用率和护栏指标，区分相关性与因果性。
- 将缓存测试缺口或迁移经验转为有所有者、期限和效果判据的行动。

## 演练通过条件

- 初步风险结论须与实际数据、接口、缓存及迁移边界一致；命中迁移等高风险触发必须升级控制，范围扩大重新评估。
- 缓存端到端失败确实阻塞合入，修复证据对应最终 SHA。
- 发布批次、开关和兼容迁移可恢复，结果记录能追溯到原始成功指标。
