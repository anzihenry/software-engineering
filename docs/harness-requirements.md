# 规范落实矩阵与来源清单

## 来源与使用边界

[机器清单](harness-requirements.json)固定盘点基线与每个来源文件 SHA-256，覆盖入口、通用规范、八阶段 workflow、所有 SKILL 和操作参考、中文交付/文档模板、兼容与升级规则。英文模板作为中文来源的 translation 引用，不建立第二套要求 ID；模板双语语义仍由独立验证负责。

清单保守登记所有非示例正文行，包含显式强制要求、执行指令、建议和背景；它不是关键词搜索结果的“强制条款总数”。一行包含多项约束时，共用来源 ID，验收必须逐项回应完整原文，不能只验证摘要前 160 字。代码示例和 frontmatter 由文件摘要绑定并由内容评审核对；不能把示例值当生产要求。强制/指令分类是维护辅助，原规范及其适用条件具有权威。

每项 ID 由来源路径、章节和原文摘要确定。原文变化需建立新 ID，并在 retired 记录旧 ID、原因、owner、正式决定和 replaced/retired 类型；replaced 列替代 ID，无替代的正式 retired 保留空列表；只移动行号不改变 ID。未经正式规范变更不能把要求删除或改成建议以获得通过。来源内容由规范文件维护，清单只保存定位、简短摘要、完整行摘要与执行引用。

## 执行映射

条款逐项绑定一个或多个 controls，跨领域条款同时消费各自执行路径；control 的实际触发条件需与原文交叉判断。以下方法对内容判断类要求提供可执行的人工/独立 Agent 路径，不代表这些要求都已由工具强制。

| control | 适用要求与节点 | 执行主体与方法 | 失败后果 | 必需证据 | 正例与反例 |
| --- | --- | --- | --- | --- | --- |
| coding | 代码实现、语言约束、代码评审 | 开发者按语言参考和项目命令执行；非作者评审不可机械判断项 | 阻止对应实现交付，修复后重验 | 实际版本、配置、格式/静态分析/构建/测试报告和逐项评审 | 合法实现及当前报告可交接；越级语法、隐藏失败、缺授权依赖不能通过 |
| branch | 修改、同步、恢复和清理前 | git-branch-management 读取 git/worktree/PR 实态 | 停止对应操作，先保护工作和恢复任务归属 | base/head、fetch、任务归属、恢复/清理核对 | 任务分支可执行；默认分支修改、待保留工作清理被阻止 |
| documentation | 文档准备、合入、专题完成、发布 | 文档维护、非作者验证和 check/snapshot/gate | 必需缺口阻塞，相关变更重验 | 九领域影响、原始报告、当前快照、独立评审和语言核对 | 当前记录可通过；缺译文、自评、旧摘要不能通过 |
| governance | 首次采用、合入判断、治理漂移 | gh 实态读取、授权 bootstrap、doctor 回读 | 治理未完成，不报告受保护合入就绪 | 真实 check/App、PR、当前规则和回读结果 | 有效保护可继续；只有设置文件、缺 check 或 bypass 不能通过 |
| content | 资产创建、责任变化、复审 | 仓库自检与独立资产内容评审 | 阻止资产交付 | 治理元信息、路由、复审依据、摘要 | 实质复审可续期；过期、缺 owner 或仅批量改日期不能通过 |
| automation | PR、候选、事故、安装、升级和诊断 | 固定版本工具、离线矩阵与真实 canary；人工核对责任边界 | 命令非零即停止相应后续写入，不放宽门禁 | 输入、不可变来源、运行报告、权限、状态和漂移结果 | 幂等/安全更新可执行；冲突、浮动来源或未授权写入被拒绝 |
| trust | 当前候选的独立评审来源与真实 CI | 受信维护者核验独立来源，固定 trusted_review 读取器通过 gh 回读 | 缺来源或身份/权限/候选漂移阻塞，不自填批准 | 不可变 envelope、实际 publisher、原始报告、head/base/merge 与真实 CI | 来源和候选一致可交接；自评、作者可改批准、伪造 CI 或旧候选拒绝 |
| lifecycle | 需求、设计、领域验证、发布、运行和复盘 | 来源 SKILL 的工作方式/停止条件和阶段 workflow，由阶段责任人执行、独立验收 | 停止当前推进或按原文回流/升级 | 要求到场景/阈值/实际证据映射、风险/决定/责任和当前环境 | 完整满足原条款可交接；关键风险未知、证据缺失或未经授权推进被阻止 |

执行细节以来源章节为准；例如领域 SKILL 直接定义环境、场景、停止条件，其 control 不替代这些局部约束。清单对 harness 能力标记 manual-executable/reference；所有目标采用状态固定 unverified，具体项目状态由采用记录维护。

## 检查与维护

运行 `.venv/bin/python scripts/requirements_check.py` 或仓库自检，核对全部来源、原始正文单元、唯一 ID、摘要、定位和执行映射。源文件变更、新 SKILL/模板、遗漏或伪造采用状态使检查失败。摘要更新不构成内容批准；独立评审须读取变更、完整原文与作用边界，核对分类/映射，确认没有通过改清单隐藏约束。

新增源文件或调整职责时更新清单及 workflow/skills 导航；规则替换保留 retired 关系。矩阵结构通过不证明语义覆盖、执行真实性或目标采用，必须与独立内容验证及项目实际证据一起使用。

## 矩阵初始交付影响

新增本矩阵、来源清单、确定性覆盖检查及行为测试，并接入仓库自检和根入口。原规范保持原职责；无新 SKILL，不改变领域路由。此为中文 harness 资产，无新增目标项目双语模板。研究/产品/设计/运行/正式发布没有行为变化；工程检查、计划和导航已更新，真实项目采用结论由独立采用记录维护，不能由矩阵清单推导。

## 合入与历史可达性

CI 使用完整 checkout（fetch-depth: 0）读取当前候选的全部 catalog 变更历史，累计历次要求及退役 ID；不能用 HEAD 清单与自身比较来掩盖已提交删除或基线改写。基线提交与历史引用必须在新 checkout 可访问。Squash 及自动删任务分支前保留原已验历史的非发布证据 tag；本轮为 harness-evidence/p0-2026-10-12，指向 d024b58586d57aa49e73abbf509a7dbfcb8364d6，保全固定盘点基线 ce6e7b97446d4734e421fe021501a041a77f08cd 和试点知识 952e840752741431c027097b5c242b7bc7fa3be5。此 tag 不表示版本发布，不取代固定 SHA 或独立验收，后续不得删除仍被有效证据引用的原始对象。
