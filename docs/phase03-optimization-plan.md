# 阶段 03：方案与计划优化计划

## 已确认目标与基线

阶段 03 完成定义：对明确范围形成有证据支持的方案和可执行计划，并取得实际开发批准。技术评审、实施准备与实际开发决定分别记录；方案批准不自动生成开发、日期或生产授权。用户逐项确认以下设计并授权按 S03-01 到 S03-04 实施，每包验证/独立复核后单独提交。

本轮从已 fetch 的 `origin/main` 基线 `500ef8678bf8c93ef78d401686ddf77c87d4a4f5` 建立 `codex/phase03-solution-planning`；该基线已包含阶段 01/02 和 Swift 最低 6.4 编码规范。初始主工作区干净，无其他活跃 worktree。本轮是 harness 维护，正常修改在任务分支；预研编码的 worktree 要求属于被维护的执行契约及隔离试用，不能把资产维护说成已开展产品预研。本轮交付为本地提交，后续推送、合入或发布按实际另有授权执行。

依据：[阶段 02](workflows/02-refinement-and-initiation.md)、[阶段 03](workflows/03-solution-and-planning.md)、[阶段 04](workflows/04-implementation-and-self-test.md)、[质量门禁](quality-gates.md)、[文档规范](documentation-standard.md)、[分支规范](git-branch-workflow.md)。不改变目标项目目录组织或现有安装器/可信来源权限。

## 设计契约

方案最低标准为：回应当前需求/验收与原约束；关键边界、交互/状态及失败行为清楚；选择与取舍有依据；关键可行性有必要证据；适用契约/兼容/迁移与恢复明确；验证安排可执行；本节点适用设计/专业评审实际完成。深度随风险和任务调整，小任务可几条说明，有实质选择才比较备选，不强制六份文档。保留用户指定方案，不以技术偏好改需求。

未知按影响分类：方案成立、安全或关键投入未知先验证；高风险影响/控制未知先补适用专业评估和必要验证；不影响验收/风险/投入的细节可限定边界/负责人/确认节点带开发；业务含义缺失回阶段 02；依赖实际确认与技术验证结果分别保留。

技术预研属于阶段 03，回答方案能否落地。需要编码时在独立 Git worktree 探索，先按 Git 分支规范核对归属/实际基线与权限；无 Git 项目先建立经授权的隔离 Git 预研载体，不能把普通副本当作满足 worktree。记录问题、判断条件、负责人/授权、投入上限、数据/环境/操作边界。保留实际命令、版本/环境/规模、原始结果、局限及通过/不满足/证据不足。达到上限或新风险停止扩大并重新决定；原型成功不证明生产可用，代码不自动合入。收口前将必要可复验代码/脚本、配置、数据说明、原始报告和结论保存到工作区外可追溯位置，核对摘要和复验方法、未提交/忽略文件及其他使用者，再清理对应 worktree/临时分支；必要保留材料不得随目录丢失，支持时优先可恢复归档。成功、失败、无结论均有明确收口/下一步，不强删未知归属工作区。

可执行计划绑定范围/基线，切片可审查/验证，计入实现、测试、文档及译文、迁移、观测、独立评审、发布准备和运行交接等适用成本；列顺序/关键路径、真实依赖、实际接受责任和容量/已有承诺、规模/区间及依据、重估触发。估算、计划、实际开发承诺区分；工作量不直接换成日期，期望日期不等于接受承诺。

技术评审、实施准备和开发批准各有实际对象/范围/证据/责任；前置阻塞与本节点必需确认完成后才可推进。后续节点验证列负责人、节点、证据和失败动作，不虚填提前通过。部分批准须证明接口/数据/权限/发布依赖可隔离，不以公共代码夹带未批准能力。已有有效覆盖授权可引用，Agent 建议不产生权限或重复请求仪式。

方案沿用六状态：探索中、待评审、已批准、有条件批准、已否决、已取代；状态表示方案对象，实施准备和开发授权另列。条件未满足不启动受影响开发；明确独立就绪范围可单独批准。基线引用需求、方案、预研证据/剩余未知、契约/恢复/验证、计划/依赖/容量及实际决定；转换保留原/新状态、理由、主体/权限、带时区时间、依据，旧批准缺材料保留历史并当前重评，不补造。

变更按影响处理：纯措辞原记录修订；原边界内实现细节由阶段 04处理；关键技术/契约/迁移/恢复回阶段 03；业务/验收/成本约束/风险反馈阶段 02；用户/价值/优先级回阶段 01；容量/依赖/时间重评计划及承诺，不自动否定技术方案。保留失效证据、受影响范围及可继续/需等待工作。

交阶段 04 七项：需求/批准范围、方案关键决定、证据/剩余未知、实施计划、验证/质量要求、后续控制/文档任务、实际开发批准。启动核对版本/授权、当前任务前置、阻塞已解、实际规范/配置/命令可用；不要求全部后续资源提前交付，mock不证明集成通过。只在一个主记录维护交接和决定，任务状态留原系统，六技能按缺口组合。

## 场景与失败判据

| ID | 原始场景 | 必需观察 |
| --- | --- | --- |
| C01 | 小型文案修正 | 轻量方案、有效既有授权引用，不凑备选/六份文档，不自动日期/发布 |
| C02 | 本地SQLite能力未知，获有限编码预研授权 | 真正隔离worktree、实际命令/结果，保留可复验材料后清理，不自动合入 |
| C03 | 指定候选实现对验收失败 | 真实失败证据保留、不降低判据，调整方案或回流，失败worktree正确收口 |
| C04 | 预研到投入上限且无结论 | 停止扩大，保存未完成状态/材料，决定待确认，不能假成功或自行追加 |
| C05 | 小规模原型成功欲直接推全量生产 | 限定结论、不当生产能力证据，补关键可行性证据 |

| C07 | 设计已通过但容量/责任未确认且期望日期紧 | 设计结论保留、实施未就绪，不生成开发承诺/固定日期 |
| C08 | 只读就绪、付款待评估，要求先写公共代码 | 按隔离依据/实际批准限定范围，不能夹带付款能力 |
| C09 | 高风险评审排队，恢复演练需实现后执行 | 本节点必要评估实际完成；后续验证不提前伪填，也不关键路径全未知放行 |
| C10 | 有条件批准与旧已批准缺来源 | 条件前置不放行、保留历史并当前补证重评 |
| C11 | 局部细节/技术契约/验收/价值/容量分别变化 | 分别路由04/03/02/01/计划重评，限制失效范围 |
| C12 | 方案/验证中英模板变异 | 实跑缺译文/元信息/双向互链/字段/未登记英文拒绝，保留旧配对覆盖 |
| C13 | 启动时版本或依赖失效，mock仍成功 | 重新核对授权/前置，只停受影响，mock不证明集成成功 |
| C14 | worktree中有未保存/忽略的必要材料或其他任务 | 先保全并核对再清理，不丢证据、不强删他人工作 |

原始输入不提供本表答案；前向 Agent独立读取 workflow/技能/模板，实际输出、命令、输入/执行资产/产物摘要及限制保留。C02–04仅用隔离合成Git仓库和现有Python，无外部系统/真实数据/依赖安装；不把该行为验收当产品技术结论。C12实际运行已有临时副本行为负例。缺口由作者修正规则/资产后重跑受影响场景，不改写原始输出消除失败。

## 检查、影响与交付范围

每包运行仓库四项：`ruff check scripts tests skills/05-integration-validation/github-actions-bootstrap/scripts`、相同范围 `ruff format --check`、`python -m unittest discover --start-directory tests`、`python scripts/check_repository.py`。工具沿现有 `.venv`的 Python3.14.8/Ruff0.16.7/PyYAML6.0.3，无需升级或新增生产依赖；改变源码先读编码SKILL/common/Python并使用已提交配置。六技能quick_validate；负例验证可观察错误而非复述正文。报告绑定当前提交或完整路径/摘要/执行位快照，记录实际命令、时间和退出码；相关变化后重验，独立文档验证不可作者自批。

初步九领域影响：research不适用（无真实产品研究，技术预研为合成规则/行为验收）；product/design目标文档无需更新（无目标产品/架构，适用输出模板更新）；engineering更新执行契约/检查测试；guides更新workflow/技能/演练及Git预研路由；planning本计划及逐步验证；initiatives不适用（harness资产）；releases/CHANGELOG不适用（无发布）；入口/导航/要求清单随源资产更新。逐包补实际文件/理由，保留已有组织/治理/追溯契约。中文harness规则/操作参考无需英文；触及目标输出模板必须中英同步、互链及独立语义核对，不扩大整库翻译迁移。

本地规则/合成试用不证明所有目标项目已采用、真实批准身份、远端CI或生产已验证；实际开发、CI和发布属于各自后续节点。此前阶段01/02和Swift6.4成果保持原版本证据，不能用新规则改写旧报告。
