# 阶段 3：方案与计划

## 目标与完成边界

对明确范围形成有证据支持的方案和可执行计划，并取得实际开发批准。技术评审、实施准备与实际开发决定分别记录；方案批准不自动产生开发、日期或生产授权。允许只完成并批准有明确隔离依据的独立切片，其余范围保持真实探索/阻塞情况。

## 输入

- 按[阶段 02 门禁](02-refinement-and-initiation.md#决策门禁)批准投入方案的当前需求基线、行为/NFR验收、风险/必需控制及责任/节点/证据、依赖事实、未知的负责人/验证目标/判据/退出与失败动作、批准范围/限制及原指定方案/假设性质。缺上游批准可整理草案，不伪造就绪。
- 现有架构、交互/状态、数据/接口、实际工具链/配置、运行基线、平台能力、容量/已有承诺和项目权限。保留原约束（包括用户指定方案），不把拟议控制或未来依赖当现有能力。

## 流程

1. **回应需求并选择方案**：逐项映射验收/约束，明确边界、主流程和失败行为；实际触及体验时补交互/状态设计。存在实质取舍才比较备选，小任务可简要说明；不为形式凑多个方案或静默改变需求。
2. **处理关键未知**：按本 workflow 分类；需要编码确认可落地的工作属于技术预研，使用独立 worktree并按下节收口，不能将原型代码自动转正式实现。
3. **设计契约、验证与恢复**：明确适用消费者、版本/兼容、错误/权限/幂等、数据不变量、迁移顺序和失败恢复；将验收/风险映射到验证方法/判据/环境/责任/节点。区分已验证事实、本节点必需证据和后续验证。
4. **形成可执行计划**：拆分可审查/验证工作，完整计入适用成本，核对顺序、真实依赖、实际接受责任/容量和估算依据。不将估算或期望日期当承诺。
5. **分别评审与决定**：技术评审和实施准备符合当前范围要求后，由有权角色实际批准开发；保存版本、范围/限制、理由、权限/来源及带时区时间。Agent建议不产生权限，已有有效且覆盖当前范围的授权可核实引用，无需重复确认仪式。

## 方案与设计最低标准

| 标准 | 最低内容 |
| --- | --- |
| 需求回应完整 | 关联当前需求基线，回应行为/NFR与原约束；无法满足回阶段 02 决定 |
| 关键设计清楚 | 开发无需猜测关键边界/流程/失败规则；按适用性明确交互/状态、权限、接口、数据 |
| 选择与取舍有据 | 选择理由、代价及实质备选（适用时），保留用户指定约束 |
| 关键可行性有证据 | 影响方案成立、安全或关键投入的假设已有必要验证，明确对象/版本/环境/规模/结果/局限 |
| 契约兼容与恢复明确 | 消费/提供方、版本、数据不变量、迁移和暂停/失败恢复可操作；代码回滚不等于数据恢复 |
| 验证安排可执行 | 验收/风险有方法、判断条件、环境/数据和责任，标明何时完成与失败停止范围 |
| 适用设计评审完成 | 针对当前方案的本节点必需评审实际完成、阻塞已解、剩余事项有去向；队列/作者自述不替代 |

深度按任务与风险裁剪，小任务几条说明即可，不强制统一句式、图表或六份文档；不适用须说明事实理由。局部实现细节可留编码，影响方案成立的决定不能只写开发时再看。

## 未知项与技术预研

| 类型 | 去向与推进 |
| --- | --- |
| 方案成立的关键未知 | 核心性能、平台能力、关键投入等先取得必要验证，再批准依赖该结论的开发 |
| 高风险影响/控制有效性未知 | 补适用专业评估与必要验证，不能用普通原型/排队替代确认 |
| 可限定实现细节 | 不影响验收/关键风险/投入判断时，列选择边界、负责人及确认节点带开发；越界重评 |
| 需求含义缺失 | 业务/范围/验收回阶段 02，不用实验替业务决定；用户/价值/优先级失效回阶段 01 |
| 依赖能力或条件未知 | 实际接受条件和技术验证分开，按阶段 02 依赖规则确认；mock成功不证明真实可用 |

技术预研记录问题及所影响决定、支持/否定/证据不足的判断条件、负责人/判断人/实际授权、时间或成本上限和允许的数据/环境/操作。达到上限、新风险或需要扩大投入时停止扩大，保留事实，由有权角色决定追加、调整/缩小方案或停止。预研通过只对已验证范围成立，不把小规模成功推为生产可用。

### 编码预研的 worktree 生命周期

1. 需要编码的技术预研必须使用独立 Git worktree；先调用[Git 任务分支管理](../../skills/04-implementation-and-self-test/git-branch-management/SKILL.md)，按[分支规范](../git-branch-workflow.md)检查归属、状态/其他worktree和remote，固定与本次判断对应的源码基线，创建/复用本次专用预研 worktree及任务分支。无Git项目先建立经授权的隔离Git预研载体，未具备时不在正式目录编码或以普通副本宣称满足隔离。
2. 原型、临时依赖和实验配置留预研worktree；遵守[编码规范](../../skills/04-implementation-and-self-test/language-coding-standards/SKILL.md)及项目实际必过检查，记录实际命令/版本/环境/规模和原始结果。不改正式工作区或默认/受保护分支；worktree仅隔离文件，不扩大外部系统/数据/安装权限。
3. 保存通过、不满足或证据不足的实际结论及局限；成功、失败、无结论均需明确后续决定，不自改判据或追加投入。原型不自动合入；需要复用的代码按明确选择、整理、项目检查和正常评审纳入已批准正式范围。
4. 清理前将必要可复验代码/脚本、配置与数据说明、运行方法、原始报告和结论保存到worktree外的可追溯位置，绑定版本/摘要并核对可读/复验路径；敏感材料只引用受控标识。检查未提交/未跟踪/忽略文件、其他任务/使用者、仍需复验的材料和实际授权，不能随目录丢证据。
5. 预研结束且不再需要工作区后，清理准确目标worktree及不再使用的预研分支；支持时优先可恢复归档，遵循分支规范的squash/其他worktree检查。归属不清、必要材料未保全或仍有任务时保留并说明解阻，不强删；保全完成再清理。记录路径/分支、原HEAD、证据位置、实际归档/移除结果和时间。

## 可执行计划

计划绑定需求/方案版本、批准候选范围/非目标，任务有产出/完成条件、顺序/关键路径/可并行部分及实际依赖所需节点。技术任务可以按模块拆分，但须映射到完整结果，不能用层级任务的完成代替验收。

计入实现、测试、文档/翻译、迁移、观测、独立评审、发布准备、运行交接等适用工作及预研投入；估算给规模或区间、依据/假设/不确定性，区分工作量与日历耗时。负责人实际接受任务，容量核对已有承诺和专业支持，Agent不代团队接单。依赖采用阶段 02 的真实确认/交付状态，不把联系人或路线图当可用资源。

估算是判断，计划是可执行顺序，开发承诺是有权实际决定；期望日期只是约束，需要日期承诺时另核对相应范围、容量、依赖和验证/评审/发布准备。记录验证失败、依赖延迟、容量或范围变化的重估触发与可继续/需等待范围；任务状态仅在原任务系统维护。

## 决策门禁

| 判断 | 责任与证据 | 可产生的结论 |
| --- | --- | --- |
| 技术评审 | 与风险相称的评审者及适用独立/专业角色，针对当前版本核对七项设计标准 | 所审范围通过、修订后复审、补专项或退回；不替开发授权 |
| 实施准备 | 实施负责人会同实际依赖/资源责任人核对计划、必要前置和容量 | 本次范围可执行或缺口，不替他方承诺 |
| 实际开发批准 | 有权负责人基于当前需求/方案/计划和上述证据，记录范围/限制、理由、权限来源、带时区时间 | 明确范围的开发授权；不自动日期/生产授权 |

中高风险保留设计评审，高风险同时完成本阶段必需安全、合规与运维可行性确认；更严格领域要求优先。角色可兼任，明确要求独立的事项不可作者自批；Agent不替专业/高风险授权。按[质量门禁](../quality-gates.md)保留必需文档、译文、证据、独立性及必过检查，不用条件结论豁免。

阻塞项及本节点必需确认须实际解决/复核；后续才可执行的验证列责任/节点/证据/失败停止动作，不提前伪填。恢复设计须有合理可执行路径和必要可行性依据，实现/预生产恢复演练在对应节点完成；不能因尚不能执行后续演练一律阻塞，也不能以计划掩盖关键恢复路径未知。部分批准须证明接口、数据、权限和发布依赖可隔离，明确可开发及等待范围，不借公共代码夹带未批准能力。

## 方案状态与基线变更

本 workflow 是方案状态/推进规则来源；需求、方案、验证、任务、文档和发布状态不混用。一份主记录维护方案状态/owner、当前基线、交接与实际决定，附件引用，不复制任务进度。

| 状态 | 含义与退出 |
| --- | --- |
| 探索中 | 选择/设计或关键验证尚在进行，形成有据候选后再评审 |
| 待评审 | 候选基线及本次评审必要材料齐备，等待实际评审，不代表已通过 |
| 已批准 | 有权角色批准指定方案基线；仍分别核对实施准备与实际开发授权 |
| 有条件批准 | 保存实际决定及未满足条件；受前置条件影响的开发不能启动，不是条件放行 |
| 已否决 | 有权角色决定不采用该候选，保留理由/证据/成果处理；新候选重新评估 |
| 已取代 | 明确新基线或决策取代原方案，关联替代记录及历史适用范围 |

转换记录原/新状态、理由、实际主体/权限、带时区时间和依据；建议另列，不补造决定。固定可引用修订号/commit/摘要，关联需求、方案关键决定、预研证据/剩余未知、契约/恢复/验证、计划/依赖/容量、评审和实际批准。已有记录版本或Issue修订可用，不强制新版本系统。旧已批准缺版本/范围/来源时保留历史和缺口，补当前证据重评，不恢复旧就绪或伪造批准。

| 变化 | 处理 |
| --- | --- |
| 纯措辞/排版且含义不变 | 原记录修订并留理由，无需重走全流程 |
| 原授权边界内实现细节 | 阶段 04 按项目规则处理，相关设计记录同步 |
| 关键技术、契约、迁移或恢复变化 | 阶段 03 复核受影响设计/证据/计划及是否重新批准 |
| 需求/验收/成本约束/风险变化 | 按阶段 02 规则确认后更新方案/计划，保留高风险门禁 |
| 用户/价值/优先级变化 | 回阶段 01 判断投入方向 |
| 容量/依赖/时间变化 | 重评受影响计划/承诺，不自动否定技术方案；若影响上列条件按相应路由 |

实质变更保留原/新基线、原因、影响下游/失效证据、复核/实际决定及可继续/需等待范围；未受影响且仍在有效授权内的工作可继续，旧批准不覆盖新增范围。

## 文档治理

专题保存方案过程，长期体验规则和技术契约分别归入 design 与 engineering。长期技术决策使用编号记录并保留替代关系；计划明确文档更新、双语同步、实际检查和独立评审任务，任务状态只维护一次。

遵循[项目文档规范](../documentation-standard.md)和[接入说明](../documentation-integration.md)。[文档维护](../../skills/04-implementation-and-self-test/documentation-maintenance/SKILL.md)负责准备与更新，[独立文档验证](../../skills/05-integration-validation/documentation-delivery-validation/SKILL.md)负责检查结论，使用[统一交付检查模板](../../templates/documentation/delivery-check.md)。缺少专用检查器时保留逐项实际核对证据，不能声称第三阶段自动门禁已启用。

## 输出与阶段 04 交接

使用[方案决策模板](../../templates/delivery/solution-decision.md)和[验证矩阵](../../templates/delivery/verification-matrix.md)，完整规则以本 workflow为准；模板按本轮计划适配，不能把文档存在当验证或批准。小任务可合写Issue，独立记录ID和全部追溯字段保留，需求/方案/验证各有其事实来源。

交接七项：当前需求与批准范围；方案关键决定；证据/局限与剩余未知边界/责任/节点；实施计划；验证/质量要求与实际命令；后续控制及文档/译文任务；实际开发批准及权限/版本/范围/理由/时间/来源。指定接收人及逐项响应位置，资料直接引用确定版本，无需复填六份文档。

启动阶段 04 核对版本有效、授权覆盖当前任务、任务所需前置/依赖/环境/权限成立、阻塞已解及规范/配置/命令可用。不要求全部后续资源提前交付；mock内工作只能在明确授权边界内推进，集成节点仍验证真实依赖。材料不可访问先补交接，技术缺口回 03，业务含义回 02，价值失效回 01，仅停受影响部分。

| 行为 | SKILL | 适用边界 | 产出 |
| --- | --- | --- | --- |
| 选择有据方案及技术预研 | [`solution-design-decision`](../../skills/03-solution-and-planning/solution-design-decision/SKILL.md) | 实质方案取舍或关键可行性未知 | 方案、原约束/取舍及worktree预研证据/收口 |
| 设计契约/兼容/数据演进 | [`contract-and-migration-design`](../../skills/03-solution-and-planning/contract-and-migration-design/SKILL.md) | 共享接口/事件/数据或迁移 | 契约、不变量、切换/失败恢复及真实确认 |
| 设计分节点验证 | [`verification-strategy`](../../skills/03-solution-and-planning/verification-strategy/SKILL.md) | 验收/风险需映射证据 | 本节点必要证据与后续验证/停止节点 |
| 设计环境推进与恢复 | [`release-recovery-planning`](../../skills/03-solution-and-planning/release-recovery-planning/SKILL.md) | 有环境/生产影响 | 控制路径/阈值/责任和待验证节点，不执行发布 |
| 形成可执行计划 | [`implementation-planning`](../../skills/03-solution-and-planning/implementation-planning/SKILL.md) | 需将方案转工作/依赖/投入 | 完整成本、真实容量/依赖、区间及重估条件 |
| 独立核对设计与必需评审 | [`technical-design-review`](../../skills/03-solution-and-planning/technical-design-review/SKILL.md) | 中高风险或明显跨边界；低风险按项目简化 | 当前范围技术评审结论，不替实施/开发授权 |

六技能按缺口组合，复用原材料，不分别创六份主记录。阶段 04 正式实现，阶段 05 集成/独立验证，阶段 06 实际发布；后端/Web按[领域执行契约](../domain-validation.md)固定完整触发、支持矩阵、预算/阈值和失败动作，缺环境不裁剪必过项。
