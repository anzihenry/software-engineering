# 阶段 3：方案与计划

## 目标

选择满足验收标准且在安全、可靠性、成本和可维护性之间取舍合理的实现路径，并使交付可计划。

## 输入

- 已立项的需求包、验收标准、风险等级、依赖与非功能要求。
- 现有架构、运行基线、平台能力、团队容量和相关技术约束。

## 流程

1. **探索方案**：识别最小可行方案及有明显差异的备选方案；评估对架构、数据模型、接口、权限、性能、成本和运维的影响。
2. **选定设计**：记录关键决策、取舍和被否决的方案。涉及外部或跨服务接口时定义版本、错误语义、幂等性、兼容性和迁移策略。
3. **设计验证策略**：将每条验收和非功能要求映射到单元、集成、端到端、性能、安全或人工验收方式。
4. **设计发布与恢复**：明确特性开关、环境推进、迁移次序、监控指标、告警阈值和可执行的回滚/前滚方案。
5. **拆分与估算**：将工作拆成可审查的小变更，标出依赖、责任人和顺序；仅在关键不确定性被处理后承诺计划。
6. **评审并批准**：中高风险变更组织设计评审；高风险同时完成安全、合规与运维可行性确认。

## 决策门禁

进入“开发与自测”前，选定方案必须覆盖验收标准、数据和接口契约、测试策略以及发布/回滚路径；关键风险均有处置人。未验证的高影响假设应先做 Spike 或原型。

## 输出

- 技术设计与决策记录、接口/数据契约、测试策略、发布与恢复计划。
- 可估算的工作拆分、依赖图、风险及评审结论。

## 异常与回流

- 无方案同时满足约束：与业务负责人协商缩小范围、调整目标或停止立项。
- 设计改变了原验收含义：回到澄清与立项更新需求包。
- 依赖不可用：重排计划、引入替代方案或显式阻塞。

## 交接给下一阶段

交接已评审的设计、任务拆分、测试映射和发布预案。开发阶段不得静默偏离关键决策；如需调整，回写设计并重新评审相应风险。
