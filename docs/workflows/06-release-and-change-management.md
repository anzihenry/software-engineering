# 阶段 6：发布与变更管理

## 目标

将通过验证的版本以受控、可观测、可恢复的方式交付到生产环境或目标用户。

## 输入

- 经批准的版本/构建产物、测试证据、变更风险等级和发布候选说明。
- 部署配置、环境状态、监控与告警、发布窗口、迁移和回滚预案。

## 流程

1. **发布前检查**：确认版本可追溯、环境健康、所需审批已完成、依赖可用、仪表板和告警可用；高风险变更确认值守人和沟通计划。
2. **预演关键路径**：在适当的非生产环境验证部署、迁移、配置、健康检查和恢复操作。不能预演时应明确剩余风险。
3. **执行渐进发布**：优先使用特性开关、灰度、金丝雀或分批推进；每一步记录版本、时间、操作者和结果。
4. **观察并判定**：依据预先定义的业务、错误率、延迟、资源和 SLO 指标判定继续、暂停、回滚或前滚。
5. **完成发布**：在观察窗口内稳定后扩大范围或完成全量；更新变更日志、运行手册和利益相关方通知。

## 决策门禁

完成发布的条件是：目标范围已达到、关键健康指标正常、无未处置的严重告警、回滚能力在发布前已验证或明确接受风险。任何继续推进都必须基于观测结果，而非仅基于部署命令成功。

## 输出

- 已发布版本、变更记录、部署日志、观察结果和对外/对内通知。
- 发布结论：`成功`、`已回滚`、`前滚修复中` 或 `暂停`。

## 异常与回流

- 指标超过阈值：立即按预案暂停、回滚或前滚，必要时转入事故响应。
- 迁移失败：停止后续推进，按恢复计划处理数据一致性并升级风险。
- 发布窗口失效：保持当前稳定版本，重新计划；不要为了赶窗口跳过门禁。

## 交接给下一阶段

交接生产版本、上线范围、监控链接、观察期限、已知问题和支持指引给运行与支持团队。
