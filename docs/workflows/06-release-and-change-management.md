# 阶段 6：发布与变更管理

## 目标

将通过验证的版本以受控、可观测、可恢复的方式交付到生产环境或目标用户。

## 输入

- 经批准的版本/构建产物、测试证据、变更风险等级和发布候选说明。
- 部署配置、环境状态、监控与告警、发布窗口、迁移和回滚预案。
- GitHub source SHA、Actions 运行、Environments/Deployments、Release/标签及制品存储能力。

按[阶段05交接](05-integration-validation.md#输出与阶段-06-交接)核对准确范围/合入SHA、CI/独立/专项及对应main合入后必需端到端实际通过、问题处置和发布准备。合入后端到端未通过的失败版本不进入发布；回退恢复基线不等于原功能已交付。接收main证据不自动使发布候选verified，仍固定源码/制品并验候选、环境和生产权限。

## 完成定义与阶段边界

将身份明确且经过验证的发布候选，在有效授权下交付到批准的目标范围；完成该范围的发布后验证和规定观察，确认用户关键路径、服务与数据状态符合预设标准，并完成可追溯的运行与支持交接。

部署命令、上传、创建Release、商店审核、上架及实际安装分别记录；达到批准目标才成功。内部目标不强制全量生产，全量目标不能以灰度成功收口。阶段06负责本次规定观察和问题处置，阶段07接收持续运行。恢复成功可结束失败发布处置，但原功能仍未交付。

## 最低成功完成八项标准

1. 交接合格：05范围、实际合入SHA、必需验证/独立证据、问题及发布约束完整。
2. 候选固定：完整包含变更、源码/制品/配置/开关/迁移/依赖及验证映射明确。
3. 批准有效：有权人类单次/分段决定或预批准策略覆盖当前对象、动作、范围与窗口。
4. 执行可追溯：批次操作、实际版本/覆盖、偏差和异常保留。
5. 发布后验证通过：实际目标环境关键路径、配置和数据必需检查通过，05证据不替代本次落地核对。
6. 健康观察通过：预设观察时间、有效样本及全部必需指标满足。
7. 问题处置完成：无阻塞，恢复验证、剩余影响及允许遗留责任明确。
8. 收口交接完成：实际结果、适用双语文档、按计划通知与07接收一致且完整。

## 正式接收与候选身份

接收核对05的批准范围/验收、PR/实际main合入SHA、CI/独立/专项/前后端到端通过、问题处置、配置开关/依赖/兼容/迁移及观测恢复/文档材料。缺口退回受影响范围，保留有效证据；接收只允许候选准备，不自动获得候选verified或发布批准。

每个候选以唯一ID和修订绑定：源码SHA及完整包含变更/排除依据、基线/版本、每个平台交付对象的不可变制品标识/摘要、构建运行/工具链/锁定依赖、适用签名/SBOM/来源证明、目标渠道/配置版本/开关/迁移/兼容条件、源码/制品/目标环境验证映射及恢复目标。多个变更组合需覆盖最终组合新增风险与候选必需验证，不机械重跑所有历史测试，也不凭各自通过代替组合验证。main包含A/B而仅计划发布A时，说明B实际生效范围、隔离机制及证据；无法证明则按完整影响评估。

同平台同交付对象在环境间提升同一制品，不在部署时重建；多平台分别绑定摘要和证据。必要重新签名、打包或商店转换记录输入输出映射，并验证实际分发物。源码、依赖、构建参数或制品改变生成新候选修订；配置/开关/迁移/范围变化更新发布记录并重评受影响验证和授权。旧成功不自动覆盖新身份。

## 发布批准与有效期

就绪沿[质量门禁](../quality-gates.md)记录passed/conditional/blocked，执行授权单独记录为批准、待条件满足、拒绝/撤销。批准最低绑定候选ID/修订/SHA/制品、环境/渠道/范围、部署/分发/启用/迁移等动作、批次与最大覆盖、带时区生效/到期/窗口、条件核验机制、停止阈值/允许恢复/值守、批准人权限来源及决定证据。

支持单次、分段或人类预批准的低风险连续策略。预批准策略写允许变更类型、风险上限、自动检查、范围和停止/恢复规则，每次核对当前适用；既有有效授权范围内可按条件完成后续批次，不重复请求确认。Agent准备建议并执行授权动作，不代替有权人类生产决定。条件未完成不得执行；明确预授权指定机制核验条件后自动执行时，先保留核验并重新判就绪passed，再按授权推进；要求再次确认的仍须确认。必需检查/文档/独立性/人类高风险门槛不因预授权省略。

候选/制品变化，配置/迁移/开关/范围越界，窗口到期，值守/观测/恢复条件失效，新阻塞缺陷/安全风险/失败，授权撤销或冲突并发，均暂停受影响未执行动作，重验并按需重批。无影响的文字/链接修正记录理由可保留批准。发布前授权停止扩大及可行恢复；未覆盖的数据删除、不可逆迁移或扩大影响恢复须另取明确授权。

## 批次执行、互斥与中断

每批预先定义目标/起始状态、制品配置/迁移、顺序、验证/观察、超时/停止/恢复；风险和渠道决定单位，不硬套固定比例。执行顺序为开始前核对→操作→确认实际落地版本/摘要/范围→目标环境关键路径/数据验证→健康观察→推进决定。保留操作者/授权、起止时区时间、命令/workflow/deployment与原始结果；不只信job成功。

可能相互影响的部署、配置、开关与迁移协调互斥，覆盖部署和观察期；单个job的concurrency不自动覆盖跨workflow观察。并行需隔离依据，紧急介入先暂停原发布并记录现场。不得自动取消正在执行的生产任务而假设没有副作用。

超时/断线/取消记结果待确认，先核实已完成/仍执行/未执行目标、版本分布、数据及外部副作用，再决定安全重试/补偿/续跑；不可重复操作先对账。续跑建立新执行记录关联原记录，保留首次失败。部分成功默认暂停扩大，记录混合版本/范围/影响、兼容依据、允许期限和处置；不能把汇总成功掩盖失败目标。环境故障解除且候选/批准仍有效，可重验现场后继续；对象改变则更新身份/受影响验证及批准。

## 健康判定与恢复决策

发布前定义技术（可用性/错误/延迟/资源/依赖）、业务关键路径、数据完整性及影响范围的适用指标，逐项记录来源、基线/对照、阈值、统计窗口、最低样本和责任人。关键安全、数据损坏或核心路径失败可立即停止，无需等统计窗口。观察同时满足时间和有效样本；低流量可按事前约定补探测/实际路径/延长窗口，不能豁免必需真实样本。

健康只有四类：通过（全部必需条件满足，可按授权继续）；继续观察（时间/样本不足，保持范围）；异常（达停止阈值，停止扩大并处置）；无法判定（观测缺失/延迟/冲突，暂停推进修复证据）。监控无报错须核对监控有效；硬停止先控影响后归因，无法证明发布致因不等于可继续，也不盲目回滚扩大影响。

按实际可逆性、恢复时间、兼容性、数据风险和授权选择关开关/停止分发、旧制品配置、数据补偿恢复或经过验证的新前滚候选。严重/扩大/超出预案与责任范围转事故响应；安全隐私走07专项。恢复验实际版本/配置/开关、数据不变量及副作用、关键路径和稳定窗；命令成功不足，部分恢复保持剩余影响。恢复后明确终止、暂停或条件满足后继续；前滚关联新候选/验证/授权，原失败不可覆盖。

## 状态、结案与运行接收

沿既有单项结果，不另造检查状态；分别记录检查结果、就绪、执行授权、发布过程状态和最终结果。过程为候选准备、待批准、发布中、观察中、暂停、恢复中、已结案；最终结果为成功交付、取消、失败已恢复、失败转事故。旧记录的成功映射成功交付、已回滚映射失败已恢复（仅恢复验证完成时），前滚修复中/暂停仍为过程，不批量重写历史。

取消核实已有操作/副作用/残留及清理；失败已恢复需恢复验证和遗留交接；失败转事故需事故负责人正式接收、关联持续处置，事故未结不虚报恢复责任关闭。暂停/恢复中有责任人、下一动作、复查时间。只有八项满足才成功完成06，失败结案不使原功能成功。

07交接实际版本/制品/分布、配置开关/迁移/兼容期限、监控日志告警/值守升级、验证过的恢复方法与限制、已知问题/临时措施、后续观察/支持/遗留的风险责任期限判据；记录接收人和时区时间，同人兼任也显式接收。必需验证/文档/阻塞问题不得转待办豁免；双写/临时开关/旧接口有退出条件与清理负责人。通知按既定范围和授权执行，外发未授权则明确待完成，不自造已通知。

## 渠道组合与紧急通道

审核、上架、可下载、安装覆盖分别核实，按批准目标判定；自更新还验更新源、升级路径、失败及适用降级。多渠道分别绑定候选/批准/结果，必须协同的单侧成功仅部分完成；可独立交付须提前有拆分/兼容和总体验收依据。兼容窗口写支持版本组合、期限、发布/启用/迁移顺序、旧接口/旧结构退出证据和批准；首批成功不授权破坏性清理。公开同版本/标签/制品不得覆盖。

紧急仅当前严重生产影响或紧迫安全风险且标准时序不能满足恢复目标；记录事件/影响/目标/负责人/紧急授权与理由，只做直接缓解的最小变更。最低构建、目标测试/关键风险、独立审查、候选追溯、授权、停止/恢复和实际观察保留。无法完成的常规项逐项记缺口/风险/决定人/补验，遵守原不可豁免规则，不借紧急把not-run改passed。恢复后可记已缓解/恢复；主线同步、补验、文档、遗留交接、复盘行动登记及适用完成要求满足才关闭紧急变更，长期改进回正常流程。

## 流程

1. **登记变更并选择模式**：关联 PR、source SHA、风险、交付渠道和目标环境；选择标准发布、已预先批准的低风险连续发布或紧急变更。截止日期压力本身不构成紧急模式。
2. **准备发布候选**：固定版本和候选 source SHA，在受控 Actions 中只构建一次；记录每个制品/镜像/安装包的不可变标识和摘要，准备迁移、兼容范围、Release notes 与恢复目标。本仓库可先手动运行 `Prepare Draft Release` 的默认 dry-run；版本、main 可达性、required checks 及重复 tag/Release 均通过后，才用版本精确确认创建 Draft Release。
3. **执行发布就绪检查**：核对候选证据、环境/依赖、GitHub workflow 与凭据边界、观测、告警、特性开关、迁移、恢复、发布批次和值守安排，形成 Go/No-Go 建议。
4. **预演非生产路径**：将同一候选提升至 staging、内部测试或 prerelease 渠道，验证部署、迁移、配置、关键用户路径、健康检查和恢复操作；不能预演的风险必须显式保留。
5. **作出生产 Go/No-Go**：由有权限的人类确认发布范围和当前证据。GitHub Environment 支持审批时使用保护规则；独立开发者或套餐不支持时保留明确的 `workflow_dispatch`/决策记录，不让 Agent 代替人类批准生产动作。
6. **执行一个渐进批次**：优先使用特性开关、金丝雀、灰度、分阶段商店发布或分批部署；生产环境一次只允许一个部署，提升同一制品且不夹带新改动。
7. **观察并判定健康**：依据预先定义的业务、错误率、延迟、资源、数据完整性、用户反馈和 SLO 指标判定继续、扩大、暂停、回滚、前滚或转入事故响应。
8. **暂停并执行恢复**：达到停止条件时立即停止扩大范围；按授权优先关闭开关、恢复旧配置/制品、处理迁移或部署已验证前滚修复，并验证用户与数据实际恢复。
9. **完成目标渠道分发**：健康窗口通过后继续下一批次直至目标范围；服务、应用商店和包/Release 分发分别遵循其可恢复性和版本不可覆盖约束。
10. **发布收口与交接**：记录实际 source SHA、制品摘要、GitHub deployment、标签/Release、上线范围和最终状态；更新变更说明、运行手册、支持信息和复盘行动。

## 发布模式

| 模式 | 适用条件 | 可压缩内容 | 不可省略 |
| --- | --- | --- | --- |
| 标准发布 | 默认模式；普通中高风险变更 | 无 | 候选、就绪、生产决策、渐进/观察、恢复、收口 |
| 低风险连续发布 | 变更类型和自动恢复已预先批准，影响受控且观测成熟 | 可自动完成 staging 和预设生产批次 | 同一制品、硬停止阈值、部署串行、可恢复和完整记录 |
| 紧急变更 | 正在缓解严重生产影响或紧迫安全风险，标准时序无法满足恢复目标 | 缩短等待、评审和验证范围 | 事件/授权、最小 diff、目标测试、恢复、观测、主线同步和事后补验 |

## GitHub 小团队基线

| 控制点 | 建议实现 |
| --- | --- |
| 候选身份 | source SHA + 版本 + Actions run + 制品摘要组成发布清单；环境间只提升同一制品 |
| 工作流边界 | 候选构建、环境部署、健康/收口职责分离；重复逻辑使用同仓库 reusable workflow |
| 环境 | 至少区分 `staging` 与 `production`；使用 GitHub Environment 记录 deployment、限制分支并隔离变量/密钥 |
| 生产决策 | 独立开发者保留手动 Go/No-Go；微型团队可由另一维护者审批。套餐不支持 required reviewers 时不得虚构平台审批 |
| 部署互斥 | `production` concurrency 同时只运行一个部署；不自动取消正在执行的生产任务，以免遗留半完成状态 |
| 身份与密钥 | Actions 默认最小权限，云平台优先 OIDC 短期凭据；签名和发布密钥仅暴露给对应 environment/job |
| 发布记录 | GitHub Deployment 记录环境推进，Draft/Prerelease/Release 与标签记录外部分发；公开版本和制品不可原地覆盖 |
| Draft Release | `workflow_dispatch` 默认只读 dry-run；只有显式关闭 dry-run 且确认字符串精确匹配版本时，写权限 job 才创建候选，不自动公开或部署 |
| 旁路 | 管理员旁路只用于已授权紧急恢复，必须记录原因、范围、结果和后续补验 |

GitHub 某些 Environment 审批、等待或密钥能力受仓库可见性和套餐影响；流程应根据实际可用能力降级为明确的人工触发和审计记录，而不是删除生产决策门禁。

## 交付渠道差异

| 渠道 | 渐进单位 | 主要恢复手段 | 特别约束 |
| --- | --- | --- | --- |
| Web/后端服务 | 实例、区域、租户、流量或特性开关 | 关开关、旧制品回滚、前滚修复 | 数据迁移需保持兼容窗口，不能假设代码回滚会自动恢复数据 |
| 移动/桌面应用 | 内测、测试用户、商店分阶段比例 | 停止扩大发布、远程开关、服务端兼容、前滚版本 | 已安装客户端通常无法即时撤回，签名制品和版本号不可随意替换 |
| 库、CLI、镜像和下载制品 | prerelease、渠道、包仓库标签 | 撤下渠道、弃用、发布修复版本 | 已公开同版本不得覆盖不同内容，下游缓存和兼容范围需记录 |

## 决策门禁

按[质量门禁规范](../quality-gates.md)分别判断候选、生产、批次及收口；条件 Go 的前置条件完成并重验前不得执行，紧急恢复成功不关闭补验任务。

发布包含四个门禁：候选门禁确保 source SHA、制品和证据一致；生产门禁确保环境、授权、观测和恢复就绪；批次门禁确保健康数据支持继续；收口门禁确保目标范围、实际版本、运行交接和对外状态一致。任何继续推进都必须基于观测结果，而非仅基于部署命令成功。

## 文档治理

正式发布前独立验证版本级发布说明、兼容/升级指南、当前候选与文档检查证据。planned、verified、released 等状态必须符合实际，不以候选验收代替发布。收口时更新双语长期文档；专题 completed 还需文档同步、验收与遗留转交，不能仅凭发布成功关闭。

遵循[项目文档规范](../documentation-standard.md)和[接入说明](../documentation-integration.md)。[文档维护](../../skills/04-implementation-and-self-test/documentation-maintenance/SKILL.md)负责准备与更新，[独立文档验证](../../skills/05-integration-validation/documentation-delivery-validation/SKILL.md)负责检查结论，使用[统一交付检查模板](../../templates/documentation/delivery-check.md)。缺少专用检查器时保留逐项实际核对证据，不能声称第三阶段自动门禁已启用。

## 输出

- 发布候选清单、已发布版本、GitHub Actions/Deployment/Release 记录、制品摘要、变更记录、观察结果和对外/对内通知。
- 发布过程状态与最终结果按[结案规则](#状态结案与运行接收)分别记录，成功须满足八项标准；保留历史结果及失败证据。
- 使用[发布记录模板](../../templates/delivery/release-record.md)关联候选身份、Go/No-Go、批次、健康与恢复证据。

## 异常与回流

- 指标超过阈值：立即按预案暂停、回滚或前滚，必要时转入事故响应。
- 迁移失败：停止后续推进，按恢复计划处理数据一致性并升级风险。
- 发布窗口失效：保持当前稳定版本，重新计划；不要为了赶窗口跳过门禁。
- GitHub Environment 或套餐能力不可用：保留手动触发、最小权限和决策记录，不把技术限制解释为免审批。
- 紧急变更：进入受控快速通道，缓解后必须同步主线、补验并形成复盘输入。

## 交接给下一阶段

按[运行接收](#状态结案与运行接收)交接实际版本/分布、监控/恢复/兼容和遗留，由阶段07显式接收；规定发布观察未通过不提前成功收口。

## 固化为 SKILL

八技能分别消费本流程的候选组合/有效批准、批次中断、四类健康、恢复验证及八项收口要求；GitHub入口编排，叶技能只负责对应决定或已有授权动作，主发布记录统一追溯。

| 行为 | SKILL | 适用边界 | 产出 |
| --- | --- | --- | --- |
| 编排 GitHub 小团队从候选到发布收口 | [`github-release-management`](../../skills/06-release-and-change-management/github-release-management/SKILL.md) | 独立开发者或微型团队需要用 GitHub 串联候选、环境、部署、健康、恢复和 Release 时 | 当前发布状态、门禁、授权和下一动作 |
| 固定版本并准备可提升的发布候选 | [`release-candidate-preparation`](../../skills/06-release-and-change-management/release-candidate-preparation/SKILL.md) | 已验证提交需要构建、签名、生成摘要或 Draft Release 时 | 发布候选清单与候选就绪结论 |
| 核对版本、环境、审批、观测和恢复条件 | [`release-readiness`](../../skills/06-release-and-change-management/release-readiness/SKILL.md) | 发布候选进入目标环境前 | Go/No-Go 结论及未满足条件 |
| 按授权预案分批推进并记录每一步 | [`progressive-release-execution`](../../skills/06-release-and-change-management/progressive-release-execution/SKILL.md) | 需要执行灰度、金丝雀、开关或分批发布时 | 发布步骤记录与当前范围 |
| 基于预设指标判断继续、暂停或恢复 | [`release-health-assessment`](../../skills/06-release-and-change-management/release-health-assessment/SKILL.md) | 每个发布批次及观察窗口内 | 健康判定与处置建议 |
| 按授权预案执行回滚或前滚恢复 | [`release-recovery-execution`](../../skills/06-release-and-change-management/release-recovery-execution/SKILL.md) | 发布达到暂停/恢复条件，需要控制用户影响时 | 恢复步骤、验证证据与当前影响 |
| 管理正在缓解严重影响的紧急变更 | [`emergency-change-management`](../../skills/06-release-and-change-management/emergency-change-management/SKILL.md) | 标准发布时序无法满足生产事件或紧迫安全风险的恢复目标时 | 紧急授权、最低证据、部署恢复和补验记录 |
| 收口稳定发布并交接运行信息 | [`release-closure`](../../skills/06-release-and-change-management/release-closure/SKILL.md) | 观察窗口稳定、准备完成发布时 | 发布结论、变更记录和支持交接 |

`github-release-management` 是阶段编排入口；候选准备、就绪判断、渐进执行、健康判断、恢复执行、紧急通道和收口分别保留独立职责。实际部署、商店/包发布、回滚、前滚、Environment 审批和管理员旁路均须由具备权限的人员或自动化在明确授权下执行。

## 隔离本地渠道

已授权合成后端/Web本地演练按[项目侧渠道参考](../local-delivery-channel.md)，由既有候选、就绪、执行、健康、恢复和收口技能记录真实制品/进程/关键路径与限制；不把本地成功当正式发布或生产Go，不扩大第二层部署写权限。
