# 阶段 1：需求与机会

## 目标

判断一个问题是否值得投入下一阶段的澄清成本。完成本阶段仅表示有权决策人批准投入澄清，不承诺开发、排期或交付日期。阶段 02 明确范围与验收，阶段 03 完成可行方案、投入与计划后，才由有权角色确认开发承诺；阶段完成本身不自动产生授权。

## 输入

- 用户反馈、客户请求、市场信号、业务目标、运行指标异常、事故或技术债线索。
- 已知背景：目标用户、当前行为、相关产品能力、时间或资源约束。
- 既有机会、任务与决定的唯一维护位置；如暂无，先确定主记录与稳定 ID。

## 流程

1. **分诊和登记**：先识别正在发生的严重事故或安全/隐私事件，立即转入[事故响应](../../skills/07-operations-and-support/incident-triage-and-response/SKILL.md)或[安全响应](../../skills/07-operations-and-support/security-privacy-incident-response/SKILL.md)，不等普通排序或填满记录。其余信号检查重复并创建/更新唯一机会，保留各次来源、提出人和时间；相似但对象/范围不同的事项可关联而不强并。普通记录只存脱敏线索和受控证据标识。
2. **理解问题**：记录受影响对象、情境、影响、频率与现有替代方式；缺陷补充实际/预期行为及可用复现条件。保留用户原始请求，区分背后问题、明确指定方案/约束和待验证假设，不擅自替换用户约束。
3. **定义结果和未知项**：明确可观察的改善、初步范围/非目标与风险。成功判据可定性；数值基线缺失时注明获取方式及限制，不编造精确值。会改变是否投入判断的关键未知先有限验证，其他未知注明负责人和下一步交阶段 02，技术细节留阶段 03。
涉及账户/权限、资金、敏感数据、合规、对外承诺、数据完整性、关键服务可用性或重大信誉影响时，必须标记高风险候选并记录触发项和需参与的安全/合规/运维等角色；不是正在发生的事件也需识别，不以材料精简降低门槛。

4. **选择投入深度**：小型明确问题沿用一条记录完成判断，不强制研究报告或重复运行三个技能；复杂跨域问题补适用研究与相关负责人判断。有限验证先由实际负责人确认假设、方法、负责人、时间或成本上限、结束判据和后续决策；到上限、无结论或发现新风险时停止扩大，记录结果/限制并决定补充、候选、延后或关闭，追加投入须重新确认，不无限调研或自动开发。
5. **排序和确认**：按价值/影响、紧迫度、证据/不确定性、澄清投入、依赖/容量作相对判断，公开决策窗口、取舍、挤出事项与重排条件，不强制数值公式。高潜力低置信机会可优先有限验证；单机会仍与容量/已有承诺比较，不制造比较对象。粗略实施成本仅作约束。必须处理的外部约束由有权角色确认后单列；业务负责人确认去向，Agent 输出建议，不自批优先级或交付承诺。

## 决策门禁

进入阶段 02 前，主记录必须满足以下六项，并有可追溯的实际批准；定性判据不降低证据、授权、适用文档或高风险门槛。

| 最小标准 | 必需内容 |
| --- | --- |
| 受影响对象 | 用户、角色或系统及问题发生情境 |
| 可观察的问题 | 当前行为、影响和原始请求，缺陷有可用复现信息 |
| 来源证据 | 可追溯来源，事实、假设和未知分开 |
| 期望结果 | 可观察改善与判断方式，可定性；缺数值时有获取方式及限制 |
| 投入理由 | 价值、紧迫度、初步范围/非目标、约束与风险、值得澄清的理由 |
| 责任与决定 | 澄清负责人、有权决策人、批准理由和带时区时间；小团队可一人兼任 |

数值目标、完整验收、技术方案和准确工作量不是本阶段统一前置要求。无法说明价值或合理验证方式时先补信息、有限验证或由决策人延后/关闭；缺关键事实不能伪造通过。

## 机会状态与转换

本节是机会状态的唯一规则来源，模板和技能引用本节。状态在机会主记录维护，不混用文档 frontmatter、专题、需求或发布状态。

| 状态 | 含义 | 必需记录与退出条件 |
| --- | --- | --- |
| 待补充 | 最小事实不足 | 缺什么、谁补、复查时间；补齐后重新界定或转有限验证 |
| 验证中 | 影响投入的关键未知正在有限验证 | 假设、方法、负责人、投入上限、结束判据；结束后按真实结果重新决定，不能自动转入澄清 |
| 候选池 | 值得关注但尚未选中投入澄清 | 保留/排序理由、负责人、复查触发条件；容量或证据改变后重排 |
| 进入澄清 | 已满足六项标准且批准投入阶段 02 | 决定及依据、决策人/时间、澄清负责人、范围和待解问题；关联下游记录 |
| 延后 | 已明确决定暂缓 | 原因、负责人、恢复条件或复查时间；触发后重评 |
| 关闭 | 当前决定不再推进 | 原因、证据、决定人/时间、关联及必要重开条件；保留历史 |

待补充/验证中表示分析进度，其余表示决策去向；候选池不是已决定暂缓的延后。每次转换保留前后状态、原因、决定主体、带时区时间和证据；决定主体须有对应权限，Agent 只能在已授权范围维护记录。关闭遇到新信号优先重开/关联原记录；进入澄清后价值失效或范围明显改变也须重评，不沿用旧批准覆盖新范围。复查条件是记录要求，不代表自动调度或获得通知他人的权限。

## 旧记录迁移

保留稳定 ID、旧状态值、原始来源/时间、映射理由、负责人确认和无法取得的材料，不覆盖历史。旧“新建”按实际完整程度映射待补充或其他已满足条件的状态；旧“调研中”只有实际有限验证已开始、方法/负责人/上限/结束判据和授权均可核对时才能映射验证中，否则列缺口交负责人决定。其余同名状态复核新语义，旧进入澄清不能凭标签推导六项标准已满足；补当前可用证据、明确历史缺口，不追溯伪造批准。没有新信息不自动批量迁移、重开或改变优先级。

## 文档治理

登记机会与研究时保留唯一来源、研究时间、范围与局限。跨专题可复用结论放 research，专题资料跟随专题；不要重复存原始材料。进入需求准备时调用文档维护技能确定归属与双语交付范围。

遵循[项目文档规范](../documentation-standard.md)和[接入说明](../documentation-integration.md)。[文档维护](../../skills/04-implementation-and-self-test/documentation-maintenance/SKILL.md)负责准备与更新，[独立文档验证](../../skills/05-integration-validation/documentation-delivery-validation/SKILL.md)负责检查结论，使用[统一交付检查模板](../../templates/documentation/delivery-check.md)。缺少专用检查器时保留逐项实际核对证据，不能声称第三阶段自动门禁已启用。

## 输出

- 一份稳定 ID 的机会主记录：六项判断、实际去向/理由、当前负责人、待解问题、状态历史与证据链接；问题框架和排序是该记录的视图/附件，不另复制任务状态。
- 建议与实际批准分别注明；事故/安全分流关联受控响应记录，不以机会关闭代替事件结束。
- 使用[机会记录模板](../../templates/delivery/opportunity-record.md)保留统一追溯字段，按项目事实选择 Issue、任务或文档承载。技能与中英模板已按本规则适配，完整场景验收进度见[实施计划](../phase01-optimization-plan.md)；不能把旧状态标签当新基线达标。

## 异常与回流

- 证据不足：按关键性选择待补充或有限验证，不以假设立项；高风险未知转相应角色判断。
- 外部约束或容量变化：重排并在原记录保留决定与对已有计划的影响；外部通知另遵循实际授权。
- 实施发现价值依据失效、范围扩大或假设被推翻：关联原决定回本阶段复核，下游保留自己的状态与承诺影响，不能通过回流抹去历史。

## 交接给下一阶段

向阶段 02 交接主记录 ID、问题与来源证据、期望结果、初步范围/非目标、约束/风险、未解问题及负责人/下一步、批准澄清的决定。用户指定方案或约束原样保留并标明性质，未验证实现假设保持假设，不默认成为批准方案。阶段 02 细化验收；需要重新确认价值或显著改变范围时回流。

## 固化为 SKILL

| 行为 | SKILL | 适用边界 | 产出 |
| --- | --- | --- | --- |
| 登记机会、去重与初步风险分诊 | [`opportunity-intake`](../../skills/01-demand-and-opportunity/opportunity-intake/SKILL.md) | 原始信号未规范记录或出现新来源时 | 主记录更新、最少补充问题或紧急分流 |
| 界定问题、结果与关键未知 | [`problem-framing`](../../skills/01-demand-and-opportunity/problem-framing/SKILL.md) | 需判断问题价值或设计有限验证时 | 主记录的问题框架、验证安排或澄清建议 |
| 比较澄清/验证投入与取舍 | [`opportunity-prioritization`](../../skills/01-demand-and-opportunity/opportunity-prioritization/SKILL.md) | 多机会排序或单机会与容量/承诺比较时 | 可由业务负责人确认的相对排序/去向建议 |

三个技能按实际缺口组合；输入已完整则复用，不重复登记、填表或强制依次执行。它们不直接创建开发承诺，立项和最终优先级仍由有权负责人确认。
