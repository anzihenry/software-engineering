# 阶段 7：运行与支持

## 目标

持续维持服务可靠性与用户信任，及时发现、缓解并学习运行问题。

## 输入

- 生产版本、服务目录、SLO/SLI、监控告警、运行手册、发布记录和支持渠道。
- 用户反馈、工单、错误报告、容量与安全信号。

## 流程

1. **持续观测**：收集可用性、延迟、错误率、吞吐、资源、成本和关键业务指标；保持仪表板、日志、追踪和告警有效。
2. **接收与分诊**：对告警、工单和反馈去重、分级、定责；记录受影响用户、时间、范围、症状和初始证据。
3. **响应事件**：按严重程度启动值守、沟通和缓解；优先恢复用户价值与控制影响，再进行根因分析。
4. **处理常规支持**：按知识库和运行手册解决问题；重复性问题形成缺陷、改进或文档任务并回流到需求阶段。
5. **维护运行能力**：定期检验告警质量、备份恢复、容量、依赖健康、权限与应急手册；移除噪声告警。
6. **关闭或升级**：确认用户影响已消除、监控恢复正常、沟通完成；重大事件进入无责备复盘。

## 决策门禁

关闭事件前，必须确认缓解/修复已生效、影响范围与时间线已记录、用户沟通完成、需要的后续行动已创建并有负责人。不能仅因告警消失而关闭高严重度事件。

## 输出

- 服务健康记录、支持工单结论、事故记录、状态通告和新增改进行动。
- 经验证或更新的运行手册、告警和知识库。

## 异常与回流

- 无法在目标恢复时间内缓解：升级事件级别和资源投入，并扩大沟通范围。
- 安全或隐私事件：立即执行专门响应与证据保全流程，限制不必要的信息扩散。
- 重复事故：创建根因治理任务，强制进入度量与复盘阶段。

## 交接给下一阶段

交接运行数据、用户影响、事故/工单时间线、已采取措施和待办行动，供度量与复盘验证效果并改进系统。
