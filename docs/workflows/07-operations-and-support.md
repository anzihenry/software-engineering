# 阶段 7：运行与支持

## 目标

持续维持服务可靠性与用户信任，及时发现、缓解并学习运行问题。

## 输入

- 生产版本、服务目录、SLO/SLI、监控告警、运行手册、发布记录和支持渠道。
- 用户反馈、工单、错误报告、容量与安全信号。

## 接收阶段06

按[发布收口与运行接收](06-release-and-change-management.md#状态结案与运行接收)确认实际版本/制品/混合分布、配置开关/迁移/兼容期限、监控告警和值守升级、恢复验证及限制、支持/后续观察、遗留风险/责任/期限/判据。接收人和时区时间明确，同人兼任也记录接收。06规定观察未通过不写成功交付；失败转事故需负责人接收，继续恢复责任，不因发布结案关闭事故。阶段07承接持续运行，不代填06未完成验证或文档。

## 完成边界与工作单元

对明确的运行对象和处理范围建立责任与有效观测，及时接收、分诊和处置异常及支持请求；以实际用户、服务和数据结果验证处置效果，完成沟通、记录和后续责任交接，并将需要持续改进的问题送入阶段08。运行持续开展，不设置整个阶段一次性完成。

| 工作单元 | 最低完成条件 |
| --- | --- |
| 运行接收 | 实际对象/版本/范围、责任、观测、访问/处置能力、手册和恢复限制核对且接收明确 |
| 健康检查或维护 | 范围/判据、当前可信实证、异常缺口处置/责任/复查齐备，不冒充所有运行风险已消除 |
| 事件响应 | 用户/服务/数据恢复及规定稳定窗通过，必要沟通/事实时间线、遗留/复盘接收完成 |
| 支持请求 | 解决有依据或按真实原因结案，转交有人接收，用户获知结果与后续入口 |
| 安全隐私专项 | 威胁/范围/可信恢复/证据及通知保全满足专项关闭条件 |
| 08交接 | 事实、影响、处置、防护和后续事项完整，有实际接收与责任 |

## 七项共同验收底线

1. 对象明确：范围、实际版本/配置、环境、用户影响和关联可核对。
2. 责任明确：负责人、接收/升级、下一动作及更新时间真实。
3. 事实可信：观察、假设、未知及结果分离，保留原始证据和修正历史。
4. 权限有效：诊断/数据访问/生产处置/通知覆盖当前范围，不因技能加载扩权。
5. 处置可追溯：操作/授权/失败/重试/副作用，中断后的实际对账保留。
6. 结果实证验证：适用的用户路径/服务/数据及规定时间/样本观察满足。
7. 交接真实完成：必要沟通、当前文档、遗留责任/期限/判据及接收齐备。

按工作单元适用，不给普通咨询套事故全流程；必需缺口保留未完成，字段齐全不等于通过。记录完成原因区分解决、转交、撤回、重复关联、无回复等，不统一计已验证解决。检查结果沿[质量门禁](../quality-gates.md)原状态，运行健康、事件过程、支持状态、信号可信度及结案原因分别维护；不为每项再建一套重复状态机。

## 运行接收与责任机制

按对象维护最小运行清单：产品/服务/任务/CLI或库、环境/渠道/范围/关键路径，当前版本/配置/依赖/限制，主负责人/替补或升级人/实际覆盖时段，监控反馈/告警接收/响应约定，手册/诊断权限/缓解恢复，遗留风险/责任/期限/完成判据。客户端覆盖旧版本与支持/兼容期限；第三方依赖有本方协调人和供应商升级渠道。

06接收需实际确认仪表板、日志、告警、手册可访问，具备约定诊断/处置或升级能力。结论为已接收、待补齐或应急接管；待补齐有缺口责任，严重影响先按授权应急接管明确范围与限制，不能因材料不齐无人处置，也不倒填06成功。

对象负责人、当前响应人、事件协调和沟通责任分别明确，小项目可兼任。确认接手、初步分诊、下一更新、适用缓解/恢复目标分别设时钟，依据承诺/影响/实际覆盖，不硬套分钟或虚构全天值守。不借晚建单/转交/改级重置原始影响时间；目标驱动升级，不作无依据修复承诺。

换班/转团队交当前影响、版本现场、已做及副作用、未完成、授权、下一动作/更新时间，接收方明确确认前原协调责任持续；无法继续按升级指定临时接管，不因自动分派/消息发出视为接手。无人确认、超目标、权限不足或影响扩大升级并保留尝试/实际接手。

## 统一接收与分诊

最低来源/发现接收时区时间、症状/对象环境/已知用户影响、已有原始证据/未知、当前接手/动作/更新足以启动；缺日志/复现/版本继续补，不延误严重响应，不索取无关用户数据。多个信号核对时间/症状/版本/依赖后关联主事件，保留各报告时间/影响及工单沟通；不只凭相似报错认同因，可按证据拆分并留关联理由。

事件严重度按用户伤害、关键性、数据安全、范围/持续/扩大及替代方案；支持优先级按实际受阻/紧迫/服务承诺/替代。沿项目等级与时限，人数少不降低单用户严重数据/安全问题，客户等级不掩盖真实影响。暂定等级写依据/可信程度/待核实；可信严重迹象先响应。升级及时，降级有影响收窄/缓解或原判断纠正证据、决定人/时间，历史不删、时钟不重置。

分诊明确进入支持、启动事件、受限专项、维护改进、关联已有或有证据排除；待核实有负责人/核实动作/复查。核心路径/数据损坏/影响扩大由工单升级，疑似攻击/凭据泄露/越权/数据暴露即专项；集中相似请求关联分析，不等固定数量。供应商故障本方继续协调用户影响；暂无即时影响的能力缺口入维护且有触发升级条件。暂不可复现不等于排除，转交须接收。

## 健康监测与主动维护

从用户路径覆盖可用性/性能、业务正确性、数据/异步任务、依赖容量、适用客户端崩溃/启动/升级/兼容，按实际选择必要信号，不只进程/CPU/HTTP200。每信号定义来源/对象、分母与成功失败/排除、窗口/有效样本、基线目标、责任/频率/触发动作；SLO/SLI沿已有口径，缺依据先补，不编目标或因表现差临时降低。

运行健康为正常、退化、异常、无法判定；观测缺失/延迟/样本不足/冲突不算正常。验证采集持续/新鲜度/版本范围、告警送达与有人确认；按风险补探测/实际路径或升级，重大长期失明不能只留普通待办。无用户影响解释的单一资源波动不直接等同事故。

告警有影响、触发/恢复判据、接收/响应时限、手册动作/升级；趋势可周期检查。聚合/抑制有依据，静默/调整写范围、理由、期限和替代观测，不为降噪删除必要覆盖；实际监控变更按授权。例行按风险/关键性/变化/最近证据/承诺设周期，重大架构/依赖/恢复变化重验。

主动维护实测告警产生→送达→接手、备份可读→恢复后数据/关键路径及实际耗时/损失与目标、容量/配额/依赖支持和替代、权限/证书/密钥轮换、当前版本手册、临时开关/双写/旧接口退出。备份任务成功或有文档不证明能力已验证；未验明确风险。演练有环境/授权/影响上限/停止恢复；实际配置/权限/架构变更回标准流程。即时影响进事件/支持，重大安全/数据/可用性风险立即升级，其他缺口有风险/责任/期限/证据，修改后重验并保留原失败。

## 事件响应、恢复与关闭

事件开始明确负责人、技术/沟通、暂定严重度、影响/事实未知、优先动作与更新时间；调查可并行，冲突生产动作统一协调。每动作有目标/预期、版本环境范围、授权/副作用/停止及验证/失败路径。有效预授权内及时处置无需重复请示；新代码/制品/迁移或越界生产动作交06，符合条件才紧急，未覆盖不可逆数据操作另取明确批准。

事实、假设、决定和实际结果分离。超时/断线/部分/取消先核实落地/仍执行及副作用，再安全重试/补偿/恢复，不删除首失败。严重影响先缓解后归因。按节奏通告已知影响/范围/措施/替代/下次时间，没有新结论也更新；有依据才估恢复时间，变化及时修正，内外事实一致，对外按授权。

已缓解表示降低或停止扩大且剩余影响明确；已恢复须用户路径/服务/数据符合标准及规定稳定时间/样本通过；可关闭还需影响/时间线/必要沟通完整，遗留/复盘有接收/期限/判据。降级恢复须事前最低服务标准，明确受限能力/临时措施/后续完整恢复；阻塞用户/数据影响仍部分恢复。无告警不等恢复，低流量/缺观测保留缺口。观察复发继续原事件并增影响区间，关闭后同因可重开关联，保留原关闭依据。长期改进未实施可交08跟踪，不提前写已做；当前恢复与必需文档/证据不因转交豁免。

## 日常支持处置

记录症状/时间/环境版本/影响/用户期望及已试，够用即处理。身份核验按动作风险，通用咨询无需账户数据；账户/权限/敏感数据/修改使用批准核验，未确认可通用帮助不能开放受限信息。最小必要脱敏信息，访问日志/用户数据有用途/范围/权限/保留，不索取密码密钥。无法复现记录已验环境/范围及下一步，不直接归咎用户。

处理中有负责人/动作/更新；等用户说明补什么/为何/替代及复查；等内部或供应商有接收方/跟进/更新；转交升级有实际接收及继续沟通责任。等待不解除责任，时钟暂停仅事前规则允许，保留原始等待与总时长。方法适用当前版本配置，生产变更走06；临时绕行说明限制/期限/永久安排。

解决须用户确认或客观证据，关闭还需结果/必要沟通/遗留。长期无回复按已公布提醒等待规则可关，记录无回复关闭、效果未确认和重开入口；转交/重复/撤回/超支持范围各记原因，不算全部已解决。回流关联事件缺陷/频率/影响/版本/临时措施，有接收人/优先依据/下一决定点；不编修复日期。知识库脱敏，保留适用版本/前置/已验步骤/风险/失败处理，未经核实猜测不作标准答案。

## 安全隐私专项与阶段08交接

可信安全隐私疑点即受限核实，不等待完全确认。信号待确认/已确认/已排除、响应进度和实际影响/未知范围分别记，普通服务恢复与专项可并行但保持同一关联和事实时间线。普通记录只脱敏最小事实/受限ID，原始凭据/个人数据/调查细节及法律通知判断留批准的受限系统。

证据依专项参考记录来源、采集人/时间/范围/工具、完整性、位置权限/流转/期限及法律保全；哈希不认证来源，缺权限/能力先保护升级。活跃攻击/外传/严重伤害授权内先控影响，条件允许保存易失现场，每动作记证据与服务影响；不自行扩采集、删证据或外联。通知由安全/隐私/法务/沟通相应负责人判断适用要求，记录发现/依据/人/截止/状态，未决有跟进，不因服务恢复忽略。威胁/残留受控、范围可决策、可信恢复、证据受控及通知/保全满足条件才专项关闭；原有专业判断不可被一般流程替代。

08交接发现/接手/判断/操作/恢复/沟通/关闭的事实时间线及修订、用户业务数据影响口径/局限、当时已知假设/授权/成功失败、防护有效与缺口、行动接收人/优先依据/期限/完成及效果判据。支持趋势和维护可周期交接；未恢复可阶段复盘但当前响应责任持续。受限原证据只脱敏摘要/受控引用，不重复扩散。

## 流程

1. **持续观测**：收集可用性、延迟、错误率、吞吐、资源、成本和关键业务指标；保持仪表板、日志、追踪和告警有效。
2. **接收与分诊**：对告警、工单和反馈去重、分级、定责；记录受影响用户、时间、范围、症状和初始证据。普通事故可使用仓库 Issue Form，状态变更先运行 `Transition Ordinary Incident` dry-run，再以 `incident-N` 精确确认写入。身份滥用、疑似攻击、凭据泄露、敏感数据暴露或隐私违规立即进入安全/隐私专项响应。
3. **响应事件**：普通运行事件按严重程度启动值守、沟通和缓解；优先恢复用户价值与控制影响，再进行根因分析。安全/隐私事件由专项负责人协调遏制、最小化取证、证据流转、通知判断和恢复，通用事件记录与专项记录保持同一标识和一致时间线。
4. **处理常规支持**：按知识库和运行手册解决问题；重复性问题形成缺陷、改进或文档任务并回流到需求阶段。
5. **维护运行能力**：定期检验告警质量、备份恢复、容量、依赖健康、权限与应急手册；移除噪声告警。
6. **关闭或升级**：确认用户影响已消除、监控恢复正常、沟通完成；重大事件进入无责备复盘。

## 决策门禁

关闭普通事件前，必须确认缓解/修复已生效、影响范围与时间线已记录、用户沟通完成、需要的后续行动已创建并有负责人。安全/隐私事件还必须确认威胁受控、证据受保护、恢复已验证，且法律保全和通知决定有明确负责人及状态。不能仅因告警消失而关闭高严重度事件。

## 文档治理

将新运行事实、支持结论和手册变化回写 guides 或长期知识，双语同步并保留受限证据位置；原始材料不重复公开。文档修正也按交付检查处理；紧急服务恢复沿既有授权流程执行，不把未完成的文档检查记成通过。

遵循[项目文档规范](../documentation-standard.md)和[接入说明](../documentation-integration.md)。[文档维护](../../skills/04-implementation-and-self-test/documentation-maintenance/SKILL.md)负责准备与更新，[独立文档验证](../../skills/05-integration-validation/documentation-delivery-validation/SKILL.md)负责检查结论，使用[统一交付检查模板](../../templates/documentation/delivery-check.md)。缺少专用检查器时保留逐项实际核对证据，不能声称第三阶段自动门禁已启用。

## 输出

接收/健康/维护/支持复用[运行与支持记录](../../templates/delivery/operations-record.md)的适用章节，事件使用下列专用记录，各工作单元稳定ID及唯一主系统。无事件不编造事故，专项原件不写入普通模板。

- 服务健康记录、支持工单结论、事故记录、安全/隐私事件证据与通知决策、状态通告和新增改进行动。
- 经验证或更新的运行手册、告警和知识库。
- 普通事件使用[事件记录模板](../../templates/delivery/incident-record.md)；安全/隐私事件仅在普通记录引用受限专项记录和证据标识。

## 异常与回流

- 无法在目标恢复时间内缓解：升级事件级别和资源投入，并扩大沟通范围。
- 安全或隐私事件：立即进入 `security-privacy-incident-response`，限制不必要的信息扩散；普通 GitHub Issue 只保留受限事件 ID 和脱敏服务影响，漏洞走 Private Vulnerability Reporting，隐私详情进入团队受限系统。通用响应可继续协调服务影响，但不得替代专项调查、证据保全和通知决策。
- 重复事故：创建根因治理任务，强制进入度量与复盘阶段。

## 交接给下一阶段

按[阶段08交接](#安全隐私专项与阶段08交接)交事实/影响口径/处置及失败/防护/后续责任并确认接收，受限材料只引用；未恢复责任持续，不能以已交复盘关闭。

## 固化为 SKILL

按当前工作单元组合五技能：监测给可信健康，维护核对接收与能力，事件统筹分诊/恢复，支持区分处理/解决/结案，专项保护受限证据。各自消费本流程的责任、授权、实际验证和08交接要求，不把多个状态合成一次自动通过。

| 定义、检查并改进服务健康信号 | [`service-health-monitoring`](../../skills/07-operations-and-support/service-health-monitoring/SKILL.md) | 需要持续理解服务可靠性和业务健康时 | 健康信号、告警质量结论和观测缺口 |
| 对告警和重大用户影响进行分诊、缓解、通报与关闭 | [`incident-triage-and-response`](../../skills/07-operations-and-support/incident-triage-and-response/SKILL.md) | 异常可能需要事件级响应时 | 事件记录、处置状态、时间线和升级/复盘输入 |
| 响应入侵、凭据泄露、敏感数据暴露或隐私事件并保全证据 | [`security-privacy-incident-response`](../../skills/07-operations-and-support/security-privacy-incident-response/SKILL.md) | 信号涉及恶意访问、信任边界失效、个人/敏感数据或通知义务时 | 受限事件记录、遏制恢复状态、证据链和通知决策输入 |
| 处置非事件级支持请求并识别重复模式 | [`support-case-resolution`](../../skills/07-operations-and-support/support-case-resolution/SKILL.md) | 用户工单、反馈或已知问题不构成事故时 | 工单结论、知识库更新或改进需求 |
| 定期验证告警、恢复、容量、依赖、权限和运行手册 | [`operational-readiness-maintenance`](../../skills/07-operations-and-support/operational-readiness-maintenance/SKILL.md) | 需要主动维持运行能力时 | 运行就绪检查结果和改进任务 |

安全或隐私事件必须使用专项响应与证据保全流程。专项流程负责安全、隐私和证据责任，通用事件流程仍可协调服务恢复；两者不得形成互相冲突的严重度、状态或时间线。
