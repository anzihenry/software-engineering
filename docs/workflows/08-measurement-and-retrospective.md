# 阶段 8：度量与复盘

## 目标

针对明确对象和观察范围，形成与证据强度相符的结果判断和系统性学习，完成必要决定及实际责任交接，并将改进纳入可验证的闭环。持续度量没有一次性终点，按工作单元验收；结果未达成或证据不足也可完成本轮评估，但不因此支持扩大投入。

## 输入

- 发布记录、成功指标基线与当前数据、SLO、质量数据、用户反馈、支持工单和事故记录。
- 计划假设、验收标准、目标与已知风险。

## 接收运行与支持

按[07交接](07-operations-and-support.md#安全隐私专项与阶段08交接)接收可追溯事实/修订、影响口径和局限、当时信息与假设/授权/失败、防护表现及后续行动责任期限判据。支持/维护趋势可周期进入，未恢复可阶段复盘但原响应责任持续；受限证据只脱敏摘要/受控引用。复盘接收不替代07恢复验证、必要沟通或专项关闭，长期改进在本阶段验证效果，不提前写已实施。

## 工作单元、触发与接收

| 工作单元 | 启动依据 | 本轮输出 |
| --- | --- | --- |
| 交付效果评估 | 到达约定观察节点，或目标/护栏显著偏差 | 目标/护栏及证据判断、后续决定 |
| 交付复盘 | 重要交付、延误/返工/协作障碍或值得复用的成功 | 当时条件、促成因素、发现去向 |
| 事件复盘 | 严重度/实际影响、复发或控制失效触发 | 事实时间线、防护与系统性风险行动 |
| 周期趋势评估 | 约定周期或支持/质量/成本/可靠性持续变化 | 跨记录趋势、累积风险与改善机会 |
| 改进行动效果验证 | 实施完成且到达预定窗口/样本条件 | 实施与效果分别验收、下一步处置 |

触发条件、责任及期限按项目风险事先约定；新风险可临时启动，不统一强制每次小变更开会。低风险可共用周期记录，仍保留各版本/范围/证据，不掩盖必须单独复盘的对象。阶段02/03确定目标、护栏与验证设计，06/07提供实际版本/批次/分布及观察安排；无法预定的内容明确由谁何时补齐，不看到结果才选有利窗口。

每单元明确ID/来源、对象版本/批次、用户群/环境、时间窗口/时区、要回答的问题、协调负责人/参与者、启动和交付期限。多个对象合并需各自结果可辨，无法区分同期变更影响时降低归因强度。材料/工单发送不等接收；接收人确认范围、责任、期限及时间，同人兼任也显式记录。未接收原协调人继续或升级，不伪造承诺。

启动不必等数据成熟，可先保全证据；结论仍须满足适用窗口/样本。到期证据不足提交缺口、受影响决定、补证方法/所有者/期限/成本上限、等待期间状态和运行责任，以及再次不足时的决定人，不无限等待。严重运行风险立即交07；未恢复可阶段复盘，原响应责任持续，后续恢复/新事实补充分析保留历史。

## 度量口径与证据强度

交付验收判断批准范围是否正确实现，结果目标判断是否产生价值，运行护栏判断有无不可接受副作用，分别列结果。验收通过不证明价值，目标改善不抵消护栏越界；即时风险先交07按权限处置，不等待归因。

指标保留目标来源、定义/公式、分子分母/排除、数据源和可复验查询或提取方法、版本/批次/环境/用户群/时间及时区、基线/目标/阈值、窗口/适用样本要求、负责人/延迟/缺失和限制。不统一样本量或统计方法。原始数据/查询结果保留身份、提取时间和摘要，敏感材料最小化并受控引用。

先查漏报、重复、延迟、采样/埋点/身份关联变化、版本覆盖及分母完整性；故障期丢失不能默作成功或无依据剔除，无投诉/告警不独证无问题。无法修复说明偏差方向/范围和结论限制；比较基线/趋势/适用对照及与风险相关分群，不能总体改善掩盖局部受损。事后发现分群注明探索性，补验证而非反复筛选有利结果。

保留原目标/口径/窗口及每次调整的原因、决定人、时间、适用范围；区分数据修正与目标调整，能重算则留重算证据，不能可靠重算明确不可直接比较，不覆盖原结果宣布原承诺达成。混杂因素包括季节/同期发布/外部事件/选择偏差/环境差异，未知如实记录。

每项目标/护栏分别记达成、部分达成、未达成或证据不足，并独立说明证据充分程度和归因层次：观察变化、支持关联或支持因果及其适用条件。不编置信数字，不要求每次对照实验；低流量/长期结果可用实际任务、访谈/案例，不能推未经验证的总体改善比例。

## 从判断到实际决定

| 去向 | 最低决定内容 |
| --- | --- |
| 维持并观察 | 维持范围、限制及下次节点 |
| 扩大采用/投入 | 对象、投入上限、护栏、停止条件及批准人 |
| 调整方案/实施 | 调整目标/范围及承接研发阶段 |
| 补证据后决定 | 会改变哪个选择、方法/所有者/期限/成本及到期再不足的处置 |
| 暂停/停止投入 | 停止范围、用户/运行/数据/兼容义务、遗留接收和沟通 |
| 回需求重新判断 | 新事实、被挑战假设及待重新排序机会 |

判断和决定分别记录，可分群作不同决定。建议、批准、执行分离，记录依据/范围/决定人/权限来源/时区时间/约束/重评条件；评估者不擅自承诺容量或接受风险。现有明确授权内继续，不重复审批；超范围交对应节点。新证据修订决定保留原依据和新原因，通知实际受影响接收人。停止可为有效决定但不倒填目标达成，遗留义务完成或实际接收后才关闭对应工作。

## 无责备复盘与完成

时间线保留计划与实际、影响、当时可见信号/缺失/矛盾、可行选择及权限/资源/依赖/时限、实际操作/失败/取消/重试/副作用、新证据和决策变化；事实、当时判断、事后推断/意见分开，争议保留各自证据不强造共识。角色/操作可追溯，不以事后知识苛求当时知道。

分析技术、流程、组织、工具、依赖、信息流和防护共同促成的机制，不强求唯一根因，不以人为失误/测试不足/沟通差为分析终点；解释部分成立则保留候选和未知。有效/失效/缺失防护及侥幸条件均分析，成功实践也核对能否重复。无责备不取消事实补充、决定、改进和验证责任；疑似违规、安全隐私等交专业机制，普通记录只最小脱敏事实/受控引用。

每个重要发现明确去向：新行动并实际接收、已有行动且核对覆盖、补调查的责任/期限、保留有效做法和适用条件，或有权限的暂不行动/接受风险及重评条件。不强制制造待办，加强意识不足以单独处理重大风险。复盘完成须事实/影响可追溯、主要判断有证据且分歧/未知明确、系统学习和发现去向完整、责任实际接收、重大风险有效处置及必要沟通/受限信息要求满足。长期行动继续，不替07恢复/专项关闭，不提前记行动有效。

## 行动状态、效果与收口

行动状态为待接收、已接收、实施中、待效果验证、验证中、已关闭；待接收不等资源批准。接收需单一协调所有者确认目标/范围/优先级/实施期限、依赖和投入权限、实施完成定义、效果判据/窗口/样本/护栏、验证责任人及调整/停止条件。探索按问题和证据验收，不可行可为有效探索产出而原风险仍在。

实施验收通过才待效果验证，实际开展才验证中。效果独立为有效、部分有效、无效、证据不足；尚未实施停止可不适用并说明。阻塞另记责任/下一动作/更新时间及原期限和调整历史。实施证据不代效果；防护可用受控负例/历史重放验证能力，不必等真事故，也不以无事故独证有效，同时查副作用/误报/维护成本。

部分有效限定已证范围并处理缺口；无效核原假设/实现后调整替代或停止；不足补证及等待风险责任；副作用严重立即对应处置。调整保留原判据和结果，不改定义涂成功。逾期由有权者补资源/缩范围/延期/替代/停止，高风险依既有升级；延期不等风险接受。接受剩余风险需权限来源、范围/理由/期限/补偿措施/重评条件，不能豁免硬门禁。

关闭另记效果或停止依据、决定人/时间、原因（已验证/替代/停止/重复合并/接受风险等）、遗留责任和必要文档/沟通；已关闭不等有效。复发、范围或新证据变化可重开/关联新行动，保留原关闭依据。行动数/Issue关闭数不代风险改善。

## 回流与规则演进

回流保留来源、目的、承接ID、接收人及时间，未接收原协调责任继续。新问题/价值/优先变化回01，范围验收约束回02，方案依赖/可行性和编码预研回03，已批准实施进04并经过适用05/06，当前运行风险回07。回流不自动开发批准，已有有效计划授权不重复审批。

通用实践先查问题证据、适用/不适用条件、现有规则能否解决、执行维护验证成本及试行判据。普遍证据不足先限定试行，严重控制缺口可及时按权限针对性修复，不等多次事故。载体选择原则/workflow/SKILL/自动化，避免复制和单次偶发全局强制。

规则分别记提案、已批准试行、试行中、待决定、已推广、已撤回或替代；每次推进保留实际证据。文件合入仅发布事实，采用还需真实入口可达/执行者具备条件及实际行为；推广需试行收益/副作用/成本证据和有权决定。规则有owner/适用范围/版本/复审，变化或到期实际复验不只改日期。同步受影响路由/引用/译文/检查并取得当前版本独立验证。

## 七项共同验收底线

1. 对象明确：对象版本/范围/窗口、目标问题与关联可追溯。
2. 证据适用：口径、质量、原始来源及限制可复核。
3. 结论准确：达成、证据充分和归因强度相匹配。
4. 学习有据：事实/当时判断/促成因素/未知分开。
5. 决定有效：去向、权限、约束及重评条件明确。
6. 责任承接：行动/回流实际接收，重大风险有效处置。
7. 记录完整：必要沟通/文档/适用译文齐备，实施/效果/关闭如实。

按适用工作单元验收，不强迫纯评估编造事故时间线或行动。评估加核目标/护栏，复盘加核事实/发现去向，行动加核效果/副作用，规则推广加核试行/采用/独立验证。证据不足可完成本轮记录但不批准扩大，行动长期不阻塞复盘，停止不计有效改善。

## 流程

1. **收集可信证据**：确定观察窗口和数据口径，对比发布前后产品、交付、可靠性和质量指标；记录数据缺口和混杂因素。
2. **评估结果**：判断目标和验收标准的达成情况，区分相关性与因果性；分析不同用户群、环境或发布批次的差异。
3. **组织复盘**：对重要发布、未达预期结果和事故举行无责备复盘，构建时间线，识别促成因素和系统性改进机会，而非归咎个人。本仓库使用 `incident:N` / `release:vX.Y.Z` 手动入口，按严重度或发布日期计算期限，并以隐藏来源标识防止重复记录。
4. **确定行动**：将结论转化为有明确预期效果、负责人、优先级和截止日期的行动项；仓库改进行动 Issue Form 强制复盘反链、单一所有者、完成定义、效果判据和观察窗口。
5. **跟踪闭环**：定期审查行动完成情况与实际效果；每周一 02:00 UTC 的只读 Actions 审计报告逾期复盘和行动，不自动评论、改标签或关闭 Issue。无效的行动应调整或关闭，并记录学习。
6. **更新基线**：按[规则演进](#回流与规则演进)试行和决定，将适用且经验证的经验版本化更新到准则、手册或自动化，标注所有者与实际复审。

## 决策门禁

复盘关闭前，结论必须由可追溯证据支撑，行动项必须有所有者和期限，重大风险必须有明确处置路径。没有数据时应记录不确定性，而非把推测写成事实。

## 文档治理

把复盘和研究的可复用发现回写长期知识，专题保留历史范围与原始证据。关闭专题或文档改进前独立核对更新与英文同步；定期复核仅补充交付检查，不能用批量更新日期代替实际复核。

遵循[项目文档规范](../documentation-standard.md)和[接入说明](../documentation-integration.md)。[文档维护](../../skills/04-implementation-and-self-test/documentation-maintenance/SKILL.md)负责准备与更新，[独立文档验证](../../skills/05-integration-validation/documentation-delivery-validation/SKILL.md)负责检查结论，使用[统一交付检查模板](../../templates/documentation/delivery-check.md)。缺少专用检查器时保留逐项实际核对证据，不能声称第三阶段自动门禁已启用。

## 输出

- 效果评估、复盘记录、关键指标趋势与可追溯数据来源。
- 已排序的改进行动及其负责人、期限、成功判据。
- 对需求池、架构/测试/运行准则、SKILL 或 workflow 的更新建议。
- 使用[效果复盘与行动模板](../../templates/delivery/outcome-retrospective-actions.md)关联结果、系统学习和行动闭环。

## 异常与回流

- 数据不足或质量不可信：按期提交证据不足判断和受影响范围，明确补证及到期决定，不作超证据强结论。
- 目标未达成：回到需求与机会重新判断问题、假设和优先级；必要时停止投入。
- 行动项长期未完成：升级给相应所有者，重新排序或明确接受风险。

## 交接给下一轮

将已验证的洞察和行动项回流到“需求与机会”，形成下一轮可排序的改进输入；按[规则演进](#回流与规则演进)限定试行，再依据证据决定推广、修订或撤回；严重控制缺口及时按权限修复。

## 固化为 SKILL

| 行为 | SKILL | 适用边界 | 产出 |
| --- | --- | --- | --- |
| 以可信口径评估交付带来的结果 | [`outcome-measurement`](../../skills/08-measurement-and-retrospective/outcome-measurement/SKILL.md) | 需要判断目标、验收或护栏指标是否达成时 | 效果评估、数据限制和后续假设 |
| 复盘重要交付或未达预期结果 | [`delivery-retrospective`](../../skills/08-measurement-and-retrospective/delivery-retrospective/SKILL.md) | 非事故的项目、发布或协作学习时 | 无责备复盘结论与改进候选 |
| 对运行事件进行无责备复盘 | [`incident-review`](../../skills/08-measurement-and-retrospective/incident-review/SKILL.md) | 稳定/恢复后的事件复盘，或不延误响应的未恢复阶段复盘 | 事实时间线、系统性改进与风险治理输入 |
| 将改进项转化为可验证的闭环 | [`improvement-action-tracking`](../../skills/08-measurement-and-retrospective/improvement-action-tracking/SKILL.md) | 已有复盘、评估或运行发现时 | 有所有者和效果判据的行动组合 |
| 依据验证结果演进准则、workflow 和 SKILL | [`playbook-evolution`](../../skills/08-measurement-and-retrospective/playbook-evolution/SKILL.md) | 稳定做法需要沉淀或现有规范需要修正时 | 版本化更新、试行与复审计划 |

复盘与流程更新必须以证据为基础，不将指标或复盘内容作为个人绩效的简化代理。

## Harness 观察与持续复验

按[运行指标与复验](../harness-observation.md)采集实际检查和复核样本，按候选策略分组、保留取消/失败/缺失，使用[双语观察报告](../../templates/documentation/harness-observation.md)。入口/知识/要求/命令依赖/环境支持/责任/权限规则变化或复审到期，交给原采用、领域和平台入口复验；非作者核准当前范围后关闭，不由指标自动豁免或改日期。
