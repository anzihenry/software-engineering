# 阶段 04：开发与自测优化计划

## 已确认目标与实施范围

阶段 04 完成意味着：在已批准范围内完成可审查的实现，本阶段必需自测实际通过，形成与当前版本绑定的可信证据和完整交接材料，具备进入阶段 05 独立集成验证的条件。完成不构成合入或发布批准。

用户已确认设计并授权实施。以 fetch 后的 `origin/main`、`e82f36e6e6bfeb83c126567608852513c1831d80` 为基线，主工作区初始干净、无其他 worktree，使用 `codex/phase04-implementation-self-test`。计划先单独提交；下列四包分别检查、独立复核和提交。本轮交付本地任务分支，不推送、合入或发布。既有阶段 01–03、Swift 最低 6.4、专业门禁、文档规范和 Git 分支规则继续适用。

## 执行契约

实现完成核对七项：批准基线和范围；正常及适用失败/权限/取消/恢复行为；跨模块连接形成完整切片；契约/兼容/数据不变量与配置；项目实际编码与运行规范；本节点测试、文档及译文、迁移和观测；与描述一致的可审查变更和追溯。骨架、关键 TODO、未连接主操作不能冒充能力完成；批准客户端/mock 范围可以独立完成，不能声称真实集成通过。

自测充分核对七项：验收/实际变化/风险映射；能区分正确错误的可观察行为；适用主流程与边界/失败/并发等；可行时修复前复现和修复后回归；实际环境/工具/目标/数据及限制；本阶段必需检查实际通过；当前提交或路径摘要及原始执行证据。轻量任务按风险选择检查，不强加无意义单测，不削减项目必过集合。

失败保留真实结果：代码修复回实现；关键方案问题回 03；业务验收歧义回 02；环境/工具/依赖、既有失败明确阻塞、负责人及解阻动作；间歇失败保留首次及全部重试，不挑绿。既有有效规则允许且实际通过的等效环境才可采用。独立确认旧断言错误才按新需求/契约修订测试，不能迎合错误实现。本阶段必需项不能事后改挂 05；既定后续验证明确负责人、节点、判据、证据及失败停止动作。

结果沿用 `passed/failed/not-run/blocked/stale/not-applicable`；不适用必须有规则及事实，缺工具不算不适用。证据绑定对象/版本、验收风险与范围、影响结果的版本/配置/依赖/环境/数据/参数、实际命令或手工步骤、执行者/带时区时间/退出码、原始报告与限制。实现、测试、依赖、工具、文档、同步或 rebase 改变时判断影响并重验；难以界定时扩大，保留项目全量重跑要求。内容相同的提交整理可凭摘要映射按规则复用，不能把旧基线当新候选通过。

区分继续修复、Draft 协作和正式交接。Draft 可讨论失败、执行诊断 CI，不代表阶段完成或正式验证中。正式交接七项：范围/授权；实际变更对象；验收/风险映射；完整实际自测；限制及后续项；文档/迁移/配置/观测/恢复；真实交接决定/接收方/动作。一个主记录链接既有需求、方案、任务和验证记录，不复制状态。

保留七状态：实现中、待评审、验证中、可合入、阻塞、已合入、已关闭。作者本阶段至多形成待评审；05 正式接收并执行才验证中，当前候选全部合入条件由 05 判定。接收不等于验证通过、合入不等于发布、关闭不证明成功。转换记录前后状态、原因、对象版本、实际主体/权限、带时区时间及证据；变更后重评受影响就绪性，未受影响授权工作可继续。

四核心技能分别负责编排完整切片、本地真实检查、有状态敏感变更、交接资格；领域入口按触发组合，不能要求每任务加载所有技能。Web 核对 UI 与状态连接及代表性浏览器证据，后端核对 API/数据/异步整体，移动端核对实际支持矩阵及平台语义，CLI 原始结果不替代整体结论。所有数据迁移保留原高风险要求；恢复验证、配置默认/缺失/非法/开关、依赖授权及锁文件、敏感日志与权限负例按影响执行。脚本和测试环境通过不产生生产权限。正式实现沿任务分支；为确定方案可落地的编码回 03，按原规则用独立 worktree 预研并保全后清理。
