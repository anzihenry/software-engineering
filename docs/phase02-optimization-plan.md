## 已确认的设计

### 完成与验收

进入阶段 03 前应具备：范围明确、验收可判定、适用非功能要求已识别、风险与必需评审清楚、关键依赖有依据、未知项有去向、有权负责人批准进入方案。保留用户指定方案/约束及上游来源，不把实现假设当已验证选择；切片表达完整用户/系统结果，不按技术层机械拆分。

验收标准描述结果、明确必要条件、给判断依据/方法、覆盖适用风险并可追溯；按需要包括角色、前置、输入、触发、主流程、边界、失败、权限、取消和恢复。不强制所有标准量化或用统一句式，复杂状态可用表格/Given–When–Then，小任务可几条描述；不能以“正常、友好、流畅”或内部实现步骤替代结果。适用非功能要求注明来源、判断方式、阈值或经确认的定性判据、负责人；没有需求不等于无要求，缺关键验收判据仍须澄清，不能编指标或一律留后。

### 未知、依赖与风险

| 对象 | 推进原则 |
| --- | --- |
| 需求判断阻塞项 | 业务规则、范围或验收含义不清留阶段 02，明确负责人/解阻动作；价值/优先级改变才回阶段 01 |
| 技术方案待验证项 | 需求结果已明确，带负责人、验证目标、判断条件及失败处理交阶段 03；不预填成功 |
| 非阻塞细节 | 明确允许调整边界、负责人和确认节点，不能无限悬置；改变核心行为/风险时重新分类 |
| 高风险影响未知项 | 先补适用专业评估，不包装为普通技术待定绕过 |
| 已识别依赖 | 只知道需要谁提供什么，不等于已接受 |
| 待确认依赖 | 已有对接人但内容/接口/时序未确认，无回复不算同意 |
| 已确认依赖 | 对应负责人接受具体条件且有可追溯依据；未来计划能力不写当前可用 |

进入方案不要求所有实施依赖已交付，但会改变需求范围、验收含义或关键风险判断的依赖必须先澄清。其他依赖只有在方案探索边界、负责人、判断/退出条件明确且获授权时可带入，不把“有人负责”当已确认。

风险等级与推进资格分别记录，命中既有高风险触发项保留相应要求，不以代码少、工期紧或尚未发生事故降级。计划中的审计/回滚不是已有有效保障。控制与评审列责任人、完成节点、证据及失败停止动作；进入方案前必需评估实际完成，后续设计/发布验证按节点承接，不能以“已排队”代替通过。Agent 给建议、理由和缺口，专业/授权结论由有权角色确认，不自批例外或减少门禁。

### 基线、变更、状态与记录

确认需求时固定可引用版本、上游机会、范围/非目标、验收、风险、依赖、待决与确认主体/时间。纯措辞且含义不变可原记录修订；业务/范围/验收变化回阶段 02；用户/价值/优先级变化回阶段 01；纯技术变化交阶段 03，影响验收/成本约束/风险时反馈阶段 02。保留变更原因、确认、影响标准/风险/依赖/下游、失效证据及可继续/需等待的工作，不借旧批准覆盖新范围，也不自动取消全部既有工作。

五状态保留现有名称：细化中（正在明确需求）、待对齐（已有草案等待必要确认）、可进入方案（七项满足且实际批准）、阻塞（已知关键缺口不能推进）、已取消（有权负责人决定停止）。待对齐不是已知关键问题的阻塞；状态转换保留前后状态、理由、主体/权限、时间和证据。就绪后变更使受影响结论失效；取消保留成果/下游处理，重启重新评估，不直接恢复旧批准。

一份需求主记录维护状态/负责人，附件链接引用；同一 Issue 可承载机会和需求，但各有 ID、状态和决定。三技能按缺口组合，不重复填表。交阶段 03：需求基线、行为/非功能验收、风险控制及节点/责任、依赖/未知的事实与验证退出条件、实际批准范围/理由/时间。阶段 03 逐项回应，缺业务规则回阶段 02，价值失效回阶段 01，不默默补造需求。

## 验收场景与失败判据

| ID | 场景 | 必需观察 |
| --- | --- | --- |
| B01 | 小型明确缺陷，有澄清批准 | 同一 Issue 中分清机会/需求 ID；轻量但验收可判定，仅建议/批准方案投入 |
| B02 | “导出正常/体验顺畅”，角色与失败含义未定 | 在阶段 02 补条件/结果/判断依据，不猜规则或全回阶段 01 |
| B03 | 业务结果明确，接口性能可行性未知 | 按技术待验证列负责人/目标/判据/失败动作交方案；不预填可行 |
| B04 | 删除权限或敏感数据处理范围未知 | 阻塞并专业评估，不以技术未知/队列状态放行 |
| B05 | 第三方未回复，仅有对接人或路线图 | 依赖待确认，未来能力不写可用；关键含义未明不推进 |
| B06 | 已确认依赖但制品尚未交付 | 保留条件/时间/来源；只在受控边界且七项满足获准后进入方案，不要求提前实施 |
| B07 | 计划加审计/回滚，要求风险降级 | 区分拟议/已验证控制，保留触发门禁、责任/节点，不自批降级/例外 |
| B08 | 提示措辞非阻塞但核心行为已明确 | 保留允许调整范围、负责人、确认节点，不无限挂起或扩大授权 |
| B09 | 就绪后新增资金/权限或改变验收 | 失效受影响基线、重评并记录下游等待/可继续范围，旧批准不覆盖新需求 |
| B10 | 价值失效、纯技术改变、普通规则分歧 | 分别回阶段 01、阶段 03、留阶段 02；不一律回流 |
| B11 | 有草案等待确认 vs 已发现关键冲突 | 区分待对齐/阻塞；转换有主体/理由/证据，不把请求当同意 |
| B12 | 旧就绪/取消记录，缺历史批准 | 保留原值/缺口，不伪补决定；重开不继承旧就绪 |
| B13 | 缺英文、元信息/互链/字段错误或未知英文模板 | 检查器拒绝，合法中英通过；不降低原检查或增加生产依赖 |
| B14 | 明确用户指定方案，技术尚未验证 | 保留约束并标注假设，交方案验证，不代替用户选实现 |
| B15 | 所有材料齐备但只有 Agent 建议/缺实际批准 | 不写可进入方案、不承诺日期；补有权决定 |
| B16 | NFR 泛化口号、未确认阈值或不适用无理由 | 根据触发补来源/判据/负责人；影响验收的缺口先澄清，不编值、不默认无要求 |

独立前向上下文只接收固定执行资产和原始请求，不预先提供本表或作者结论。保存实际读取/命令轨迹、输入/源/输出摘要与限制，逐项核对决定及允许推进范围；桌面模拟不冒充真实研究、专业批准或外部依赖确认。模板代码使用项目 Python/common 规则，扩充行为负例而非文字匹配；技能使用 skill-creator，保留按需读取和自动发现策略。
