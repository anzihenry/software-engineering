# Software Engineering Harness v1.3.0

[English](v1.3.0.en.md)

本文是版本说明，正式发布状态、时间、精确source SHA及资产摘要以[GitHub Release](https://github.com/anzihenry/software-engineering/releases/tag/v1.3.0)和附件为准。发布范围为仓库知识资产及既有GitHub自动化包，不涉及生产部署或目标项目自动升级。

## 主要变化

- 01批准澄清、02批准方案投入，03有据方案/可执行计划/实际开发批准分开；技术预研在worktree运行，保全后清理。
- 04完整实现、自测和正式交接，05独立验证及每次功能合入前后端到端；合入不等集成收口。
- 06固定候选/有效授权、批次和时间/样本观察、中断对账、恢复及运行接收。
- 07运行接收/健康维护/事件支持/受限专项按工作单元验收，缓解、恢复、关闭不混用。
- 08可信口径/结果/归因/决定分别记录，无责备复盘、行动实施和效果验证及规则试行回流。
- 八阶段目录71技能，10组中英交付模板，三条完整演练及152条独立场景；相关更新见[生命周期](../software-development-lifecycle.md)和各阶段验证报告。
- 文档维护/独立验证、目标项目双语模板和check/snapshot/gate、风险与权限边界、来源追溯、Git分支及Swift最低6.4基线；遵循项目已提交工具配置，不静默升级。

## 获取与兼容

完整知识资产使用[tag源码](https://github.com/anzihenry/software-engineering/tree/v1.3.0)或GitHub自动生成源码归档。Release附件 `github-lifecycle.zip` 和 `.sha256` 只包含manifest声明的第二/三层自动化，不含skills、八阶段工作流、全部模板或内部验证工具；`release-candidate.json`、checklist和发布证据是来源材料而非安装包。

Manifest仍schema3，原四profile、内置adapter及legacy读取/三方升级契约保持；没有声明所有旧项目或平台自动兼容。按[升级指南](../../UPGRADING.md)与[兼容矩阵](../version-compatibility.md)核对原包/新包和安装记录，本地定制/冲突拒绝覆盖，不隐式删除或改变profile/adapter。

现有Swift adapter实际runner与目标项目工具约束仍需核对，知识规范Swift最低6.4不证明既有adapter已自动安装6.4。目标CI/可信来源/真实身份和完整阶段门禁需实际接入验证。

## 证据与发布范围

八阶段验证报告保留各自固定版本、原始失败/重试、独立评审和局限。152案包括桌面判断和限定真实隔离执行，不能全部计为生产端到端测试。正式候选需当前四检查/236测试、独立文档核对、PR/main门禁及实际产物核验通过；最终命令、SHA和附件核验链接记录在Release证据，本文不预填未来结果。

发布准备使用现有Python3.14环境和固定依赖，无生产运行时/数据迁移；不以旧canary为新版本真实平台通过。发布授权来源为用户本次明确要求发布新版本，范围限此仓库正式tag/Release及附件。原始/source/包身份变化重验，公开后不移动tag或覆盖资产。

## 采用、运行和恢复

按项目采用规范合并知识入口，再运行实际项目检查和独立验收；自动化升级在独立PR处理。运行关注下载、摘要、解包/安装及已有记录兼容反馈，问题由本仓库维护者接收，不承诺全天值守或自动通知。当前执行者负责核对公开Release、tag/source及重新下载附件，未完成前不报告发布成功。

有阻塞停止公开并保全证据。公开后发现问题保留旧tag/资产，标明受影响范围并发布前滚修复或有权撤回说明；已有采用者按自身安装记录/Git历史恢复，当前工具不自动降级。无目标云/商店部署或外发通知。
