# 移动端实现与自测

在既有产品和技术设计内实现可审查的跨平台移动端变更，并协调 iOS/Android 的行为与证据。仅涉及 iOS 或 Android 平台专属代码时分别使用 `ios-implementation-and-self-test` 或 `android-implementation-and-self-test`；本 SKILL 不负责应用商店发布、签名审批或完整设备矩阵认证。

## 输入

- 验收标准、交互/视觉设计、技术设计、风险等级和支持的系统/设备范围。
- 项目架构、状态管理与导航约定，权限、存储、网络和遥测要求。
- iOS/Android 平台影响与对应自测记录（涉及平台专属行为时）。

## 工作方式

1. 确认目标平台、最低系统版本、设备形态以及原生或跨平台边界；区分共享逻辑和平台专属行为。原生桥接、系统能力或生命周期语义发生变化时，组合对应 iOS/Android SKILL。
2. 沿既有导航、状态和依赖注入边界实现最小切片；处理前后台切换、中断、进程重建、重复触发和资源释放。
3. 对权限、深链、通知、本地存储、缓存/离线、网络重试和系统 API 采用平台推荐模式；数据或状态升级必须兼容已有安装。
4. 添加最靠近风险的测试，并在适用的模拟器或真机上检查主流程、失败恢复、不同屏幕/字体、键盘、安全区和辅助功能。
5. 对照两端验收行为，区分必须一致与允许平台化的结果；汇总平台自测证据、构建变体、系统/设备、测试数据和网络条件，将完整矩阵与性能结论交给移动端验证。

## 输出格式

```markdown
## 移动端实现与自测记录
- 平台、系统与设备范围：
- 变更切片及共享/平台专属边界：
- iOS/Android 一致性要求与允许差异：
- 生命周期、权限、状态与弱网处理：
- 自动化测试：
- iOS/Android 自测证据与模拟器/真机结果：
- 可访问性与视觉适配检查：
- 未覆盖项、剩余风险与后续验证：
```

## 停止条件

- 当目标平台可构建、关键行为有测试且代表性设备自测通过时，交给本地质量验证和交接准备。
- 当问题涉及跨设备/系统矩阵、两端一致性、升级兼容或性能基线时，交给 `mobile-validation`；平台专属验证分别交给 `ios-validation` 或 `android-validation`。
- 当实现需要改变交互、契约或支持范围时，回流方案或需求阶段，不在代码中静默决定。
