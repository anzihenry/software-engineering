# SQL 编码规范

## 方言与格式

- 首先确认数据库产品、主版本、迁移工具和 ORM/驱动。没有方言声明时只使用标准 SQL 概念，不假设 PostgreSQL、MySQL、SQLite、SQL Server 等语法、NULL、锁或 DDL 事务行为等价。
- 使用项目 formatter 和命名规范。新项目默认关键词大写、schema/table/column 使用 `snake_case`，但既有数据库命名优先，禁止纯风格重命名破坏兼容。
- 明确列名和表别名；生产查询避免 `SELECT *`、隐式 join、依赖物理行顺序和未限定的同名列。分页必须有稳定且唯一的排序。

## 正确性与安全

- 所有外部值使用驱动参数绑定；禁止字符串拼接标识符/条件/排序。确需动态标识符时使用受控 allowlist 和方言安全 quoting API。
- 正确处理三值逻辑：用 `IS NULL`/`IS NOT NULL`，不要假设 `NOT IN`、比较或聚合在 NULL 下符合二值直觉。
- 多步不变量放在明确事务中，选择与风险匹配的隔离和锁策略；事务尽量短，不在持锁时调用网络或等待用户输入。
- 用主键、唯一键、外键、NOT NULL 和 CHECK 等数据库约束保护持久不变量；应用校验不能替代并发条件下的数据库约束。
- UPDATE/DELETE 必须有可审查过滤条件；批量数据变更评估锁、日志、复制、超时和回滚。高风险操作先用只读查询确认目标数量。

## 查询与 schema

- 优先集合操作和明确 join；相关子查询、窗口函数或 CTE 的选择以可读性和实际执行计划为准，不迷信某种写法必然更快。
- 索引根据真实过滤、连接、排序和基数设计；考虑写放大、存储和重复索引。性能结论必须有目标版本和代表性数据上的 `EXPLAIN`/等价证据。
- schema 迁移遵循 expand/contract：先兼容读取/写入，再回填和切换，最后移除旧结构。迁移可重复、可中断恢复，并提供验证与恢复说明。
- 时间使用明确时区语义，金额避免浮点；JSON/数组等方言类型不应逃避关系约束和查询需求。

## 验证

- 在与生产相同产品和主版本上运行语法、迁移、事务和回滚测试；内存数据库不能替代方言兼容验证。
- 测试空集、NULL、重复、边界值、并发写入、约束冲突和大数据量；迁移验证前后 schema、行数/校验和及应用兼容。
- 查询性能记录 SQL、参数分布、数据规模、执行计划和耗时范围；不只测试单个理想参数。
