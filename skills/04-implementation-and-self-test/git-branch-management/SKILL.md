# Git 任务分支管理

将任务修改留在可独立评审的功能分支，保护其他任务的工作。开发入口在修改前调用本技能；提交、推送、同步、误提交恢复或合入后清理时按实际操作再次使用，不因加载技能自动获得推送、删除或 PR 合并权限。

## 依据与输入

先读取项目入口和[分支规范](../../../docs/git-branch-workflow.md)，以用户要求、项目具体规则及现有授权为准。确认目标仓库、任务归属、当前 coding agent、实际默认分支、工作区/worktree 状态、remote/upstream；清理时还需 PR 状态及精确 head。独立分发时须同时提供固定规范或项目等价副本；依据缺失时报告缺口。

## 按操作选择流程

- **准备任务分支**：读取状态并 fetch，检查已有对应任务分支及其他 worktree。已有任务分支复用；否则从最新远端默认分支创建 `<当前 agent>/<英文小写连字符任务名>`，如 `codex/...` 或 `deepseek-harness/...`。一个分支对应一个可独立评审任务，更换 Agent 不重命名；用户/项目指定名称优先。默认及其他受保护分支不承载任务修改或新提交。无关未提交工作先确认归属，不自动丢弃、stash、暂存或搬移；无法确认基线时报告缺口。
- **提交或推送**：将请求解释为针对当前任务功能分支，核对暂存范围、remote、分支及 upstream，不夹带其他任务内容或推送其他分支。若任务修改误落在基线，先进入恢复流程。
- **同步分支**：核对远端任务分支与默认分支的差异，保护未提交和未推送工作。独占未发布分支可 rebase，共用已推送分支默认 merge；共用状态未知时先确认，项目具体规范优先。不直接强推覆盖远端。冲突在任务分支处理，语义不明时先确认；同步后重跑受影响检查并刷新相关评审证据。
- **恢复误提交**：先停止基线提交/推送，将本次修改和提交保留到任务分支并核对完整性；fetch 后确认基线没有其他待保留工作、未被其他 worktree 使用，才恢复为远端状态。不可先重置再找回。任务分支随后同步、验证，再在授权范围内推送/创建 PR。已经推送的远端默认分支通过修复/回退 PR 处理，不强推撤销历史。
- **合入后清理**：核对 PR 已合并和精确 head，验证远端实际删除。需补删时确认 ref 未被复用、没有新增待保留提交且已有清理授权。本地清理前安全切换并同步默认分支，确认没有未提交、未合入或待保留工作，也未被其他 worktree 使用。Squash 后结合 PR 和实际内容核对，不只依赖 Git 合并判断或以安全删除被拒绝为由强删；条件不足保留分支，不批量删除归属不明的历史分支。

## 输出与边界

记录任务分支、实际基线/同步结果、工作归属、操作及检查结果；恢复记录原提交与新位置，清理记录 PR/head、远端删除及本地保留/删除理由。不能验证的条件明确记为未完成。

远端保护/自动删分支设置交给 `github-repository-bootstrap`，PR 评审和合入判断交给 `github-pr-integration` / `merge-readiness`。本技能不合并 PR、不绕过保护，也不把本地同步成功当成远端治理或交付通过。
