# Web UI 与交互实现自测

在既有设计系统和组件架构内实现可复用、可访问的 Web 界面，并证明关键交互状态成立。页面级状态、路由和服务端数据协同使用 `web-state-data-implementation-and-self-test`；本 SKILL 不替代独立视觉与可访问性验证。

## 输入

- 验收标准、交互/视觉设计、内容、目标浏览器/视口和风险等级。
- 设计 token、组件规范、图标/字体资产、可访问性要求及本地化约束。

## 工作方式

1. 将设计和验收标准展开为默认、悬停、焦点、按下、禁用、加载、空、错误和成功等必要状态，明确组件职责与组合边界。
2. 优先复用设计系统、语义化 HTML 和平台原生交互；新增抽象须解决重复行为，不把单页偶然样式提升为全局约定。
3. 实现键盘操作、清晰标签、焦点进入/返回、错误关联和动态状态通知；自定义控件必须补齐原生控件已有的语义与行为。
4. 在目标视口、缩放、长文本和本地化内容下处理布局、溢出、换行、触控目标、主题与减少动态效果偏好，避免只适配理想文案。
5. 添加组件或交互测试，覆盖行为与状态转换；在代表性浏览器中检查视觉、键盘和辅助功能树，并记录需独立验证的差异。

## 输出格式

```markdown
## Web UI 与交互实现自测记录
- 页面/组件、设计系统复用与新增边界：
- 交互和内容状态：
- 语义、键盘、焦点与错误反馈：
- 响应式、缩放、主题与本地化处理：
- 组件/交互测试及浏览器自测：
- 视觉与可访问性专项验证需求：
- 未覆盖项和剩余风险：
```

## 停止条件

- 当组件可构建，关键状态和交互有测试，并在代表性浏览器/视口完成自测时，交给前端协调层和本地质量验证。
- 当结论需要完整视觉基线、浏览器/视口矩阵或辅助技术时，交给 `web-visual-accessibility-validation`。
- 当设计缺少状态、内容或可访问性含义时，回流设计/需求，不在实现中静默决定产品行为。
