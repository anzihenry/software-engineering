# 后端实现与自测

在既有服务边界内协调可审查的后端变更，并证明入口、领域数据和异步依赖组合后的行为。主要涉及同步入口、领域持久化或异步集成时分别使用 `backend-api-implementation-and-self-test`、`backend-domain-data-implementation-and-self-test` 或 `backend-async-integration-implementation-and-self-test`；迁移和生产配置另由 `data-and-configuration-change` 管理。

## 输入

- 验收标准、服务设计、API/事件契约、数据模型、风险等级和非功能要求。
- 授权模型、事务与一致性约定、依赖策略、可观测性规范及容量基线。
- 按风险涉及的 API、领域数据和异步集成专项自测记录。

## 工作方式

1. 将验收标准映射到同步入口、领域/持久化和异步/外部依赖边界，明确专项所有者、契约、数据流和失败责任。
2. 协调输入校验、授权、领域不变量、事务和副作用顺序，确保一个边界失败不会造成未说明的部分成功或错误重试。
3. 对跨边界写路径明确幂等标识、并发策略、事件提交/发布、超时和补偿，保持 API 错误与后台最终状态可解释。
4. 汇总单元、组件和本地集成测试，覆盖从入口到数据/消息的关键切片及失败路径，而非只证明各模块孤立行为。
5. 统一日志、指标和追踪关联并避免高基数/敏感字段，记录调用方、数据、依赖及无法本地证明的专项风险。

## 整体交接边界

API、数据库和消息均受影响时，API单测绿不能证明完整切片；按风险实际验证授权/事务/幂等/并发、部分失败和恢复。真实依赖专项按原计划分节点；本阶段必需数据/消息检查不能因难执行转交05冒充完成，替身只证明限定范围。

按[阶段04完整实现、自测和正式交接门槛](../../../docs/workflows/04-implementation-and-self-test.md)保留当前版本/环境/原始结果与限制；领域自测不替代共享本地质量验证和单一交接记录。继续修复、Draft诊断与正式移交分开，本阶段完整必需项实际通过才交05；后续项列负责人、节点、判据、证据和失败停止动作。代码/契约/依赖/工具环境变化后重验受影响证据，不以旧绿测或一个平台结果外推整体。

## 输出格式

```markdown
## 后端实现与自测记录
- 服务切片、专项所有者与接口/事件/数据边界：
- 兼容性与调用方影响：
- 事务、幂等、并发和失败处理：
- 权限与敏感数据处理：
- 专项自测证据、跨边界测试与本地依赖：
- 日志、指标与追踪变化：
- 未覆盖项、剩余风险与后续验证：
```

## 停止条件

- 当变更可构建，关键领域规则和失败语义有测试且本地必需检查通过时，交给本地质量验证和交接准备。
- 当结论依赖真实数据库、中间件、下游、并发、容量、安全负向或故障注入时，交给对应专项并由 `backend-validation` 汇总。
- 当契约、数据所有权或一致性模型需要改变时，回流方案与计划；迁移不得作为普通代码细节处理。
