# 实现与自测

在已批准的设计和任务范围内交付可维护、可审查的变更，并形成自测证据。此 SKILL 不重新设计需求、不替代独立代码评审，也不绕过项目质量门禁。

## 输入

- 按[阶段 03 交接](../../../docs/workflows/03-solution-and-planning.md#输出与阶段-04-交接)的当前需求/方案/计划基线、验收/证据/剩余未知、任务/验证/后续控制/文档与实际开发授权。设计评审结论不自动替代开发批准。
- 项目编码规范、目标分支、依赖策略和本地检查要求。

启动核对版本有效、授权覆盖当前任务、所需依赖/环境/权限和阻塞条件已满足、实际规范/配置/命令可用；不要求后续资源全部提前交付，mock不证明真实集成。需要编码确认方案可落地的工作回阶段03，在独立worktree技术预研并保全证据后清理，不混入正式实现。

## 修改前分支要求

修改代码、文档或配置前必须先调用 `git-branch-management` 并读取[Git 分支规范](../../../docs/git-branch-workflow.md)，检查当前分支/工作区和任务归属、fetch 后创建/复用功能分支；不得在默认/受保护分支进行任务修改或新提交。分支按当前 coding agent 命名，一个分支对应一个可独立评审的任务；用户或项目具体规则优先。同步与误提交恢复按该规范执行，保留无关工作；该要求也适用于领域技能。

## 工作方式

1. 确认当前基线、任务关联和受影响的验收标准；先识别会改变范围的设计缺口或阻塞依赖。若变更主要属于移动端、Web 前端或后端，分别使用 `mobile-implementation-and-self-test`、`web-frontend-implementation-and-self-test` 或 `backend-implementation-and-self-test` 补充领域约束；跨领域变更由本 SKILL 维持整体切片和证据关联。
2. 将实现限制在一个可独立审查和回退的切片，遵守既有架构边界、接口契约、授权模型和错误处理约定；无关重构另行拆分。
3. 按实际变化和风险选择最接近风险来源的行为验证，覆盖正常及适用边界/失败/授权/并发/取消/恢复。轻量文案不强加无意义单测，项目必过集合仍执行；缺陷可行时先复现再回归，无法复现写原因、替代证据及限制。测试应区分正确错误，不能只复述实现或内部调用次数。
4. 本地运行相关检查并检查变更是否仍与需求、设计和契约一致；记录未执行或无法自动化的验证及其原因。
5. 更新受影响的代码内说明、契约、运行说明或用户文档，并准备清晰的变更摘要。

## 完整性与推进资格

按[阶段04七项实现、七项自测及门禁](../../../docs/workflows/04-implementation-and-self-test.md)核对批准基线、完整行为、边界接通、契约/兼容/不变量、实际项目规范、本节点配套和审查追溯。UI主操作未连接、模块孤立成功、关键TODO或临时返回不能当完整能力；批准客户端/mock范围可交其限定成果，不能声称真实集成。未经批准的依赖/工具链升级、敏感日志、权限或公共契约变化回对应流程。

当前任务前置失败只停受影响范围；关键设计/可行性回03、业务验收歧义回02。原批准范围内实现细节可继续，不把所有正式编码都当worktree预研。继续修复或Draft诊断不代表完成；正式交接必须本阶段必需自测实际通过、文档/译文和当前证据齐备，既定05项按负责人/节点/判据/证据/停止动作移交，不事后延期必需项。

## 文档交付要求

调用 `documentation-maintenance` 同步本次受影响文档与英文，按[交付检查模板](../../../templates/documentation/delivery-check.md)保留文件级影响、实际检查和当前快照。独立文档验证属于后续非作者评审，本实现上下文不得自行批准。

## 输出格式

```markdown
## 实现与自测记录
- 任务分支、实际基线、工作区归属与 fetch/同步结果：
- 关联需求、设计与任务：
- 变更切片与范围：
- 已实现行为及对应验收标准：
- 新增/更新的测试及覆盖场景：
- 已运行检查与结果：
- 未执行验证、原因与后续计划：
- 更新的文档/契约：
- 已知限制、风险与发布注意事项：
```

## 停止条件

- 实现后用本地质量验证确认真实结果；只有完整范围、当前必需检查和配套满足阶段04门槛，才能交接为待评审。质量/材料未齐可继续准备或Draft协作，不标可合入。
- 当实现暴露设计缺口时，暂停扩大变更，回到方案与计划；不得静默改变关键设计。
- 当验收含义不清时，回到需求澄清，不以开发者猜测替代业务决策。
