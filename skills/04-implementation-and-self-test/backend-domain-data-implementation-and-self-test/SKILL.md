# 后端领域与数据实现自测

实现可追溯的领域规则和数据访问，并用测试证明不变量、事务与失败语义。迁移和生产配置由 `data-and-configuration-change` 管理；本 SKILL 不执行生产数据变更。

## 输入

- 验收标准、领域模型、数据所有权、schema/迁移设计、一致性模型和风险等级。
- 事务、并发控制、数据访问、审计、保留和容量约定。

## 工作方式

1. 将业务不变量放在可被所有入口复用的领域边界，明确数据所有者、生命周期及跨服务一致性假设。
2. 为每个写路径定义事务边界、隔离/并发策略、幂等键和失败回滚；避免隐藏的部分提交或读改写竞态。
3. 让查询的过滤、排序、分页和空值语义明确，检查索引与访问模式匹配；避免无界读取、逐项查询和敏感数据过度返回。
4. 为 schema 演进准备向前/向后兼容、回填、双读写或恢复所需代码与说明，不把一次性生产操作嵌入普通请求路径。
5. 添加领域和持久化测试，覆盖不变量、边界、并发冲突、事务回滚、重复执行及代表性数据规模，并记录需真实数据库证明的项目。

## 输出格式

```markdown
## 后端领域与数据实现自测记录
- 领域规则、不变量与数据所有权：
- schema、查询与访问模式：
- 事务、并发、幂等和回滚：
- 迁移兼容、回填与恢复准备：
- 自动化测试及本地数据库条件：
- 未覆盖项和一致性验证需求：
```

## 停止条件

- 当领域规则、事务和数据失败路径有测试且迁移准备明确时，交给后端协调层、本地质量验证及数据配置变更流程。
- 真实数据库、迁移兼容和一致性收敛交给 `backend-data-consistency-validation`；容量/争用交给性能并发验证。
- 数据所有权或一致性模型不明确时回流方案设计，不以代码默认值替代架构决策。
