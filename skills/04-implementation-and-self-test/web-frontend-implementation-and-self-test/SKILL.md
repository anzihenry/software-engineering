# Web 前端实现与自测

在既有设计系统和前端架构内协调可审查的 Web 变更，并证明 UI、状态和数据边界组合后符合验收标准。主要是界面/组件时使用 `web-ui-implementation-and-self-test`，主要是路由/状态/数据时使用 `web-state-data-implementation-and-self-test`；本 SKILL 不替代跨服务端到端验证或生产发布。

## 输入

- 验收标准、交互/视觉设计、目标浏览器与视口、技术设计和风险等级。
- 组件与设计系统、状态/路由/数据获取约定、接口契约、可访问性和性能预算。
- UI/交互和状态/数据专项自测记录（涉及对应边界时）。

## 工作方式

1. 将验收标准映射为页面状态和完整用户路径，明确 UI/交互与路由/状态/数据责任边界，并把专项实现交给对应 SKILL。
2. 协调组件事件、页面状态、URL、接口和错误语义，确保加载、空、错误、无权限、成功和恢复状态在边界间一致，不复制服务端业务裁决。
3. 检查 UI 状态不会因竞态、导航、缓存或会话变化而陈旧，数据流也不会绕过语义、焦点和可访问反馈。
4. 汇总单元、组件、状态和浏览器自测，确保测试覆盖跨边界关键路径而非只证明各模块孤立行为；接口替身须受契约约束。
5. 在代表性浏览器中检查完整切片的控制台、网络、资源和用户反馈，记录浏览器/视口、性能影响以及需独立验证的项目。

## 输出格式

```markdown
## Web 前端实现与自测记录
- 页面、组件与用户路径：
- UI/交互与状态/数据责任边界：
- 加载、错误、权限与恢复状态的一致性：
- 响应式和目标浏览器范围：
- 可访问性处理：
- 专项自测证据、跨边界测试与浏览器自测：
- 性能/资源影响：
- 未覆盖项、剩余风险与后续验证：
```

## 停止条件

- 当变更可构建，关键状态和交互有测试，代表性浏览器自测通过时，交给本地质量验证和交接准备。
- 当需要完整浏览器矩阵、真实依赖、视觉/可访问性或性能基线时，分别交给对应专项验证并由 `web-frontend-validation` 汇总。
- 当设计、接口契约或浏览器支持范围不明确时，回流对应阶段，不以临时前端逻辑掩盖缺口。
