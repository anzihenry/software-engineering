# Web 状态与数据实现自测

实现可预测的页面/应用状态和服务端数据交互，并证明加载、失败与并发条件下的行为。视觉组件与细粒度交互协同使用 `web-ui-implementation-and-self-test`；本 SKILL 不复制后端业务规则或替代真实依赖验证。

## 输入

- 验收标准、用户路径、路由和状态设计、接口契约、认证模型及风险等级。
- 数据获取/缓存约定、SSR/客户端渲染边界、遥测要求和目标浏览器能力。

## 工作方式

1. 区分 URL/路由状态、服务端状态、持久客户端状态和瞬时 UI 状态；为每类确定所有者、生命周期和唯一事实来源。
2. 按契约实现输入/输出、认证和错误映射，不在前端复制应由服务端裁决的权限或领域规则；对契约演进保持兼容或显式失败。
3. 处理请求取消、乱序响应、重复提交、缓存失效、重新验证、乐观更新与回滚；导航、卸载或会话变化后不得提交陈旧结果。
4. 明确加载、空、部分成功、无权限、会话过期、离线和可恢复/不可恢复失败状态；敏感数据不进入不受控存储、URL 或日志。
5. 添加状态、路由和数据流测试；测试替身须受契约约束，并覆盖竞态、重试、回滚和 SSR/hydration 等适用边界，记录需真实环境证明的项目。

## 输出格式

```markdown
## Web 状态与数据实现自测记录
- 用户路径、路由与状态所有权：
- 接口、认证和错误语义：
- 缓存、取消、竞态、乐观更新与回滚：
- 加载、空、权限、离线和恢复状态：
- 自动化测试与契约替身：
- 遥测和敏感数据处理：
- 未覆盖项、真实依赖验证需求和剩余风险：
```

## 停止条件

- 当关键数据流和状态转换有测试，竞态与失败语义明确，且代表性用户路径可本地运行时，交给前端协调层和本地质量验证。
- 当结论依赖真实认证、浏览器存储、服务端渲染或后端协同时，交给 `web-functional-compatibility-validation` 或系统级验证。
- 当接口、权限或数据所有权不清时，回流方案与契约设计，不以客户端补丁掩盖边界问题。
