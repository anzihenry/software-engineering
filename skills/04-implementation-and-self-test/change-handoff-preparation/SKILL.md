# 变更交接准备

让评审者和集成验证者无需猜测变更意图、证据和发布影响即可开始工作。此 SKILL 仅准备材料；它不执行独立评审、不合并代码，也不批准发布。

## 输入

- 已完成的代码/配置/迁移变更、自测记录、本地质量验证结果。
- 关联需求、设计、风险评估、验证策略和发布恢复预案。

## 工作方式

1. 汇总变更目的、范围和非目标，并链接到需求、设计和风险记录；明确本次变更是否包含迁移、接口、权限或运行影响。
2. 列出已完成的测试与本地检查，以及未验证项目、环境限制和剩余风险；不将计划中的检查写成已完成。
3. 更新受影响的接口说明、迁移说明、运行手册、用户文档或变更日志，并说明不需要更新的理由（如适用）。
4. 写明发布影响：特性开关、部署/迁移顺序、观测、回滚/前滚注意事项、审批或专项评审状态。
5. 形成可供独立评审的 PR 描述，保证变更粒度和提交内容与描述一致；过大的混合变更应先拆分。

## 输出格式

```markdown
## PR / 交接说明
- 目的、关联需求与设计：
- 变更范围与非目标：
- 关键实现选择：
- 数据、配置、接口和权限影响：
- 已运行测试与质量检查：
- 未验证项、限制与剩余风险：
- 文档更新：
- 发布、观测与恢复注意事项：
- 需评审者特别关注的事项：
```

## 停止条件

- 当材料能让独立评审者理解意图、风险、证据和发布影响时，提交给集成验证阶段。
- 当关键测试、迁移说明或发布风险缺失时，回到相应实现/验证工作，不以简短 PR 描述掩盖。
- 不在本 SKILL 中自行批准、合并或发布变更。
