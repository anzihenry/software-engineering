# 变更交接准备

让评审者和集成验证者无需猜测变更意图、证据和发布影响即可开始工作。此 SKILL 仅准备材料；它不执行独立评审、不合并代码，也不批准发布。

## 输入

- 当前代码/配置/迁移对象及状态、自测记录、本地质量验证完整结果；未完成对象只能准备材料或Draft协作。
- 关联需求、设计、风险评估、验证策略和发布恢复预案。

## 工作方式

1. 汇总变更目的、范围和非目标，并链接到需求、设计和风险记录；明确本次变更是否包含迁移、接口、权限或运行影响。
2. 列出已完成的测试与本地检查，以及未验证项目、环境限制和剩余风险；不将计划中的检查写成已完成。
3. 更新受影响的接口说明、迁移说明、运行手册、用户文档或变更日志，并说明不需要更新的理由（如适用）。
4. 写明发布影响：特性开关、部署/迁移顺序、观测、回滚/前滚注意事项、审批或专项评审状态。
5. 形成可供独立评审的 PR 描述，保证变更粒度和提交内容与描述一致；过大的混合变更应先拆分。

## 交接资格与状态

先按[阶段04正式交接七项](../../../docs/workflows/04-implementation-and-self-test.md#输出与阶段-05-交接)核对范围/授权、实际变更版本、验收风险映射、完整实际自测、限制/后续验证、配套完成和真实交接决定。使用[变更交接模板](../../../templates/delivery/change-handoff.md)，可在现有Issue/PR维护唯一主记录；需求/方案/任务/验证事实留原处，以ID链接，不复制状态。

本阶段完整实现与必需自测实际通过、文档/译文/迁移/配置和当前证据到位才标待评审。既有失败、环境缺工具、重试绿不能靠记录风险变通过；保留原始结果，既定后续05项列负责人/节点/判据/证据/停止动作。Draft讨论或诊断CI可早于完成，不能当正式接收或验证中。

沿用[七状态与转换证据](../../../docs/workflows/04-implementation-and-self-test.md#变更交接七状态)：实现中、待评审、验证中、可合入、阻塞、已合入、已关闭。05实际接收并执行才验证中；作者不能凭自测标可合入。接收不是通过、合入不是发布、关闭不是成功证明。实际转换保留原/新状态、理由、对象版本、主体/权限、带时区时间及证据；新变更重评受影响就绪性，不补造接收/批准。

05接收前核对当前对象/证据/前置，缺口退回受影响范围；未受影响授权工作可继续。当前候选变更按workflow重验，不拿旧提交成功覆盖新候选。

## 分支交接要求

执行分支操作时调用 `git-branch-management`；按[分支规范](../../../docs/git-branch-workflow.md)记录任务分支、remote/upstream、base/head、同步与冲突处理，以及最新检查。提交/推送请求默认针对任务分支，核对暂存范围并保留无关工作；默认/受保护分支不创建任务提交。误在基线分支修改/提交时先安全恢复，不直接推送基线。此技能只记录交接，不因准备材料获得推送或合并权限。

## 文档交付要求

使用 `documentation-maintenance` 和[统一检查模板](../../../templates/documentation/delivery-check.md)记录实际文件影响、双语更新、机械检查与当前快照，交给非作者 `documentation-delivery-validation`。尚未独立通过时明确待验证；不能把模板填写等同验收。

## 输出格式

```markdown
## PR / 交接说明
- 任务分支、remote/upstream、base/head 与同步状态：
- 目的、关联需求与设计：
- 变更范围与非目标：
- 关键实现选择：
- 数据、配置、接口和权限影响：
- 已运行测试与质量检查：
- 未验证项、限制与剩余风险：
- 文档更新：
- 发布、观测与恢复注意事项：
- 需评审者特别关注的事项：
```

## 停止条件

- 材料完整且阶段04正式门槛满足后交阶段05，记录实际接收方及下一动作；材料清楚但必需检查未通过时仅限准备/Draft协作。
- 当关键测试、迁移说明或发布风险缺失时，回到相应实现/验证工作，不以简短 PR 描述掩盖。
- 不在本 SKILL 中自行批准、合并或发布变更。
