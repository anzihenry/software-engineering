# 数据与配置变更

确保有状态或敏感的变更具备明确的边界、验证和恢复方式。仅在涉及数据、迁移、配置、权限或密钥时使用；它不执行生产操作，也不处理未授权的敏感信息。

## 输入

- 设计中的数据/契约迁移和发布恢复预案、风险等级、现有配置管理与数据政策。
- 受影响环境、数据规模、访问控制、保留规则和可用恢复能力。

## 工作方式

1. 列出受影响的数据集、配置键、权限和环境，区分版本化的应用配置、部署配置、运行时开关与秘密信息。
2. 对迁移确认前向兼容、读写顺序、回填/双写、批量大小、执行时长、完整性校验和恢复策略；不可逆数据操作必须显式标注并按高风险处理。
3. 将密钥只保留在批准的秘密管理系统或部署注入路径中；不得写入源代码、示例值、日志、测试快照或 PR 描述。
4. 对权限与配置变更定义最小权限、默认安全值、环境差异、审计需求和生效/回退方式。
5. 确定可在非生产环境验证的内容、必须在发布期间观察的信号，以及需要专家或所有者确认的事项。

## 输出格式

```markdown
## 数据与配置变更记录
- 受影响数据/配置/权限及环境：
- 数据迁移与完整性校验（如适用）：
- 兼容性与执行顺序：
- 密钥处理路径（仅描述机制，不记录秘密）：
- 最小权限与审计要求：
- 验证、监控与恢复方式：
- 不可逆风险、审批和待决事项：
```

## 停止条件

- 当变更有明确的受控存放方式、验证和恢复路径时，交给本地质量验证与交接准备。
- 当数据完整性、秘密管理或恢复能力不能被确认时，停止实现并升级给对应所有者。
- 不在本 SKILL 中访问、输出或传播真实密钥，也不执行生产迁移。
