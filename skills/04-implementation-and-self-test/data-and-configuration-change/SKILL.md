# 数据与配置变更

确保有状态或敏感的变更具备明确的边界、验证和恢复方式。仅在涉及数据、迁移、配置、权限或密钥时使用；它不执行生产操作，也不处理未授权的敏感信息。

## 输入

- 设计中的数据/契约迁移和发布恢复预案、风险等级、现有配置管理与数据政策。
- 受影响环境、数据规模、访问控制、保留规则和可用恢复能力。

## 工作方式

1. 列出受影响的数据集、配置键、权限和环境，区分版本化的应用配置、部署配置、运行时开关与秘密信息。
2. 对迁移确认前向兼容、读写顺序、回填/双写、批量大小、执行时长、完整性校验和恢复策略；所有数据迁移沿用生命周期高风险要求，不仅不可逆迁移；不可逆操作额外显式标注。按批准判据验证数据不变量、读写/事件顺序、重复/并发、部分失败、兼容与非生产恢复，保留实际数据规模/命令/结果；脚本存在不等于恢复已验证。
3. 将密钥只保留在批准的秘密管理系统或部署注入路径中；不得写入源代码、示例值、日志、测试快照或 PR 描述。
4. 对权限与配置变更定义最小权限、默认安全值、环境差异、审计需求和生效/回退方式；实际验证缺失/非法值、开关开启/关闭和恢复路径，不能用开关掩盖本范围关键实现缺失。
5. 确定可在非生产环境验证的内容、必须在发布期间观察的信号，以及需要专家或所有者确认的事项。

新增依赖或工具链变化先确认原授权、必要性、兼容及锁文件和受影响目标；无授权回相应设计/范围决定，不当成普通配置修复。权限、资金、敏感数据和日志遵守原专项/负例门禁；不得用本地绿测替代所有者或人类高风险决定。

按[阶段04](../../../docs/workflows/04-implementation-and-self-test.md)区分本节点必需实测和既定后续验证，后续列负责人/节点/判据/证据/失败动作。若本节点规定迁移恢复却未执行，记录not-run或blocked并补齐，不能正式交接；不执行生产迁移来补本地证据。测试环境成功与实际生产操作授权分别记录。

## 输出格式

```markdown
## 数据与配置变更记录
- 受影响数据/配置/权限及环境：
- 数据迁移与完整性校验（如适用）：
- 兼容性与执行顺序：
- 密钥处理路径（仅描述机制，不记录秘密）：
- 最小权限与审计要求：
- 验证、监控与恢复方式：
- 不可逆风险、审批和待决事项：
```

## 停止条件

- 受控存放、实现及本节点必需验证/恢复实际完成、证据绑定当前对象，后续控制有明确安排后，交给本地质量验证与交接准备；不能只凭计划存在宣称完成。
- 当数据完整性、秘密管理或恢复能力不能被确认时，停止实现并升级给对应所有者。
- 不在本 SKILL 中访问、输出或传播真实密钥，也不执行生产迁移。
