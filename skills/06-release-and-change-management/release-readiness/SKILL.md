# 发布就绪检查

确认发布候选已具备受控推进的最低条件。此 SKILL 只形成就绪结论，不批准发布，也不实际部署、修改环境或执行回滚。

## 输入

- 可追溯的发布候选版本、合入/验证证据、风险等级和发布恢复预案。
- 目标环境状态、部署配置、依赖健康、监控告警、发布窗口和值守/沟通安排。

## 工作方式

1. 确认候选版本与构建产物可追溯至已验证提交，且目标范围、配置和迁移版本明确。
2. 核对风险所需的审批、专项评审、发布窗口和值守责任是否满足；缺失授权不以口头假设补足。
3. 检查目标环境及关键依赖的健康状态，确认仪表板、日志、告警和健康检查在发布前可用。
4. 审查发布控制、推进批次、暂停条件、回滚/前滚和数据恢复路径；必要时确认关键操作已在非生产环境预演，未预演部分需标出剩余风险。
5. 给出 Go、条件 Go 或 No-Go 结论；条件 Go 必须列出在开始前可验证完成的具体条件与责任人。

## 输出格式

```markdown
## 发布就绪结论
- 候选版本、目标范围与风险等级：
- 验证/审批/专项评审状态：
- 环境与依赖健康：
- 观测、告警和值守准备：
- 发布控制、迁移与恢复预案：
- 预演结果与未验证风险：
- 结论：Go | 条件 Go | No-Go
- 开始前需完成的动作与责任人：
```

## 停止条件

- 当结论和未满足条件清晰时，交给有权限的发布负责人决定是否执行。
- 关键环境、观测、恢复、审批或值守条件缺失时，结论为 No-Go 或条件 Go，不建议开始发布。
- 不将部署命令可用或 CI 成功等同于发布就绪。
