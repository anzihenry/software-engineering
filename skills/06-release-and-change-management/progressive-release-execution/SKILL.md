# 渐进发布执行

按既定发布预案以小范围、可观测的方式推进变更，并保存可恢复的操作记录。此 SKILL 不在未获明确授权时操作生产环境，也不允许临时扩大范围或跳过暂停条件。

## 输入

- 发布就绪 Go/条件 Go 结论、已授权的发布预案和当前版本/环境状态。
- 发布批次、开关/部署机制、观察指标与阈值、暂停/恢复步骤和值守人。

## 工作方式

1. 在每次操作前确认授权仍有效、当前环境与预案一致、source SHA/制品摘要未变化、前一批次已满足继续条件。
2. 确认生产环境只有一个部署在执行；对生产 concurrency 不自动取消正在运行的部署，以免留下半完成迁移或未知状态。
3. 按预案推进一个批次或步骤，例如部署到目标环境、启用有限范围开关或扩大金丝雀受众；不重新构建制品，也不同时引入未在预案中的改动。
4. 记录时间、版本/摘要、GitHub workflow/deployment、目标范围、操作者、操作结果和相关配置/迁移状态，确保可追溯。
5. 进入预定观察窗口，将健康信号交给 `release-health-assessment` 形成继续、暂停或恢复建议。
6. 若达到暂停条件或出现不在预案内的异常，停止扩大范围，保留证据并通知发布负责人；恢复操作转交 `release-recovery-execution` 按授权预案执行。

## 输出格式

```markdown
## 渐进发布记录
| 时间 | 版本/摘要与 GitHub deployment | 环境与范围 | 已执行步骤 | 结果 | 观察窗口/后续决定 |
| --- | --- | --- | --- | --- | --- |

- 当前发布状态：未开始 | 进行中 | 暂停 | 已恢复 | 已完成
- 授权与预案引用：
- 偏差、异常与已通知对象：
```

## 停止条件

- 每个批次完成后，等待健康判定再继续；达到目标范围或收到暂停/恢复决定时结束当前执行。
- 缺少授权、预案或健康信号时，不执行生产操作。
- 不在本 SKILL 中自行批准超出预案的扩容、回滚或前滚。
