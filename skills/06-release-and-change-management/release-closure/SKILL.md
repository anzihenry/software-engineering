# 发布收口

确认发布已在目标范围内稳定，并将后续运行和支持所需信息完整交接。此 SKILL 不掩盖未解决问题，也不把“部署完成”误写为“发布成功”。

## 输入

- 发布记录、健康评估、目标范围、观察窗口、变更候选和支持/沟通计划。
- 当前生产版本、已知问题、运行手册、变更日志和用户/内部通知渠道。

## 工作方式

1. 确认目标发布范围是否已达到，观察窗口内关键健康指标是否稳定，以及是否存在未处置的严重告警或用户影响。
2. 记录最终结论：成功、已回滚、前滚修复中或暂停；结论应与实际版本、范围和健康证据一致。
3. 更新变更记录、版本信息、运行手册、监控链接、特性开关状态和必要的用户/内部通知。
4. 将已知问题、剩余风险、观察期限、支持指引和需跟踪的行动项交接给运行与支持团队。
5. 对未达预期、回滚或重大异常，创建事故/复盘或改进输入，避免以发布关闭取代问题治理。

## 输出格式

```markdown
## 发布收口记录
- 最终版本、环境与上线范围：
- 观察窗口与健康证据：
- 发布结论：成功 | 已回滚 | 前滚修复中 | 暂停
- 已更新的变更/运行/用户信息：
- 已知问题、剩余风险与观察期限：
- 支持交接与责任人：
- 新增事故、复盘或改进行动：
```

## 停止条件

- 当发布结论、运行交接和待跟踪事项已清楚时，交给阶段 7 运行与支持。
- 存在未处置的严重影响时，不以成功收口；转入恢复或事故响应。
- 不删除、改写或淡化发布过程中的失败证据。
