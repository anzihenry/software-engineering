# 发布健康评估

基于发布前定义的指标与阈值评估当前批次的影响，给出可解释的推进或恢复建议。此 SKILL 不将单一短暂指标视为根因，也不在未授权时实际执行处置操作。

## 输入

- 当前 GitHub deployment、发布批次、版本/制品摘要、基线版本、目标范围、观察窗口和预设继续/暂停/恢复阈值。
- 业务、错误率、延迟、资源、数据完整性、SLO、告警和用户反馈信号。

## 工作方式

1. 确认观测对应当前 deployment、版本/制品摘要和批次，覆盖足够的观察窗口与受众范围，并与发布前基线、对照组或未受影响范围比较。
2. 检查预设的关键技术和业务信号，区分超过硬阈值、接近阈值、数据不足和与发布无明显关联的异常。
3. 排查基础信号质量：监控中断、采样变化、已知外部事件或依赖故障可能使结论不可靠时，明确标注。
4. 将观察结果与预案判据对应，建议继续当前批次、扩大范围、暂停调查、回滚或前滚；说明证据、置信度和需要授权的操作。
5. 对严重或快速恶化的影响，建议立即停止推进并转交发布负责人或事故响应；不等待完整根因分析才控制影响。

## 输出格式

```markdown
## 发布健康判定
- GitHub deployment、版本/摘要、批次、范围与观察窗口：
- 基线/对照与数据质量：
| 信号 | 阈值/预期 | 实际观察 | 趋势 | 判定 |
| --- | --- | --- | --- | --- |

- 异常与可能混杂因素：
- 建议：继续 | 扩大范围 | 暂停 | 回滚 | 前滚 | 转入事故响应
- 证据、置信度与需授权操作：
```

## 停止条件

- 当当前批次已有与预案一致的建议和证据时，交给发布负责人或获授权自动化执行。
- 指标不足、监控不可信或异常无法归类时，建议暂停并补充证据，而非默认继续。
- 不因部署任务成功就建议扩大范围。
