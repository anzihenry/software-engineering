# 契约与迁移设计

为跨边界行为和数据演进定义可实现、可验证、可恢复的契约。仅在变更涉及接口、事件、共享数据、数据模型或迁移时使用；纯内部且无数据影响的变更无需强制使用。

## 输入

- 选定方案、需求包、风险评估，以及现有接口、事件或数据模型。
- 生产数据规模、消费者/提供方、保留政策、兼容性和恢复约束（如适用）。

## 工作方式

1. 列出生产者、消费者、所有权边界与受影响版本；不要把内部实现细节误当成对外承诺。
2. 定义契约的请求/响应或事件结构、字段语义、校验规则、错误语义、授权、幂等性、顺序与超时/重试要求。
3. 设计兼容性：新增、修改、弃用和删除的版本策略，以及各方切换次序。对外或跨服务变更不得假定消费者与提供者同步部署。
4. 涉及数据时，明确源/目标模型、读写路径、回填或双写、完整性校验、数据保留和审计需求。
5. 为迁移设计可操作路径：前向兼容、执行批次/时长、暂停点、失败处理、回滚或前滚策略；不可逆操作必须显式标注并升级风险。

## 输出格式

```markdown
## 契约与迁移设计
- 边界、所有者与受影响消费者：
- 版本与兼容性策略：
- 契约：输入/输出或事件、字段语义、错误、授权、幂等性：
- 数据模型与完整性规则（如适用）：
- 迁移/回填路径（如适用）：
- 验证方法：
- 恢复方式与不可逆风险：
- 待确认事项：
```

## 停止条件

- 当消费者、契约语义、兼容性、数据完整性和恢复路径清楚时，交给验证与发布恢复规划。
- 当外部所有者、数据政策或恢复能力不明时，停止实现设计并要求相应负责人确认。
- 不在本 SKILL 中执行迁移或修改生产数据。
