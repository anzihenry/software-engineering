# 技术设计评审

## 独立性与输入

按[阶段 03 workflow](../../../docs/workflows/03-solution-and-planning.md)及[质量门禁](../../../docs/quality-gates.md)执行。中高风险、跨服务/迁移或明显架构影响的设计由未参与编写/修改的评审者独立读取当前需求/方案/计划、原始预研证据及契约/验证/恢复设计；低风险可按项目简化，既有独立文档/领域要求仍保留。角色可兼任不等于作者能自批；Agent不能替有权安全/合规/架构/运维确认。

## 审查与结论

1. 固定所审需求/方案/计划的修订或摘要及范围，逐项核对七项设计标准、原约束及实测/推断/未验证边界；资料缺失不假定正确，代码审查先读编码规范/common/实际语言及项目配置。
2. 核对失败/权限/一致性/兼容/容量/恢复/依赖与运维所有权；高风险触发含数据迁移，后果和控制按实际证据判断，不因代码少或计划审计/回滚降级。
3. 需要编码的预研应有独立worktree/基线/授权/投入上限/判断和真实运行轨迹，结果仅在适用环境规模有效；核对必要材料已在工作区外可复验、清理实际事实或保留理由，原型未自动合入。失败/无结论不当可行，小样本不推全量。
4. 区分阻塞项、本节点必需确认、后续节点必做项及非阻塞建议。每项有位置/依据、影响/动作、责任/节点及失败停止范围；本节点未完成不能改为建议放行，后续才能做的验证不能预填通过。技术计划不能替必需专业评估或生产授权。
5. 给出“所审范围通过 / 修订后复审 / 需补专项评审 / 退回需求或方案”的技术结论，列实际读取/证据、发现与复核。中高风险保留设计评审，高风险本节点安全/合规/运维可行性需实际确认；前置条件未满足不以有条件批准推进。

## 输出与权限边界

结论绑定当前版本、范围/限制、评审身份/独立性、原始证据、时间及时区及复审触发，更新或链接[方案记录](../../../templates/delivery/solution-decision.md)，不另造整体批准。技术评审通过不等于实施准备或实际开发授权；容量/负责人/依赖不足交计划核对，真正开发决定由有权角色针对当前基线作出。明确隔离的已就绪切片可单独评审/批准，其余保持真实状态。

涉及文档交付按[文档规范](../../../docs/documentation-standard.md)交 `documentation-delivery-validation`，作者不能自批；所审内容/基线或关键条件改变后复核受影响范围，旧批准不覆盖新范围。存在阻塞或缺必需证据时输出最小解阻动作，不给可进入开发的混合结论。
