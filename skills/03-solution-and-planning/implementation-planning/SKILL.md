# 实现计划

读取[阶段 03 workflow](../../../docs/workflows/03-solution-and-planning.md)的计划/门禁/变更规则，接收当前需求/选定方案、契约/验证/恢复、预研实际结论、真实依赖、团队容量/已有承诺和项目权限。不重新定义验收或方案状态。

- 固定本次范围/非目标和需求/方案版本，按可审查、可验证的产出拆任务；技术任务可按模块，但关联到完整结果，列完成判据、实际负责人/接受证据、依赖所需节点、顺序/关键路径/可并行范围。
- 完整计入适用实现、测试、文档/译文、迁移、观测、独立评审、发布准备及运行交接；技术预研单列投入/上限/判断/退出，不把未验证方案的正式工作承诺成已确定任务。预研编码使用独立worktree，计入证据保全与清理成本，代码不自动复用。
- 给规模或区间、依据/假设/不确定性，区分工作量、日历耗时及等待/专业评审。核对实际容量和已有承诺，责任人需实际接受，Agent不替团队接单、挤出既有承诺或确认日期。
- 依赖按已识别/待确认/已确认及实际交付情况记录；无回复/联系人/路线图不当当前能力。只要求当前切片所需前置满足，后续资源按节点到位；mock设计/实现不证明真实集成。
- 顺序兼容验证和恢复（例如先可观测/兼容再迁移/切流），记录验证失败、依赖/容量/范围变化的重估触发和可继续/需等待范围。部分批准需接口/数据/权限/发布依赖隔离依据，不以公共代码先做未批准能力。

在原任务系统或[方案主记录](../../../templates/delivery/solution-decision.md)维护一份任务表：任务/产出、完成条件、依赖顺序、区间依据、负责人及实际确认；引用而非复制状态。汇总实施准备结论/缺口，估算不自动形成承诺；有权角色需针对当前基线实际批准开发，已有有效覆盖授权可核实引用。期望日期仅约束，需要日期承诺另核容量/依赖/验证评审和发布准备。

交接workflow七项给阶段04，由接收人核对版本、实际授权、当前任务前置/阻塞及规范/配置/命令可用。设计通过但容量/关键依赖未确认时保留技术结论、报告准备不足，不能宣布阶段03完成；业务/风险变化回02，技术变化回03，价值回01，容量时间变化重评计划。
