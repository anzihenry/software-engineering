# 发布与恢复规划

在实施前定义变更如何安全进入目标环境，以及出现异常时如何控制影响并恢复。此 SKILL 只产出预案，不执行发布或审批生产变更。

## 输入

- 选定方案、风险等级、契约/迁移设计、验证策略和现有部署能力。
- 目标环境、SLO/SLI、监控告警、发布窗口、值守和恢复约束。

## 工作方式

1. 明确发布单位、环境推进顺序、前置依赖及每一步的成功条件；迁移和应用版本必须按兼容性要求排序。
2. 选择与风险相称的控制方式：特性开关、灰度、金丝雀、分批发布或维护窗口。无法渐进时，记录原因和增强控制。
3. 定义观察信号与阈值：错误率、延迟、资源、数据完整性、关键业务行为及 SLO；为每个信号指定观察窗口和责任人。
4. 预先定义继续、暂停、回滚和前滚的条件与执行步骤。若版本回滚不能恢复数据，必须给出前滚/数据恢复路径并升级风险。
5. 识别发布期间的沟通、值守、审批和用户支持需求，链接运行手册或需补建的能力。

## 输出格式

```markdown
## 发布与恢复预案
- 版本/变更范围与风险等级：
- 环境与推进顺序：
- 发布控制（开关、灰度、金丝雀等）：
- 前置检查与责任人：
- 观察指标、阈值与窗口：
- 继续/暂停/回滚/前滚判据：
- 迁移与数据恢复步骤（如适用）：
- 值守、沟通、审批和支持安排：
- 未验证风险与需补充能力：
```

## 停止条件

- 当推进、观测和恢复均有可执行路径与责任人时，交给实现计划和技术设计评审。
- 当缺少可接受的恢复路径或关键观测能力时，停止进入开发承诺，先补能力或回到方案决策。
- 不以“可重新部署”替代已验证的恢复计划。
