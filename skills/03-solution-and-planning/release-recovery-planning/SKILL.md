# 发布与恢复规划

读取[阶段 03 workflow](../../../docs/workflows/03-solution-and-planning.md)与当前方案/风险、契约/迁移、验证安排、现有部署/观测/恢复能力和目标环境约束。复用运行手册，不另维护发布状态或取得生产权限。

- 明确发布单位、环境顺序、前置依赖、版本兼容、每步成功/停止条件及负责人；迁移与应用按兼容次序，不假定重新部署会恢复数据。
- 按风险选择开关、灰度、金丝雀、批次或维护窗口；无法渐进需原因及相应控制。保留高风险渐进发布要求，若所选方案无法满足既有必需控制则调整方案或补能力，不能以本技能自批例外。
- 定义错误、延迟、资源、数据不变量、关键业务及SLO信号的来源、阈值/窗口和责任；关键判据不足先补依据，不编基线。设计继续/暂停/回滚/前滚/数据恢复的具体动作、触发及验证。
- 区分恢复路径设计及必要可行性证据、后续实现/预生产演练和实际生产结果。阶段03应有合理可操作路径；关键恢复/观测能力未知先补预研/评估或调整方案。只能后续执行的演练保留责任、完成节点、判断、证据和失败停止动作，不提前虚填成功，也不因尚无实现一律阻塞全部设计。
- 标明值守、沟通、审批和支持需求的实际接受情况、待补能力与节点。方案/开发批准不产生发布授权，高风险/生产人类Go/No-Go按既有门禁保留。

输出到[方案记录](../../../templates/delivery/solution-decision.md)及验证矩阵的推进/观测/恢复安排，交实现计划和独立设计评审。阶段06按当前制品和实际环境再次判断并执行；本技能不发布、不批准例外，不以“可重部署”当已验证恢复。
