# 方案设计与决策

在需求与约束已明确时，选择最合适的实现路径并使决策可追溯。此 SKILL 不负责具体编码、任务排期或正式专家审批。

## 输入

- 需求包、验收标准、非功能要求、风险评估、依赖与既有架构约束。
- 可用的运行基线、成本边界、平台能力及相关设计记录。

## 工作方式

1. 从需求和约束中提取必须满足的结果、兼容性边界和不可接受风险；将尚未验证的高影响假设单独列出。
2. 提出最小可行方案，并在风险或取舍显著时比较一至两个实质不同的备选方案。不要为形式而罗列微小变体。
3. 比较方案对架构边界、数据、权限、安全、可靠性、性能、运维、成本、交付复杂度和未来演进的影响。
4. 选择方案并记录理由、主要取舍、被拒绝方案及其适用条件；设计无法满足的需求须回流到业务/需求决策。
5. 标出需要契约设计、验证策略、发布恢复计划、Spike 或专家评审的后续工作。

## 输出格式

```markdown
## 方案决策
- 关联需求包与风险等级：
- 必须满足的结果与约束：
- 高影响假设：

### 方案 A（推荐）
- 概要与关键组件：
- 如何满足要求：
- 主要影响与取舍：

### 备选方案（如适用）
- 概要、优势、限制与未采用原因：

- 决策与理由：
- 后续设计/评审事项：
- 已知剩余风险：
```

## 停止条件

- 当方案覆盖需求、约束和主要风险，并有明确后续设计事项时，交给契约、验证和发布规划。
- 当关键假设无法以合理成本验证时，建议 Spike 或回到需求澄清；不要伪造确定性。
- 不在无业务授权时用技术偏好改变已确认的目标或范围。
