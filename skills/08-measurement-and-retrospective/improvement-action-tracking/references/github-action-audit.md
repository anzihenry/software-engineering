# GitHub 改进行动与审计契约

Issue Form要求复盘反链、一个协调所有者、ISO日期期限、完成定义、效果判据和观察窗口及公开安全确认；表单字段存在不认证实际接收、资源批准、效果或风险接受。六类行动状态/效果/关闭原因在关联行动记录单一维护，GitHub OPEN/CLOSED只表达平台开关；关闭既可能验证完成也可能停止等，不能自动认定实现完成或有效。

每周一02:00 UTC及手动审计读取普通Issue、评论与正式Release；只更新Actions summary/退出结果，不评论、标签、分配或关闭。当前实现读Due date，只有OPEN且due<as_of报行动逾期，关闭行动仍解析日期但不报该逾期；不解析新状态、接收和效果。待效果验证行动应保留可追踪责任/期限，不能仅靠关Issue让风险消失；已有关闭但效果未验的记录需主动核对/继续关联跟踪，不宣称只读审计自动覆盖。

审计对复盘的元信息、重复来源、开放逾期，以及恢复/关闭普通事故和正式非预发布Release缺复盘做检查；事故缺复盘按转换评论最早recovered/closed时间计算，不能与手动稳定锚点混同。记录异常会报告invalid；通过仅在实际读取范围/时点没有这些结构发现，不证明五类工作单元全部触发或行动风险降低。实际数据源、权限和当前policy需核对，未执行不报告已生效。
