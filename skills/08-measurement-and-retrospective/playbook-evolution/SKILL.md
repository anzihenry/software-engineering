# 研发手册演进

将有适用证据的做法经过限定试行和决定沉淀为团队准则、流程、SKILL 或自动化，同时删除或修正不再匹配实践的规则。此 SKILL 不把单次事件的临时应对扩大为普遍强制流程。

## 输入

- 来自度量、复盘、运行维护或实际使用的证据、改进行动和现有手册内容。
- 适用范围、团队约束、所有者和受影响的工具/自动化信息。

## 工作方式

1. 说明问题、证据和目标受众，区分可推广模式、局部修复和一次性观察；普遍性不足可限定试行，严重缺口按权限及时修复。
2. 选择最小合适载体：原则用于长期决策约束，workflow 用于跨角色编排，SKILL 用于高频场景指导，自动化用于重复且可确定验证的操作。
3. 定义变更的适用范围、输入输出、关键约束、例外、所有者和复审时间；避免复制通用知识或无证据增加门禁。
4. 对影响较大的变更先小范围试行，收集采用成本、质量与结果证据，再决定推广、修订或撤回。
5. 版本化更新相关文档、SKILL 或自动化引用，保持导航和相邻流程一致，并记录变更理由。

## 试行、采用与推广

按[08回流与演进](../../../docs/workflows/08-measurement-and-retrospective.md#回流与规则演进)判断局部修复还是通用实践。说明问题证据、受众/不适用条件、现有规则能否解决、执行维护验证成本及试行收益/副作用/撤回判据。普遍证据不足先限定试行，严重控制缺口按已有权限及时针对性修复，不需等多次事故；不直接推广偶发经验。

分别记提案、已批准试行、试行中、待决定、已推广、已撤回或替代，各次推进有实际证据/决定人/权限/时间。文件合入只发布事实，采用须核真实入口可达、执行条件与行为；试行效果和成本支持才有权推广。环境/规则/依赖变化或复审到期实际复核，不只改日期。停用保留历史、替代和受影响接收。

更新受影响workflow/技能/模板/导航/引用/适用译文及检查，独立验证绑定当前对象；不以文档存在认证CI强制。新需求回01、范围回02、可行性回03、已批实施走04及后续、当前风险交07，接收留来源/ID/人/时间，未接收原协调继续。

使用[效果复盘与行动记录](../../../templates/delivery/outcome-retrospective-actions.md)按类型填写适用部分，关联稳定ID，不重复维护状态。

## 输出格式

```markdown
## 手册演进提案/记录
- 问题、证据与目标结果：
- 选择的载体：原则 | workflow | SKILL | 自动化
- 适用范围与非目标：
- 拟定规则/流程/行为：
- 例外与风险：
- 所有者、试行范围与复审日期：
- 采用/效果证据与最终决定：推广 | 修订 | 撤回
```

## 停止条件

- 当变更有证据、明确范围、所有者和复审计划时，可进入试行或版本化更新。
- 偶发或边界不明先记录/补证或限定试行，不固化全局规则；严重缺口按权限针对性处置。
- 不以流程文档替代需要业务、技术或安全负责人作出的实际决策。

## Harness 运行观察与复验

按[运行指标与复验](../../../docs/harness-observation.md)区分产品效果与 harness 执行观察，使用[双语报告](../../../templates/documentation/harness-observation.md)。采集实际原始事件、分组/缺口和指纹变化；指标不能批准门禁或自动关闭行动。当前闭环由非作者实际核验，未执行复审不得推进日期。内部只读工具不代表目标 CI 或周期任务已接通。
