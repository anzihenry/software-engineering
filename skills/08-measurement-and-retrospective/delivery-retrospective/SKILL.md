# 交付复盘

从重要交付、延误或未达预期结果中提取可执行学习，关注系统、信息和流程而非归咎个人。此 SKILL 不替代运行事件的专项复盘，也不将意见当作未经验证的事实。

## 输入

- 交付背景、目标、计划/实际时间线、效果评估、质量/可靠性数据和参与者反馈。
- 已知假设、风险、依赖、变更记录和未完成事项。

## 工作方式

1. 确定复盘范围、目标和参与角色，收集可追溯的事实：计划与实际、关键决策、依赖变化、结果数据和用户影响。GitHub Release 来源必须已经正式发布而非 Draft/Prerelease，使用 `release:vX.Y.Z` 建立默认 30 天、隐藏来源标识去重的复盘 Issue。
2. 构建时间线，区分事实、解释、假设和意见；为存在分歧的叙述保留不确定性，不强迫达成虚假共识。
3. 讨论哪些做法有助于结果、哪些系统条件阻碍交付，以及哪些信号本可更早暴露风险。聚焦可改变的流程、工具、边界和信息流。
4. 将学习转化为少量影响明确的改进候选，并交给行动跟踪评估优先级、所有者和效果。
5. 记录无需行动的结论和仍待验证的假设，避免每次复盘都产生无价值的待办清单。

## 发现去向与复盘收口

按[08复盘契约](../../../docs/workflows/08-measurement-and-retrospective.md#无责备复盘与完成)接收对象/版本/范围、问题、角色、期限及实际接收。记录当时信息缺失/矛盾、可行选择/权限/资源约束、实际失败/取消/重试及副作用、新证据与决定变化；事实、当时判断、解释/意见分离，分歧保留双方依据。多因素说明证据和作用，不强求唯一根因；成功做法查可重复条件与侥幸。

每个重要发现明确新增已接收行动、已有行动并核覆盖、补调查责任期限、保留有效做法，或有权暂不行动/接受风险及重评条件；加强意识不能单独证明重大风险处置。事实影响、主要判断/局限、系统学习、发现去向、实际承接及必要沟通/受限信息要求齐备可完成复盘，长期行动继续，不提前写已实施或有效。新风险立即交07/专项，不延误处置。

GitHub正式Release入口只覆盖工具支持对象，其30天来自当前policy；非正式Release交付/周期趋势仍可用通用模板，不伪造正式来源。普通记录仅脱敏摘要/受控引用，疑似违规交专业机制，无责备保留事实和改进责任。

使用[效果复盘与行动记录](../../../templates/delivery/outcome-retrospective-actions.md)按类型填写适用部分，关联稳定ID，不重复维护状态。

## 输出格式

```markdown
## 交付复盘
- 范围、目标与参与角色：
- 结果与事实证据：
- 时间线：
- 有效做法与促成条件：
- 阻碍、风险信号和系统性因素：
- 改进候选与待验证假设：
- 不确定性和数据缺口：
```

## 停止条件

- 当学习、证据和改进候选已被记录时，交给行动跟踪或流程演进。
- 若发现未处置的严重运行影响或安全风险，转交相应事件/专项流程。
- 不将复盘用于评价个人表现或寻找单一责任人。
