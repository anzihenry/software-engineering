# 事件复盘

按当前处置阶段理解事件为何能在当时的系统条件下发生和持续，识别防止或降低重演影响的改进。此 SKILL 不延迟事件恢复以等待复盘，也不把复盘作为个人问责工具。

## 输入

- 事件当前处置阶段、时间线、影响范围、通信、实际处置操作和运行数据；未恢复保留当前响应责任。
- 架构/依赖信息、告警、发布记录、运行手册、历史相似事件和恢复目标。

## 工作方式

1. 先确认处置阶段，约定阶段性或恢复后复盘范围、参与角色及不延误响应的安排；敏感安全/隐私信息按专项要求处理。本仓库按 [GitHub 复盘自动化契约](references/github-retrospective-automation.md)建立去重、带期限的普通事故复盘。
2. 从证据重建时间线，包括检测、分诊、沟通、缓解、恢复和用户影响；区分观察事实、当时可获得的信息与事后推断。
3. 分析技术、流程、组织、工具、依赖和防护层如何共同促成影响或延长恢复。避免用“人为失误”作为终点，继续追问系统条件。
4. 识别有效防护、缺失/失效防护、检测与恢复盲区，并提出可验证的风险降低行动。
5. 记录结论、不确定性、行动候选和需要长期治理的主题；将行动交给统一跟踪，必要时回流需求、架构或运行维护。

## 阶段复盘与响应责任

按[08工作单元](../../../docs/workflows/08-measurement-and-retrospective.md#工作单元触发与接收)和[复盘完成](../../../docs/workflows/08-measurement-and-retrospective.md#无责备复盘与完成)区分未恢复阶段复盘与恢复/稳定后复盘。前者可及时保全/分析但不占用必要响应资源、不接走07责任或认证恢复；后续新事实/恢复证据补充并保留原判断。工具稳定确认不能为启动阶段复盘虚填。

时间线包括当时信号/未知/矛盾、权限/可选动作及约束、真实失败/取消/重试/副作用与新证据，事实/当时判断/事后推断分离。分析共同促成因素及有效/失效/缺失防护，不停在人为失误，不强造唯一根因或叙述共识。所有重要发现有实际去向/接收，重大风险及时专业处置、必要沟通和受限证据完整才复盘完成；长期行动继续，不替07或安全专项关闭。无责备不免事实补充/决定/实施/验证责任。

使用[效果复盘与行动记录](../../../templates/delivery/outcome-retrospective-actions.md)按类型填写适用部分，关联稳定ID，不重复维护状态。

## 输出格式

```markdown
## 事件复盘
- 事件、影响与恢复状态：
- 复盘范围与参与角色：
- 事实时间线：
- 当时可见信号与决策背景：
- 促成因素与系统条件：
- 有效/失效的防护与恢复能力：
- 改进行动候选、风险与不确定性：
```

## 停止条件

- 当事实、系统性学习和行动候选清晰时，交给行动跟踪和流程演进。
- 证据不足时标记不确定性并补充调查，不以事后推断代替事实。
- 不将无责备原则理解为不处理制度、设计或控制缺口。
