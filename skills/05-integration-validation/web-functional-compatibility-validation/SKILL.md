# Web 功能与浏览器兼容验证

在代表性浏览器和可信依赖环境中验证完整用户路径及浏览器运行时差异。视觉/辅助技术和性能分别交给对应专项验证；本 SKILL 不以测试替身结果代替必须由真实集成证明的行为。

## 输入

- 验收标准、风险等级、前端自测记录、待验证构建和浏览器/设备支持策略。
- 真实或契约可信的接口环境、测试账号/数据、认证配置及观测手段。

## 工作方式

1. 根据支持策略、用户分布和变更触点选择浏览器引擎、版本、设备类别与视口矩阵，明确自动化、人工和未覆盖范围。
2. 验证关键端到端路径及加载、空、无权限、会话过期、部分失败和恢复状态；检查刷新、前进/后退、深链和多标签页等适用导航行为。
3. 使用真实协议验证认证、Cookie/存储、缓存、文件上传下载及第三方集成；覆盖取消、重复提交、乱序响应、离线/重连和依赖失败。
4. 检查 SSR/hydration、客户端路由、Service Worker 或渐进增强等适用边界，记录控制台异常、失败请求和浏览器特有行为。
5. 将结果映射到验收标准和浏览器矩阵，区分产品缺陷、契约问题、环境问题与经批准的不支持范围。

## 输出格式

```markdown
## Web 功能与兼容性验证报告
| 要求/风险 | 浏览器、设备与环境 | 用户路径/场景 | 证据 | 结果 |
| --- | --- | --- | --- | --- |

- 导航、认证、存储与真实依赖结论：
- 失败、离线、竞态与恢复结论：
- 浏览器特有差异：
- 控制台、网络和环境异常：
- 未覆盖矩阵及影响：
- 总结：通过 | 有条件通过 | 阻塞 | 环境不可信
```

## 停止条件

- 当高风险用户路径和必要浏览器矩阵已有可信证据，且未覆盖范围已明确处置时，将结果交给 `web-frontend-validation`。
- UI 或状态实现失败回流对应前端开发；契约或跨服务问题回流后端/系统级验证。
- 关键浏览器或真实依赖无法验证时，不以单一浏览器或测试替身给出无条件通过结论。
