# Web 性能验证

在可复现条件下验证前端加载、交互和运行时性能，区分代码回归、环境噪声与第三方影响。使用项目预算和用户场景作为通过标准；实验室结果不无条件代替真实用户数据。

## 输入

- 性能预算、关键页面/用户路径、风险等级、待验证构建和可比较基线。
- 目标设备/浏览器、网络与 CPU 条件、资源清单、观测工具及可用的真实用户数据。

## 工作方式

1. 固定构建、浏览器、设备能力、网络/CPU、缓存状态、测试数据和重复次数；基线与候选必须在可比较条件下测量。
2. 按风险测量导航、关键内容呈现、交互响应和布局稳定性，以及适用的长任务、内存增长和持续交互性能；报告分布而非只取最佳单次结果。
3. 检查脚本、样式、字体、图片和第三方资源的体积、优先级、压缩、缓存及加载瀑布，识别阻塞、重复下载和未使用资源。
4. 将回归定位到网络、主线程、渲染、框架 hydration、缓存策略或第三方依赖，并说明证据；不通过放宽预算或移除观测来制造通过。
5. 对照可用的真实用户信号评估实验室代表性，记录设备/网络覆盖、波动范围和只能在发布后继续观察的指标。

## 输出格式

```markdown
## Web 性能验证报告
| 页面/路径 | 场景与环境 | 指标/预算 | 基线 | 候选 | 结论 |
| --- | --- | --- | --- | --- | --- |

- 资源、缓存与第三方影响：
- 主线程、渲染与运行时瓶颈：
- 测量波动和环境限制：
- 实验室与真实用户信号差异：
- 发布后继续观察的指标：
- 总结：通过 | 有条件通过 | 阻塞 | 环境不可信
```

## 停止条件

- 当关键页面/交互已有可重复测量且预算结论明确时，将结果交给 `web-frontend-validation`。
- 代码或资源回归回流对应前端开发；预算与产品目标冲突时回流方案/需求决策。
- 基线不可比、环境波动过大或关键指标缺失时，结论为环境不可信或有条件，不给出无依据的通过。
