# CI 质量门禁评估

确认 CI 对当前变更执行了必需检查，并准确解释结果、失败和限制。此 SKILL 不修改、禁用或绕过 CI 门禁，也不把环境失败描述为验证成功。

## 输入

使用[质量门禁规范](../../../docs/quality-gates.md)核对例外；既有必过 CI 不可豁免，原始失败或未运行结果必须保留。

- PR 的提交标识、风险等级、所需门禁和 CI 运行结果。
- 构建日志、测试/扫描报告、基线或已知环境问题（如有）。

## 工作方式

1. 从项目受控规则、验收/风险及[阶段05](../../../docs/workflows/05-integration-validation.md)核对完整期望集合，绑定PR/head/base、实际所测集成源码/构建或main合入SHA；回读真实平台run/job/check及来源，不能只信PR自填passed或只看已出现的绿项。
2. 逐项核对格式/静态/类型/构建/测试/依赖密钥及适用专项、端到端是否真实执行。未触发、取消、超时、错误跳过不能通过；原平台结论保留，用passed/failed/not-run/blocked/stale/not-applicable准确归类，NA需规则及事实，缺环境不算不适用。
3. 保存原始日志/报告、实际命令/环境/时间/退出码和范围。保留首次及全部重试、基线与当前失败；重试绿不能抹掉失败，已有Issue不豁免必过项，不删测/禁用/continue-on-error制造通过。
4. 代码回04、关键方案回03、业务验收回02；环境所有者解阻，测试缺陷按确认依据修正且仍检错。调查无结论保留未解决，给影响范围/责任/最小解阻/复验条件；未受影响授权工作可继续。
5. 区分PR旧诊断可取消和每次合入后必需端到端不可丢失；取消/超时要补跑准确对象，B版本绿不自动替代A。实质修改/目标基线/依赖环境变动按影响失效重验；未变证据可依规则复用，但要求最新head的CI与前后端到端仍实际执行。
6. 例外仅沿质量门禁允许的非强制范围，核对真实授权/对象/节点/到期/补救，保留原结果；既有必过CI/文档译文/证据/独立性及高风险人类决定不能豁免。结果给独立评审/系统验证/merge-readiness或合入后收口，不自行合并或接受风险。

## 输出格式

```markdown
## CI 质量门禁结论
- 提交/目标分支与运行标识：
- 必需门禁与状态：
- 失败或未运行项及影响：
- 环境可信度与限制：
- 已批准豁免及到期/补救计划：
- 结论：通过 | 阻塞 | 需重跑；非强制例外另列，不替代必需通过
- 后续责任人和动作：
```

## 停止条件

- 当当前提交的必需门禁状态及任何例外已准确记录时，交给评审、系统验证或合入就绪确认。
- 当失败或不可信环境影响关键验证时，结论为阻塞或需重跑；不得用部分成功掩盖。
- 不在本 SKILL 中改变 CI 配置或批准豁免。
