# CI 质量门禁评估

确认 CI 对当前变更执行了必需检查，并准确解释结果、失败和限制。此 SKILL 不修改、禁用或绕过 CI 门禁，也不把环境失败描述为验证成功。

## 输入

- PR 的提交标识、风险等级、所需门禁和 CI 运行结果。
- 构建日志、测试/扫描报告、基线或已知环境问题（如有）。

## 工作方式

1. 确认 CI 运行对应当前待合入提交和目标分支；目标或提交变化后，先判断是否需要重新执行检查。
2. 检查按风险和项目规则要求的构建、格式化、静态/类型分析、测试、依赖、密钥及适用的其他扫描是否实际运行。
3. 分类结果：通过、代码/配置失败、测试失败、基础设施/环境失败、已批准豁免或未运行。每类都保留可追溯链接或摘要。
4. 对失败定位到可行动的责任边界；代码或设计问题回流实现/设计，环境问题需说明其对验证可信度的影响并修复或替换环境。
5. 对豁免确认授权人、原因、范围、到期时间和补救计划。无此记录的失败不得视为已豁免。

## 输出格式

```markdown
## CI 质量门禁结论
- 提交/目标分支与运行标识：
- 必需门禁与状态：
- 失败或未运行项及影响：
- 环境可信度与限制：
- 已批准豁免及到期/补救计划：
- 结论：通过 | 阻塞 | 需重跑 | 需处理豁免
- 后续责任人和动作：
```

## 停止条件

- 当当前提交的必需门禁状态及任何例外已准确记录时，交给评审、系统验证或合入就绪确认。
- 当失败或不可信环境影响关键验证时，结论为阻塞或需重跑；不得用部分成功掩盖。
- 不在本 SKILL 中改变 CI 配置或批准豁免。
