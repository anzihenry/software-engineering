# 文档交付独立验证

## 输入与独立性

读取[通用规范](../../../docs/documentation-standard.md)、目标项目执行配置、[统一交付检查模板](../../../templates/documentation/delivery-check.md)、当前实现/diff、双语文档、原始检查证据及提交或摘要快照。相对链接需要完整 harness checkout；单独技能安装必须提供固定规范/模板或项目等价副本，缺失时报告依据不足。

执行者不能参与本次内容编写或修改。作者上下文应交给另一位人类或独立 Agent，评审只提供原始任务、实际文件、配置、检查清单和证据；不能只给作者的预期结论。独立 Agent 必须自行读取材料。身份、范围与快照先写入记录，不能把 AI 结论冒充 GitHub 人工批准。检查源代码时同时遵循项目编码评审规则。

## 语言适用边界

目标项目正式文档和对应输出模板仍需双语；harness 规范、workflow、SKILL 及操作参考只需中文，双语配对/翻译评审记为不适用并说明资产身份。文件影响、实际检查、独立内容评审与当前版本绑定不能省略。下文英文同步与缺译文阻塞条款只适用于确有双语要求的对象。

## 验证方式

1. 独立确定真实变更范围和验收目标，对照逐领域/逐文件影响清单，主动查找遗漏，而不是仅审作者列出的文件。核对未更新/不适用的理由。
2. 验证源码提交、产物或未提交文件摘要与证据一致；检查元信息、合法状态、命名、双语配对、互链、章节引用、导航、唯一事实来源及历史范围。没有专用检查器时记录逐项检查方法、范围和证据；不能将未执行检查写成通过。
3. 直接核对实现与文档、中文与英文语义、适用示例和命令、候选与发布证据。不存在实现变更时说明为何不适用；文件存在、测试数量和作者声明不证明内容正确。按需要实际执行可逆验证，保留环境与结果。
4. 发现问题记录位置、影响和修正要求，交由作者处理，本评审者不修改被审内容。修正后独立复核新快照的受影响范围；相关变更使旧结论失效。
5. 合入必须通过本次文档检查；专题 completed 还需核对完成标准、长期文档与英文更新、遗留转交；正式发布必须核对版本级说明、兼容/升级指南和对应产物证据。可复用有效范围的证据，但不能用早期成功结果覆盖新变化。

## 输出与门槛

按统一模板记录评审身份与独立性、实际读取文件和证据、所评审版本、机械/内容/双语结果、问题与复核、结论和时间。

结论只能为通过或阻塞。所有必过检查与独立内容评审通过、双语同步、无本次必需缺口才通过。缺规范、配置、必需文档、翻译、实际证据、项目必过 CI、独立性或当前版本绑定时阻塞；不得给文档条件通过或风险豁免。无关既有问题可以单独跟踪，但说明本次不受影响的理由。输出最小解阻动作，交由合入/发布机制决定下一步；不合并、不发布、不自行变更保护规则，既有人类高风险决定仍必需。

## 机械执行入口

按[工具接入](../../../docs/documentation-tooling.md)配置目标项目登记清单并运行 check/snapshot/gate。评审记录由独立评审者填写实际读取、证据和结论；不得自动生成 passed。CI 模板必须接通可信独立记录来源并验证实际平台门禁，不能仅因模板存在声称已强制。
