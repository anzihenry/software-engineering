# 系统级验证

验证单元或组件检查无法充分覆盖的跨边界行为，并说明所得结论的适用范围。此 SKILL 不将测试环境的结果无条件外推为生产结论，也不执行生产发布。

## 输入

- 验证策略、需求/非功能要求、风险等级、PR、契约与迁移说明。
- 可用集成、预发布或隔离测试环境，依赖状态和生产基线（如有）。

## 工作方式

1. 从验证策略选出必须在系统层验证的风险：集成、契约、端到端、性能、并发、韧性、恢复或安全场景。领域风险分别交给 `mobile-validation`、`web-frontend-validation` 或 `backend-validation`；跨客户端、服务和外部依赖的完整用户旅程仍由本 SKILL 汇总验证。
2. 为每项场景确认环境、测试数据、依赖版本、基线、通过阈值和观测方式；标注环境与生产的关键差异。
3. 执行或审查验证结果，记录输入、步骤、观察输出、指标和失败时的可复现信息。
4. 验证接口兼容性、数据迁移/恢复和外部依赖异常路径；高风险场景不应只测试成功路径。
5. 将结果映射回验收标准和风险，并区分已证实、未证实、受环境限制和需要生产观测的结论。

## 输出格式

```markdown
## 系统级验证报告
| 要求/风险 | 场景与环境 | 证据/指标 | 结果 | 生产适用限制 |
| --- | --- | --- | --- | --- |

- 依赖与环境差异：
- 失败、缺陷或回流建议：
- 发布后需要继续观察的信号：
- 总结：通过 | 有条件通过 | 阻塞 | 环境不可信
```

## 停止条件

- 当系统级关键要求已有证据或限制已明确时，交给合入就绪确认。
- 当失败指向实现、设计或契约问题时，回流相应阶段；当环境不可信时，停止把结果作为发布依据。
- 不因“难以搭建环境”而自动放弃高风险验证。
