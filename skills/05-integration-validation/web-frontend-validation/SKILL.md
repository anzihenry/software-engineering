# Web 前端验证

规划并汇总 Web 前端的功能兼容、视觉可访问性和性能证据，形成浏览器支持范围内的综合结论。专项风险分别使用 `web-functional-compatibility-validation`、`web-visual-accessibility-validation` 和 `web-performance-validation`；本 SKILL 不将任一局部成功外推为整体通过。

## 输入

- 验收标准、风险等级、前端自测记录、三类专项验证报告、目标浏览器/视口和待验证构建。
- 真实或受控接口环境、测试数据、设计基准、可访问性要求和性能预算。

## 工作方式

1. 依据支持策略、用户占比、变更触点和风险定义浏览器、设备类别、视口与验证类型矩阵，明确哪些专项必需及未覆盖范围。
2. 将验收标准映射到功能兼容报告，确认关键用户路径、真实依赖、导航、认证、存储和失败恢复均有对应证据。
3. 将界面要求映射到视觉可访问性报告，确认关键状态、响应式、键盘和辅助技术覆盖充分，所有基线差异均已审查。
4. 将性能预算映射到性能报告，确认关键页面/交互、资源和运行时回归已有可比测量，并明确实验室结论的适用范围。
5. 汇总缺陷、环境限制和专项结论；任一高风险要求缺少必需证据时不得用其他专项的成功替代。

## 本节点和端到端边界

按[阶段05](../../../docs/workflows/05-integration-validation.md)由system-level-validation协调每次功能合入前后端到端；领域报告给批准支持矩阵和本节点完整必需项，不用单平台/单专项绿替整体。实际环境/设备/辅助技术/依赖缺失保持blocked/not-run，不能NA或仅明确限制就通过；既有专业/性能/安全/恢复门禁保留。

当前head/base和实际main版本分别绑定原始结果，前后必需执行不可互相替代；每次合入的取消/超时补跑准确对象，连续更晚版本绿不能自动覆盖。替身/小规模只支持所测范围，覆盖关键风险不足就补真实验证或阻塞。完整本节点必需集合实际通过才给本节点通过；conditional按质量门禁不能合入/收口。领域结论交系统级/PR编排汇总，不产生生产授权。

## 停止条件

- 当本节点完整必需浏览器/场景实际通过、证据有效且后续范围明确时，交给 `merge-readiness`。
- 功能/状态问题、UI 问题分别回流对应前端开发；契约、设计或预算问题回流相应阶段。
- 关键浏览器、可访问性或性能要求未验证时，不以局部成功给出无条件通过结论。

## 场景执行与机器报告

按[领域执行契约](../../../docs/domain-validation.md)盘点完整要求、适用性、支持矩阵与受控策略；实际场景和原始报告绑定当前候选。schema 1 读取器只核对一致性，旧 Markdown 继续独立人工审查；缺适用专项、原始执行、批准基线或必要辅助技术保持阻塞，不能从其他成功报告推导通过。
