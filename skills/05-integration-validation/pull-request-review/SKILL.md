# PR 评审

审查变更是否符合已确认的需求、设计和风险控制，并给出可行动的反馈。此 SKILL 不替代安全、合规或架构专项审批，也不在未审阅证据时给出通过结论。

## 输入

- PR 描述、变更内容、自测记录、本地/CI 结果及关联需求、设计和风险评估。
- 契约、迁移、发布恢复预案和项目评审规则（如适用）。

## 工作方式

1. 确认身份与未参与本次实现/修改，记录当前head/base或文件摘要。微型团队优先未参与实现的维护者，独立开发者用全新上下文Agent；不继承作者结论，实际自行读需求/设计、diff及相关调用路径/测试和原始证据。Agent不冒充GitHub人工批准，高风险专业/人类决定仍必需；源码评审先读语言规范/common/匹配参考和实际配置。
2. 按[阶段05六方面](../../../docs/workflows/05-integration-validation.md#独立评审最低要求)核对批准范围/验收、实现路径/失败/并发/资源、契约/授权/数据不变量、测试检错及端到端覆盖、运行/迁移/恢复、文档/译文/当前证据。深度按风险，不能凭CI绿、测试数量或无发现声明全覆盖。
3. 主动检查遗漏、隐藏范围扩大/升级、兼容及真实链路边界。按system-level-validation核对每次功能合入前后端到端的完整集合、实际对象、判据和限制；合入前未来的合入后运行保持未执行，不能伪造完成。
4. 反馈分阻塞、待澄清、非阻塞改进、可选建议，每项给触发、可观察后果、证据、所需动作和复审范围。影响正确性/验收/风险/合入判断的疑问先澄清；非阻塞给处理或后续任务/理由，建议可不采纳，个人偏好不升硬门槛。
5. 修复核对实际代码/行为回归和受影响复审，关闭线程不是解决证据。分歧依据需求/契约/项目规则交相应负责人，不靠投票改写原失败。记录已审/未覆盖范围、证据、剩余问题和复审条件；未变有效范围可复用，新代码/基线/依赖变化后重评。
6. 本评审者如直接参与修复，就不是该修改范围的独立批准者，交另一非作者人类/全新上下文Agent复核；不能用另起同一作者身份自述伪造独立性。本技能只给评审结论，merge-readiness汇总整体资格，实际合并/发布需要既有权限。

## 文档交付要求

合入前按[文档规范](../../../docs/documentation-standard.md)使用 `documentation-delivery-validation` 独立核对实现、双语内容、漏项和真实证据。评审者若参与文档修改须换独立上下文；本次必需文档、翻译或证据缺失应阻塞，不能转为一般风险豁免。

## 输出格式

```markdown
## PR 评审结论
- 评审范围、提交与风险等级：
- 结论：批准 | 修订后复审 | 需专项评审 | 阻塞

| 分类 | 发现/问题 | 影响与证据 | 所需动作 |
| --- | --- | --- | --- |

- 已确认的测试与不足：
- 需额外系统/专项验证：
- 复审条件：
```

## 停止条件

- 当评审结论和所有阻塞/待处理事项明确时，交给作者处理或 `merge-readiness` 汇总。
- 当材料或验证证据不足时，不批准；列出缺失项。
- 评审不应因时间压力跳过高风险影响或替作者解决未验证的关键问题。
- 独立开发者无法提供第二位评审者时，应准确记录 Agent 评审和自我决策的边界，不虚构审批身份或批准状态。
