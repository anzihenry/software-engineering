# 后端性能与并发验证

用可复现负载验证后端容量、资源和共享状态行为，区分性能回归与功能性竞态。使用已批准预算和负载模型；测试环境结果不无条件外推到生产容量。

## 输入

- 性能/容量预算、关键接口或任务、并发不变量、风险等级和可比较基线。
- 环境拓扑、数据规模、依赖容量、负载模型、遥测与待验证构建。

## 工作方式

1. 固定构建、实例/资源、依赖、数据、预热和负载参数，定义到达模式、并发度、持续时间及通过阈值。
2. 测量延迟分布、吞吐、错误/超时、队列和 CPU/内存/连接等饱和信号，不以平均值或最佳单次结果代替尾部行为。
3. 对共享状态和写路径施加并发、突发和长时负载，检查竞态、锁争用、连接池耗尽、重复处理及不变量破坏。
4. 验证限流、排队、背压和过载保护，确认系统以受控方式降载，而不是把压力无界传给数据库或下游。
5. 对照基线定位代码、查询、序列化、运行时、网络或依赖瓶颈，记录环境缩放假设和只能发布后观察的容量信号。

## 停止条件

- 当关键负载和并发不变量已有可重复证据且预算结论明确时，将结果交给 `backend-validation`。
- 实现回归回流对应开发；预算或容量方案缺口回流方案与计划。
- 基线不可比、依赖先饱和或环境波动过大时，限制结论或标记环境不可信。
