# 合入就绪确认

对合入前的必要证据进行最终一致性检查，避免旧的成功结果、未解决反馈或未记录豁免随代码进入目标分支。此 SKILL 只给出结论，不自行合并代码或批准例外。

分支准备、同步、误提交恢复或清理的实际执行使用 `git-branch-management`，不在本技能复制其操作规则；本技能原有 CI、设置或合入判断职责不变。

## 输入

先按[质量门禁规范](../../../docs/quality-gates.md)核对原结果、就绪和授权；条件结论不允许合入。

- 当前 PR 提交和目标分支状态、CI 门禁结论、评审结论、系统验证报告。
- 项目合入规则、风险等级、未决事项和任何豁免记录。

## 工作方式

1. 确认当前head/base及实际所测集成内容，读取项目完整期望集合/风险触发、原始结果及来源，不只核对显示的绿项。按[阶段05](../../../docs/workflows/05-integration-validation.md)核对04交接合格、必需CI、独立评审/必要复审、适用专项及合入前端到端均实际通过。
2. 核对项目审批数量/角色、专业高风险决定、文档/译文独立通过、契约/迁移/恢复与发布信息、有效治理、PR非Draft和无冲突。任何必需失败/未触发/取消/超时/错误跳过/证据不足均阻塞，不靠多数绿项或一般例外放行。
3. 阻塞意见有实际修复/行为证据及复审或有依据证明不成立；关线程不是解决。影响判断的待澄清先解决，非阻塞/建议有处理或后续理由。汇总者不能替专项所有者改原结果；评审者参与修改时该范围换非作者复核。
4. 核对非强制例外的规则、实际授权来源、范围/节点、到期/撤销和补救，硬门禁不可豁免。代码/基线/冲突/依赖/环境变化重验复审受影响范围，项目最新head CI仍执行，难界定时扩大。
5. 本节点只作可合入/阻塞/需重验结论及最小解阻责任，不产生合并授权。合入后必需端到端尚待实际main运行，提前列完整集合/责任/环境/证据/失败动作；不能因未来项未发生声称05已完成，也不能把原合入前缺项改挂后续。实际合入、合入后验证及06交接由PR编排承接，不由本技能提前批准。

## 分支与同步证据

Git 项目按[分支规范](../../../docs/git-branch-workflow.md)核对任务分支、base/head、同步和冲突处理，确保检查/评审对应最新提交且 PR 无阻塞冲突。发现误提交或任务混入时先恢复/拆分再判断；不只凭分支名称证明任务范围。缺失或过期证据给出阻塞或重验结论，本技能不执行恢复或清理。

## GitHub 仓库治理要求

GitHub 项目必须核对[默认治理基线](../../../docs/github-repository-defaults.md)的当前有效默认分支保护及 `delete_branch_on_merge=true`。缺失或无法验证时结论为阻塞，交给 `github-repository-bootstrap` 补齐；非 GitHub 项目记录不适用原因。本技能不隐式写入设置。

## 文档交付要求

必须消费 `documentation-delivery-validation` 对当前提交/快照的通过结论，核对[交付检查](../../../templates/documentation/delivery-check.md)中影响完整性、英文同步和修正复核。缺失、过期或阻塞时不得可合入；本次必需文档、翻译、证据不可豁免。

## 输出格式

```markdown
## 合入就绪确认
- 当前提交、目标分支与检查时间：
- 必需 CI / 评审 / 系统验证 / 专项审批状态：
- 已解决与未解决反馈：
- 豁免及其授权、到期和补救计划：
- 冲突、分支新鲜度和重验要求：
- 结论：可合入 | 阻塞 | 需重跑/复审
- 最小后续动作与责任人：
```

## 停止条件

- 当结论、证据对应关系和剩余事项清晰时结束，交给项目既有的合并机制。
- 任何必需检查、审批、验证或授权豁免缺失时，结论为阻塞或需重验。
- 不在本 SKILL 中执行合并、变更分支保护或自行批准风险例外。

## 证据来源复核

采用[受信维护者接入](../../../docs/evidence-trust.md)时，运行固定来源读取器，回读实际作者、当前 head/base/merge、真实 CI 和不可变评审；缺失、漂移或作者自填批准均阻塞。不把 status 名称本身当独立性认证。
