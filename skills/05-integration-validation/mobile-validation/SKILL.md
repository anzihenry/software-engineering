# 移动端验证

规划并汇总 iOS、Android 和 HarmonyOS 验证，确认共享用户行为、跨平台一致性和整体设备覆盖。平台专属风险分别使用 `ios-validation`、`android-validation` 和 `harmonyos-validation`；本 SKILL 不执行签名、商店提交或生产发布。

## 输入

- 验收标准、风险等级、移动端自测记录、各目标平台专项验证报告、构建版本和支持矩阵。
- 设备/模拟器、测试账号与数据、后端/推送等依赖环境及性能基线。

## 工作方式

1. 根据用户占比、变更触点和风险定义跨平台系统/API、设备形态及真机/模拟器矩阵；将平台专属场景路由给 iOS/Android/HarmonyOS 验证，并明确未覆盖组合。
2. 将验收标准映射到各目标平台报告，确认安装升级、生命周期、权限、系统集成、数据兼容和端侧性能等平台风险均有对应证据。
3. 在所有目标平台执行或审查相同关键用户路径，比较业务结果、错误语义、埋点和恢复行为；区分缺陷与经设计批准的平台差异。
4. 汇总正常、慢速、离线、切网和依赖失败下的共享网络行为，确认重试、取消、重复触发及恢复策略没有因平台实现而偏离。
5. 汇总覆盖矩阵、性能/稳定性信号和环境限制，将结论映射回验收标准；需要实际运行平台官方工具链或补采原始证据时组合 `mobile-cli-execution`，缺少任一必需平台证据时不得用其他平台结果替代。

## 本节点和端到端边界

按[阶段05](../../../docs/workflows/05-integration-validation.md)由system-level-validation协调每次功能合入前后端到端；领域报告给批准支持矩阵和本节点完整必需项，不用单平台/单专项绿替整体。实际环境/设备/辅助技术/依赖缺失保持blocked/not-run，不能NA或仅明确限制就通过；既有专业/性能/安全/恢复门禁保留。

当前head/base和实际main版本分别绑定原始结果，前后必需执行不可互相替代；每次合入的取消/超时补跑准确对象，连续更晚版本绿不能自动覆盖。替身/小规模只支持所测范围，覆盖关键风险不足就补真实验证或阻塞。完整本节点必需集合实际通过才给本节点通过；conditional按质量门禁不能合入/收口。领域结论交系统级/PR编排汇总，不产生生产授权。

## 输出格式

```markdown
## 移动端验证报告
| 要求/风险 | 平台、系统与设备 | 场景 | 证据/指标 | 结果 |
| --- | --- | --- | --- | --- |

- 安装/升级与生命周期结论：
- 权限、系统集成与弱网结论：
- 性能、稳定性、可访问性与隐私结论：
- 跨平台一致性与已批准差异：
- 未覆盖矩阵及影响：
- 总结：通过 | 有条件通过 | 阻塞 | 环境不可信
```

## 停止条件

- 当本节点完整必需平台/场景实际通过、证据有效且后续范围明确时，交给 `merge-readiness`。
- 共享功能或跨平台实现失败回流移动端开发，平台问题回流对应 iOS/Android/HarmonyOS 开发；契约、设计或支持范围问题回流相应阶段。
- 关键真机或系统组合无法验证且缺少替代证据时，不给出无条件通过结论。
