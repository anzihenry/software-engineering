# 后端数据一致性验证

在代表性数据库和数据条件下验证领域不变量、事务及 schema 演进，说明一致性结论的范围。此 SKILL 不直接执行生产迁移或修改生产数据。

## 输入

- 数据模型、不变量、迁移/回填/恢复方案、风险等级、自测记录和待验证构建。
- 数据库版本、代表性数据规模、并发模型、兼容窗口和完整性观测方式。

## 工作方式

1. 确认数据库版本、schema、数据分布、隔离级别和生产差异，为不变量与收敛定义可检查条件。
2. 验证事务提交/回滚、约束、重复写、并发冲突和失败重试，确认没有部分更新、丢失更新或越界关联。
3. 按旧代码/新代码与旧 schema/新 schema 的必要组合验证向前向后兼容、滚动部署及回滚窗口。
4. 验证迁移和回填的重复执行、断点恢复、校验/对账、耗时和锁影响；恢复路径必须实际演练到风险要求的程度。
5. 对最终一致流程验证延迟、重复、乱序和补偿后的收敛，记录无法在环境中证明的规模或时间窗口。

## 输出格式

```markdown
## 后端数据一致性验证报告
| 不变量/风险 | 数据库、schema 与数据条件 | 场景 | 证据 | 结果 |
| --- | --- | --- | --- | --- |

- 事务、并发和完整性结论：
- 迁移、回填、兼容和回滚结论：
- 最终一致、对账和补偿结论：
- 规模/环境限制及生产适用范围：
- 总结：通过 | 有条件通过 | 阻塞 | 环境不可信
```

## 停止条件

- 当高风险不变量、兼容组合和恢复路径已有证据时，将结果交给 `backend-validation`。
- 领域/持久化问题回流对应开发；迁移执行控制回到数据与配置变更流程。
- 代表性数据库或关键恢复路径无法验证时，不把内存替身或静态检查外推为通过。
