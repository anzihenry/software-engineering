# 后端验证

规划并汇总后端专项验证，形成服务在真实协议、数据和依赖条件下的综合结论。按风险组合 `backend-contract-integration-validation`、`backend-data-consistency-validation`、`backend-performance-concurrency-validation`、`backend-resilience-recovery-validation` 和 `backend-security-authorization-validation`；本 SKILL 不执行生产迁移或发布。

## 输入

- 验收标准、风险等级、后端自测记录、按风险必需的专项报告、契约/迁移说明和待验证构建。
- 集成环境、依赖版本、代表性数据、容量/延迟/错误率基线和观测手段。

## 工作方式

1. 根据变更触点、数据等级、调用方、负载和故障影响选择必需专项，定义环境、依赖版本、数据规模、阈值和生产差异。
2. 将验收与兼容要求映射到契约集成报告，将不变量、迁移和收敛要求映射到数据一致性报告。
3. 将容量、延迟和共享状态风险映射到性能并发报告，将依赖故障与恢复目标映射到韧性恢复报告。
4. 对认证授权、租户/资源边界和敏感数据风险，确认安全授权报告及所需安全专项审批齐备。
5. 汇总缺陷、豁免、环境限制和专项结论；未触发的专项说明理由，任一高风险要求缺少必需证据时不得用其他专项成功替代。

## 本节点和端到端边界

按[阶段05](../../../docs/workflows/05-integration-validation.md)由system-level-validation协调每次功能合入前后端到端；领域报告给批准支持矩阵和本节点完整必需项，不用单平台/单专项绿替整体。实际环境/设备/辅助技术/依赖缺失保持blocked/not-run，不能NA或仅明确限制就通过；既有专业/性能/安全/恢复门禁保留。

当前head/base和实际main版本分别绑定原始结果，前后必需执行不可互相替代；每次合入的取消/超时补跑准确对象，连续更晚版本绿不能自动覆盖。替身/小规模只支持所测范围，覆盖关键风险不足就补真实验证或阻塞。完整本节点必需集合实际通过才给本节点通过；conditional按质量门禁不能合入/收口。领域结论交系统级/PR编排汇总，不产生生产授权。

## 输出格式

```markdown

| 要求/风险 | 环境与依赖 | 场景/负载 | 证据/指标 | 结果 |
| --- | --- | --- | --- | --- |

- 契约与调用方兼容结论：
- 数据一致性、迁移与恢复结论：
- 并发、容量与性能结论：
- 依赖故障与可观测性结论：
- 安全授权与专项审批结论：
- 已执行/未触发的专项及理由：
- 环境差异及生产适用限制：

```

## 停止条件

- 当本节点完整必需契约/数据/并发/依赖场景实际通过、证据有效且后续范围明确时，交给 `merge-readiness`。
- 实现失败回流对应后端开发专项；契约、数据模型、容量、恢复或安全模型缺口回流相应阶段/负责人。
- 环境规模或依赖替身不足以支撑关键结论时，降低结论范围或阻塞，不将结果外推到生产。

## 场景执行与机器报告

按[领域执行契约](../../../docs/domain-validation.md)盘点完整要求、适用性、支持矩阵与受控策略；实际场景和原始报告绑定当前候选。schema 1 读取器只核对一致性，旧 Markdown 继续独立人工审查；缺适用专项、原始执行、批准基线或必要辅助技术保持阻塞，不能从其他成功报告推导通过。
