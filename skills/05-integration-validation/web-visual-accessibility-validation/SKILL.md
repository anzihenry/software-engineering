# Web 视觉与可访问性验证

验证界面在目标视口、内容和辅助技术条件下保持可理解、可操作且符合批准的设计。此 SKILL 不自行批准视觉差异或用自动扫描替代关键路径的人工辅助技术检查。

## 输入

- 验收标准、风险等级、待验证构建、批准的设计/基线和目标浏览器/视口。
- 组件状态清单、内容/本地化样本、可访问性要求和适用的辅助技术。

## 工作方式

1. 选择覆盖关键断点、内容密度、主题和交互状态的浏览器/视口矩阵；视觉基线必须对应已批准版本、稳定数据和可复现环境。
2. 检查布局、间距、字体、颜色、图标、层级、溢出、遮挡和状态反馈；审查视觉差异的原因，不通过盲目更新基线消除失败。
3. 验证窄屏、宽屏、缩放/reflow、长文本、本地化、深浅主题、系统字体和减少动态效果等适用条件。
4. 仅用键盘完成关键路径，检查操作顺序、可见焦点、焦点保持/返回、跳转机制和无键盘陷阱；表单错误须可定位和理解。
5. 使用适用的屏幕阅读器检查语义、名称/角色/值、标题与区域、动态通知和阅读顺序，并结合自动检查评估对比度及明显规则问题。

## 停止条件

- 当高风险界面状态和关键辅助技术路径已有证据，且所有差异已审查时，将结果交给 `web-frontend-validation`。
- 实现缺陷回流 `web-ui-implementation-and-self-test`；设计基线或交互含义问题回流设计/需求。
- 缺少关键状态基线或必要辅助技术验证时，不以自动扫描或默认视口结果给出无条件通过结论。
