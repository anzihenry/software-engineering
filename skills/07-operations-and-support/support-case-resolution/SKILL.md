# 支持请求处置

以准确、可追溯和尊重用户的方式处理常规工单与反馈，并把重复问题转化为产品或运行改进。此 SKILL 不替代重大事件响应，不在未经授权时访问超出解决问题所需的用户数据。

## 输入

- 用户工单、反馈、错误报告、知识库、运行手册和相关服务状态。
- 允许访问的账户/日志信息、支持 SLA 和隐私/身份验证要求。

## 工作方式

1. 按操作风险核验必要身份和可处理范围，通用咨询无需账户数据；记录症状、影响、时间、环境、复现信息及用户期望；对疑似事故先升级分诊。
2. 去重并关联已知问题、发布或现有工单；按影响和紧迫度排序，不承诺未经确认的修复时间。
3. 使用已批准的知识库、运行手册和低风险操作解决问题；每次处理记录证据、用户沟通和结果。
4. 无法解决时明确下一步、所有者和预计更新点；涉及产品缺陷、文档缺口、可靠性问题或安全风险时创建相应回流输入。
5. 对重复模式汇总频率、影响和共同症状，提出知识库、自动化、缺陷或需求改进建议。

## 处理状态、解决与结案

按[日常支持契约](../../../docs/workflows/07-operations-and-support.md#日常支持处置)收集够用的症状/时间/环境版本/影响/期望/已试，通用咨询可先处理，最小必要脱敏信息。账户/权限/敏感信息或数据修改按风险使用批准身份核验；未确认身份可通用帮助，不能开放受限信息。不索取密码密钥，无授权不扩访问，所需日志/数据有目的范围和保留方式。

- 严重度与工单优先级分开；单用户严重数据/安全也升级，集中请求不等固定数量。无法复现说明已验证环境/范围及下一核实，不归咎用户。去重关联保留原来源影响/沟通，不机械同报错认同因。
- 处理中记录当前人/动作/下次更新；等待用户写需什么/为何/替代及复查；等内部/供应商有接收方/跟进/更新；转交升级有实际接收和用户沟通责任。接收前原协调继续，供应商未解本方继续跟踪。时钟暂停只按事前规则，保留原等待及总时长。
- 步骤适用当前版本/配置，用户数据/账户操作核对授权和副作用；生产修改走06，工单不产生发布权限。临时绕行明确限制、期限与永久安排，不编修复日期，可承诺有依据的下一更新时间。
- 解决有用户确认或客观证据；结案另记录原因：已验证解决、无回复、转交/升级、重复、撤回或超支持范围。无回复须沿已公布提醒/等待规则，效果未确认且可重开；转交不算已解决。
- 回流关联缺陷/事件的频率、影响、版本和临时措施，有接收人/优先依据/下一决定点；知识库脱敏，记录适用版本/前置、已验步骤、风险及失败处理，不传播未核实猜测。趋势和支持结果交08时保留测量局限。

输出同一工单内的处理状态、解决验证及结案原因、实际责任接收/时钟、授权操作/结果、沟通与后续。必需事实/效果不能因关闭工单而假设通过，复发按原关联重开或升级。

正式记录复用[对应双语模板](../../../templates/delivery/operations-record.md)及现有主系统，按适用工作单元填写，保留独立ID和当前证据；模板存在不代表执行通过。

## 输出格式

```markdown
## 支持工单结论
- 工单、用户影响与优先级：
- 已验证事实与关联记录：
- 采取的处置及结果：
- 用户沟通与下一次更新：
- 状态：已解决 | 等待用户 | 已转交 | 已升级为事件
- 知识库更新或改进输入：
```

## 停止条件

- 当用户确认或有证据表明问题已解决，或已明确转交/升级且沟通完成时关闭或转出。
- 当影响超出常规支持范围或多个用户持续受影响时，转交事件响应。
- 不为关闭工单而假设用户数据、根因或修复效果。
