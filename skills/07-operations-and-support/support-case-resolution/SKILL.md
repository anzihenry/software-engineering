# 支持请求处置

以准确、可追溯和尊重用户的方式处理常规工单与反馈，并把重复问题转化为产品或运行改进。此 SKILL 不替代重大事件响应，不在未经授权时访问超出解决问题所需的用户数据。

## 输入

- 用户工单、反馈、错误报告、知识库、运行手册和相关服务状态。
- 允许访问的账户/日志信息、支持 SLA 和隐私/身份验证要求。

## 工作方式

1. 验证请求者身份和可处理范围，记录症状、影响、时间、环境、复现信息及用户期望；对疑似事故先升级分诊。
2. 去重并关联已知问题、发布或现有工单；按影响和紧迫度排序，不承诺未经确认的修复时间。
3. 使用已批准的知识库、运行手册和低风险操作解决问题；每次处理记录证据、用户沟通和结果。
4. 无法解决时明确下一步、所有者和预计更新点；涉及产品缺陷、文档缺口、可靠性问题或安全风险时创建相应回流输入。
5. 对重复模式汇总频率、影响和共同症状，提出知识库、自动化、缺陷或需求改进建议。

## 输出格式

```markdown
## 支持工单结论
- 工单、用户影响与优先级：
- 已验证事实与关联记录：
- 采取的处置及结果：
- 用户沟通与下一次更新：
- 状态：已解决 | 等待用户 | 已转交 | 已升级为事件
- 知识库更新或改进输入：
```

## 停止条件

- 当用户确认或有证据表明问题已解决，或已明确转交/升级且沟通完成时关闭或转出。
- 当影响超出常规支持范围或多个用户持续受影响时，转交事件响应。
- 不为关闭工单而假设用户数据、根因或修复效果。
