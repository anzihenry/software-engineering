# 事件分诊与响应

以恢复用户价值和控制影响为优先，按严重程度组织事件响应并保留可复盘的事实记录。此 SKILL 不替代安全/隐私事件的专门流程，也不在无授权时执行高影响生产操作。

## 输入

- 告警、用户报告、错误信号、发布记录、服务健康数据、运行手册和值守规则。
- 已知受影响范围、时间、症状、依赖状态和初始证据。

## 工作方式

1. 建立事件记录，保留时间、来源、症状、初步影响和已知事实；合并重复信号，避免多个并行记录分散处置。本仓库的普通事故遵循 [GitHub 状态自动化契约](references/github-incident-automation.md)，先 dry-run 再由人类确认状态写入。
2. 按用户影响、范围、持续时间、关键性和恢复紧迫度分级。身份滥用、凭据泄露、敏感数据暴露、隐私违规或疑似攻击应立即转入 `security-privacy-incident-response`。
3. 根据严重度通知授权值守人和利益相关方，指定协调、技术处置和沟通责任；沟通只陈述已知影响与下一次更新时间，不猜测根因。
4. 先执行经过授权且可逆的缓解措施以降低影响，再开展根因调查；记录每项操作、时间、结果和副作用。
5. 持续评估影响和健康信号，必要时升级级别、扩大资源或转入发布恢复/专项安全响应。
6. 关闭前确认缓解或修复生效、监控恢复、用户沟通完成、影响时间线完整，并创建后续行动或复盘输入。

## 运行接收、分诊与恢复判据

按[阶段07契约](../../../docs/workflows/07-operations-and-support.md#统一接收与分诊)消费运行对象/责任清单，接手、初分诊、更新与恢复目标分开，沿项目实际等级和覆盖时段，不编24小时值守。最低信号足以开始，缺复现/版本继续补，可信严重影响先响应。主事件关联原告警/工单及时间影响，合并有证据、可拆分；工单用户沟通继续。

- 事件严重度按伤害/关键路径/数据安全、范围/持续/趋势及替代，区别支持优先级；单用户严重问题也升级。暂定等级保留依据/未知，降级需新证据/人/时间，转交改级不重置原影响时钟。
- 对象负责人、当前响应、事件协调、沟通可兼任但明确；换班/转专项/供应商协作交现场/已做副作用/未完成/授权/下一步，实际接收前原协调持续，无法继续按升级指定接管。严重影响且06缺材料可应急接管，不倒填发布成功。
- 事实/假设/操作结果分离；已有有效预授权内可直接缓解，超范围/不可逆或新代码制品迁移交06与适用紧急通道。超时/中断/部分成功先核实落地、仍执行、数据及外部副作用，再安全重试/补偿，保留失败历史。
- 已缓解只表示影响降低/停止扩大；已恢复需实际用户路径/服务/数据、版本配置及规定稳定时间/样本。降级恢复有事前最低服务标准、受限能力/期限及完整恢复计划，阻塞影响仍部分恢复。无告警或health200不足，缺观测/低样本保留缺口。
- 可关闭还需时间线/影响结束及必要沟通、当前文档、遗留/复盘实际接收、责任/期限/判据；长期改进交08验证效果。观察复发继续原事件记区间，关闭后可重开关联，保留原依据。
- 按节奏更新已知影响/措施/替代/下次时间，无新结论也更新，有依据才估恢复时间；外发需实际授权。08接收事实/口径局限/当时信息/授权失败/防护及行动，不以交复盘关闭当前响应。

输出在同一主事件记录保留以上当前对象、责任/时钟、分诊/合并、实际操作/验证、沟通与接收。GitHub状态写入仍遵循本技能既有dry-run/人类精确确认契约，预授权缓解不自动放宽平台写入机制；状态更新成功不认证恢复或关闭证据。

正式记录复用[对应双语模板](../../../templates/delivery/incident-record.md)及现有主系统，按适用工作单元填写，保留独立ID和当前证据；模板存在不代表执行通过。

## 输出格式

```markdown
## 事件记录
- 事件标识、开始时间与来源：
- 严重度、用户影响和范围：
- 当前状态：调查中 | 缓解中 | 已恢复 | 已关闭 | 已升级
- 已知事实与未知项：
- 时间线：
- 已执行措施、结果和授权：
- 沟通与下次更新时间：
- 关闭依据、后续行动与复盘要求：
```

## 停止条件

- 当事件按恢复/关闭标准验证或升级后获实际接收，且事实、沟通和后续责任完整时结束相应响应工作单元；恢复不自动等于关闭。
- 无法在目标恢复时间内缓解时，升级严重度和资源投入；不要仅因告警消失而关闭高严重度事件。
- 对安全或隐私事件，停止通用安全判断并执行 `security-privacy-incident-response`；若同时存在服务影响，可继续协调恢复，但共享同一事件标识和事实时间线。
