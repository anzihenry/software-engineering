# 安全与隐私事件响应

在控制攻击、数据暴露和用户影响的同时，保留足以判断范围、支持恢复及满足后续审查的可信证据。本 SKILL 不替代法务意见、隐私影响判断、正式数字取证或有权限人员的生产和对外通知决定。

## 输入

- 可疑告警、用户/供应商报告、身份与数据访问记录、受影响资产、当前用户影响和已有事件记录。
- 若已知：数据类别与主体、地区、第三方、保留政策、通知时限、法律保全要求、响应联系人和授权边界。

## 工作方式

1. 创建访问受限的专项事件记录并指定事件负责人、技术处置、证据保管、隐私/法务和沟通责任；主要身份或通信系统可能失陷时，使用已批准的带外渠道。普通服务影响可并行使用 [`incident-triage-and-response`](../incident-triage-and-response/SKILL.md)，但保持单一事件标识和一致时间线。GitHub 公共/受限入口遵循[报告边界](references/github-reporting-boundary.md)。
2. 将信号标为`待确认`、`已确认`或`已排除`，按机密性、完整性、可用性和用户伤害评估严重度；记录受影响资产、身份、数据类别/主体、地区、持续攻击、横向移动和第三方影响，不把缺少证据解释为没有影响。
3. 由事件负责人权衡立即遏制与易失证据保全。人身风险、活跃数据外传或攻击扩散优先控制；条件允许时在改变系统、撤销身份或清除载荷前采集高价值易失证据，并记录每项操作对证据和服务的影响。
4. 只由获授权人员使用批准工具采集完成范围判断所需的最少证据。采集、复制、验证、转移或处置证据时遵循[证据保全与流转](references/evidence-preservation.md)，保护原件、完整性、来源、访问权限和保留期限；事件频道、工单和普通日志不粘贴密钥、完整个人数据或恶意载荷。
5. 依据指标、时间线、身份行为、数据流和持久化迹象持续验证影响范围；执行可审计、尽量可逆的隔离、令牌撤销、访问阻断或配置控制。需要紧急生产变更时转入 [`emergency-change-management`](../../06-release-and-change-management/emergency-change-management/SKILL.md)，不以调查名义绕过授权。
6. 隐私/法务负责人依据已验证事实判断适用地区、数据主体、合同/监管时钟、法律保全和通知义务。记录发现时间、决策人、依据、截止时间和状态；Agent 不自行联系监管机构、执法部门、受影响用户、媒体或攻击者，也不承诺不存在违规。
7. 从可信基线清除持久化、修补入口、轮换受影响凭据并验证关键用户路径、数据完整性和监控。恢复不能销毁仍受保全要求约束的证据；未知攻击路径、残留访问或数据范围未被控制时保持升级状态。
8. 以最小必要范围同步已知事实、当前影响、已采取措施和下一更新时间。威胁受控、恢复验证且通知决定有负责人后，交接受限事件记录和脱敏时间线给 [`incident-review`](../../08-measurement-and-retrospective/incident-review/SKILL.md)，并按政策保留或经授权处置证据。

## 输出格式

```markdown
## 安全/隐私事件记录
- 事件标识、发现时间、来源与当前状态：待确认 | 已确认 | 已排除 | 遏制中 | 恢复中 | 已移交 | 已关闭
- 严重度、机密性/完整性/可用性与用户影响：
- 事件负责人、技术处置、证据保管、隐私/法务与沟通责任：
- 受影响资产、身份、数据类别/主体、地区与第三方：
- 已知事实、未知项、假设与范围判断：
- 时间线、遏制/调查/恢复操作、授权及结果：
- 证据清单、完整性/来源、保管位置与流转记录：
- 法律保全、通知/披露决定、负责人、依据与截止时间：
- 当前威胁、恢复验证、残余风险和下一更新时间：
- 复盘、长期行动与证据保留/处置计划：
```

## 停止条件

- 活跃攻击、数据外传或用户伤害仍在扩大时，不等待完整归因；在授权范围内优先遏制并保存可取得的关键证据。
- 缺少取证能力、证据保管授权、隐私/法务判断或安全生产权限时，不自行扩大采集和操作；保护现状、记录缺口并升级给相应负责人。
- 只有威胁已受控、影响范围达到可决策程度、恢复得到验证、证据受控且通知/法律保全已有明确负责人和状态时，才结束当前响应并交接复盘。
- 未经授权不删除证据、解除法律保全、公开归因、通知外部主体、联系攻击者或执行付款。
