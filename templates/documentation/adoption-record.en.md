# Project adoption acceptance record template

[中文](adoption-record.md)

- record_id, record_status, owner, decision_authority, risk_level, related_records, created_at, updated_at:
- source_version: harness repository/full knowledge commit, tool commit or digest, target head/base/merge, environment and configuration:
- Root/global/directory entry inventory and override analysis, skill/standard paths, applicable references, owners and single task fact source:
- Actual commands, versions, original reports, unexecuted checks and reasons:
- Independent Agent task, identity/separate context, tool reading/execution trace, findings/corrections/recheck:
- Actual GitHub identity/write permissions, trusted record source, PR, CI/App, rules readback and invalid-candidate merge blocking:
- Positive/negative cases with current object, results and original evidence:
- Separate local, observed behavior and remote conclusions, applicability limits and inapplicability rationale:
- Remaining migration/blockers, owners, unblock tasks and revalidation conditions:

Follow the [adoption standard](../../docs/harness-adoption.md) (Chinese). Self-reported loading, file presence or local success cannot prove whole-project adoption or remote enforcement. Required gaps cannot be waived.
